# 지식 표현: 택소노미 → 온톨로지 → 지식그래프

> **범위**: AI Agent 시스템에서 "구조화된 지식"을 표현하는 세 층위의 차이, 표준(RDF/OWL/SHACL/SKOS)과 Property Graph의 선택 기준, 온톨로지가 에이전트에서 하는 역할. 온톨로지를 실제로 설계하는 절차는 [Part 2/06](../02-data-pipeline/06-ontology-driven-modeling.md), 그래프를 구축하는 파이프라인은 [Part 2/05](../02-data-pipeline/05-knowledge-graph-construction.md).

## 요약 (3줄)

1. 택소노미는 **찾게** 하고, 온톨로지는 **의미를 갖게** 하고, 지식그래프는 **연결되게** 한다. 셋은 대체재가 아니라 층위다.
2. 2026년 온톨로지가 다시 핵심이 된 이유는 GraphRAG가 "임베딩 + 그래프 탐색"에 머물러 **스키마 없는 그래프**를 만들었기 때문이다. 온톨로지는 추출 결과를 정렬·검증하고 에이전트의 판단을 접지(grounding)한다.
3. 표준 스택(RDF/OWL/SHACL)과 Property Graph(LPG)는 **추론·상호운용 vs 개발 편의·성능**의 트레이드오프다. 대부분의 에이전트 프로젝트는 LPG로 시작해 SHACL 류 제약을 애플리케이션 계층에서 흉내 내다가, 외부 데이터 통합이나 규제 설명이 필요해지면 표준 스택을 검토한다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** | 도메인의 개념·관계·제약을 기계가 읽을 수 있게 표현한 모델과, 그것을 저장·질의·검증하는 스택의 선택 |
| **언제** | 다음 중 하나라도 해당하면: 엔티티 간 관계를 따라가는 질문(멀티홉)이 있다 / 같은 것을 다른 이름으로 부르는 소스가 여럿이다 / 판단 근거를 규제·감사에 설명해야 한다 / UI가 도메인 개념 단위로 구성된다. **해당 없으면 벡터 인덱스만으로 시작한다** |
| **어떻게** | ① 택소노미(분류 체계)부터 만든다. 이것만으로도 메타데이터 필터링이 가능 → ② 핵심 엔티티 10~30개와 관계를 정의(경량 온톨로지) → ③ 저장 스택 선택(LPG vs RDF) → ④ 제약(필수 속성, 허용 관계)을 SHACL 또는 코드로 → ⑤ 추출 파이프라인이 이 스키마에 정렬되도록 |
| **왜** | 스키마 없는 그래프는 LLM이 추출한 엔티티명이 "삼성전자 / 삼성 / Samsung Electronics"로 흩어지고, 관계명이 수백 종으로 폭발한다. 검색은 되지만 추론·검증·설명이 안 된다 |

## 문제와 맥락

RAG 1세대는 문서를 청크로 자르고 벡터로 검색했다. 이 방식은 "이 문서에 뭐라고 쓰여 있나"에는 강하지만 다음에 약하다.

- **멀티홉**: "A 프로젝트의 담당 부서가 작년에 발주한 계약의 공급사는?" 청크 하나에 답이 없다
- **동일성**: 같은 고객이 소스마다 다른 ID·이름으로 등장
- **집계·비교**: "최근 3년 인시던트 중 같은 서비스에서 반복된 것"
- **설명**: "왜 이 답인가"를 그래프 경로로 보여줘야 하는 규제 환경

GraphRAG(2024~)는 LLM으로 엔티티·관계를 추출해 그래프를 만들었지만, 비판자들은 많은 구현이 **온톨로지 없이** 임베딩과 그래프 탐색만 쓴다고 지적한다 `[2차]` (Neo4j NODES 세션, AllegroGraph 블로그 등 — 그래프 벤더의 프레이밍임을 감안). 2026년의 흐름은 "그래프에 스키마와 제약을 되돌려 놓자"다.

## 핵심 개념

### 세 층위

| 층위 | 표현하는 것 | 표준 | 에이전트에서의 쓰임 | 비용 |
|---|---|---|---|---|
| **택소노미** (Taxonomy) | 개념의 계층 분류 (is-a, broader/narrower) | SKOS | 메타데이터 필터, 라우팅 카테고리, UI 네비게이션 | 하. 2~3일 |
| **온톨로지** (Ontology) | 개념(클래스), 속성, 관계, 제약, 공리 | OWL, RDFS; 제약은 SHACL/ShEx | 추출 스키마, 검증, 추론(상위 클래스 추론·역관계), 설명 | 중~상. 경량이면 2주, 정식이면 수개월 |
| **지식그래프** (Knowledge Graph) | 온톨로지에 따라 채워진 인스턴스와 관계 | RDF 트리플 또는 LPG | 멀티홉 검색, 엔티티 중심 컨텍스트 조립, 근거 경로 | 구축·유지 비용이 지배적 |

**택소노미만으로 끝나는 프로젝트가 많다.** 문서 유형·부서·제품군 분류만 있어도 ACL 필터와 라우팅의 대부분이 해결된다. 온톨로지와 그래프는 멀티홉·동일성·설명 요구가 확인된 뒤에 올린다.

### 표준 스택 vs Property Graph

| 항목 | RDF / OWL / SPARQL (표준 스택) | Labeled Property Graph (Neo4j, 기타 LPG) |
|---|---|---|
| 데이터 모델 | 트리플(주어-술어-목적어). 관계에 속성을 달려면 재구성(RDF-star) 필요 | 노드·관계 모두 속성 보유. 직관적 |
| 스키마 | 온톨로지(OWL)로 의미 정의, SHACL로 제약 검증. 스키마와 데이터가 같은 언어 | 스키마 선택적. 제약은 DB 기능 또는 애플리케이션 코드 |
| 추론 | OWL reasoner로 상위 클래스·역관계·전이 관계 자동 추론 | 기본 없음. 쿼리나 코드로 구현 |
| 상호운용 | 글로벌 URI, 외부 온톨로지(schema.org, FIBO, SNOMED 등) 재사용 용이 | 조직 내부용. 외부 통합은 변환 필요 |
| 개발 편의 | 학습 곡선 가파름, 툴링 상대적으로 적음 | 개발자 친화적, 시각화·툴링 풍부 |
| 성능 | 트리플스토어별 편차 큼 | 경로 탐색에 최적화 |
| 벡터 통합 | 일부 트리플스토어가 지원 | 주요 LPG DB가 벡터 인덱스 내장 |

**혼합 전략**이 현실적이다. 온톨로지는 OWL/SHACL로 **정의**해 단일 진실 원천으로 두고, 운영 저장소는 LPG를 쓰며, 온톨로지 → LPG 스키마 변환과 SHACL → 코드 제약 변환을 자동화한다. 외부 통합·규제 설명이 생기면 RDF 내보내기를 추가한다.

### 온톨로지가 에이전트에서 하는 네 가지 역할

1. **추출 스키마**: LLM이 문서에서 엔티티·관계를 뽑을 때 "이 클래스·이 관계만"으로 제한. 관계명 폭발 방지 ([Part 2/05](../02-data-pipeline/05-knowledge-graph-construction.md))
2. **검증기**: 추출 결과·LLM 출력이 제약(필수 속성, 도메인·레인지, 카디널리티)을 지키는지 SHACL 류로 검사. 뉴로심볼릭의 Neural→Symbolic 패턴 ([04](04-neuro-symbolic-ai.md))
3. **접지(grounding)**: 에이전트가 쓰는 용어·선택지·툴 인자를 온톨로지 개념에 묶어 환각과 용어 드리프트를 억제. 2026-03 arXiv 2604.00555는 Role/Domain/Interaction 3계층 온톨로지로 21개 산업 650+ 에이전트를 운영했다고 보고 `[검증-단일저자, 독립 재현 없음]`
4. **설명**: "이 답의 근거는 A→B→C 경로"를 사람이 읽을 수 있게. 규제·감사 대응 ([Part 5/04](../05-cross-cutting/04-governance-explainability.md))

### 시맨틱 레이어

BI 세계의 "시맨틱 레이어"(지표 정의, 차원, 관계를 중앙에서 정의)가 에이전트에도 들어오고 있다. 에이전트가 SQL이나 그래프 쿼리를 생성할 때 테이블·컬럼이 아니라 **비즈니스 개념**을 보게 하는 것. 온톨로지의 실용적 구현 형태로 볼 수 있다 `[2차]`.

## 아키텍처 / 파이프라인

```
도메인 전문가 ─▶ [택소노미] ─▶ [경량 온톨로지: 클래스·관계·제약] ─┬─▶ LLM 추출 프롬프트의 스키마
                                                                   ├─▶ SHACL/코드 검증기
                                                                   ├─▶ LPG 스키마 (운영 저장소)
                                                                   ├─▶ 결정 모델·툴의 enum 소스
                                                                   └─▶ UI 컴포넌트 매핑 (Part 4/05)
```

## 기술 비교표 — 지식 표현 스택

| 기술 / 접근 | 적합한 상황 | 부적합한 상황 | 비용·복잡도 | 성숙도 | 검증 수준 |
|---|---|---|---|---|---|
| 택소노미만 (SKOS 또는 단순 트리) | 분류·필터·라우팅이 주 요구. 멀티홉 없음 | 관계 질의, 동일성 해소 필요 | 하 | 표준 | `[검증]` |
| 경량 온톨로지 + LPG | 대부분의 에이전트 프로젝트. 멀티홉 있음, 내부용, 빠른 개발 | 외부 온톨로지 통합, 자동 추론 필요 | 중 | 안정 | `[검증]` |
| 정식 온톨로지 (OWL) + 트리플스토어 + SHACL | 규제 설명, 외부 표준 재사용(의료·금융), 자동 추론 | 소규모 팀, 빠른 반복 필요 | 상 | 표준(W3C) | `[검증]` |
| 혼합 (OWL/SHACL 정의 + LPG 운영) | 내부 개발 속도와 장기 상호운용을 모두 원할 때 | 변환 자동화를 유지할 여력이 없을 때 | 중~상 | 안정 | `[2차]` |
| 스키마 없는 그래프 (GraphRAG 기본 출력) | 탐색적 분석, 빠른 PoC | 운영, 검증·설명 필요 | 하(초기) / 상(유지) | 안정 | `[2차]` 관계 폭발 문제 널리 보고 |
| 시맨틱 레이어 (BI형) | 정형 데이터 중심, Text-to-SQL 에이전트 | 비정형 문서 중심 | 중 | 신생(에이전트 용도로는) | `[2차]` |

### 선택 가이드

- **멀티홉·동일성·설명 요구가 없다면** → 택소노미 + 벡터 인덱스. 이유: 온톨로지는 유지 비용이 크다
- **멀티홉이 있고 내부용이라면** → 경량 온톨로지 + LPG. 이유: 개발 속도, 벡터 통합 용이
- **규제 설명이나 외부 표준(FIBO, SNOMED 등) 재사용이 필요하다면** → 정식 OWL + SHACL. 이유: 추론·상호운용은 표준 스택만 제공
- **판단이 어려우면** → 경량 온톨로지를 OWL로 **정의**하되 LPG에 **저장**. 이유: 나중에 어느 쪽으로든 갈 수 있다

## 설계 시 고려사항 (체크리스트)

- [ ] 멀티홉·동일성·집계·설명 요구 중 실제로 있는 것을 확인했는가 (없으면 온톨로지 보류)
- [ ] 택소노미를 먼저 만들었고 메타데이터 필터에 연결했는가
- [ ] 핵심 클래스가 30개 이내인가 (초기 온톨로지가 크면 추출 품질이 떨어진다)
- [ ] 관계마다 도메인·레인지(어떤 클래스 간 관계인지)를 정의했는가
- [ ] 필수 속성·카디널리티 제약을 SHACL 또는 코드로 표현했고 추출 결과에 적용하는가
- [ ] 엔티티 해소(entity resolution) 규칙(ID 매핑, 별칭)이 있는가
- [ ] 온톨로지 버전 관리와 변경 시 그래프 마이그레이션 절차가 있는가
- [ ] 외부 표준 온톨로지 중 재사용할 것이 있는지 확인했는가 (schema.org, 산업별 표준)
- [ ] 온톨로지 소유자(도메인 전문가)가 정해져 있는가

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 온톨로지 유지 비용 | 도메인 변화를 따라가지 못해 추출·검증이 현실과 어긋남 | 경량 유지, 소유자 지정, 변경 요청 절차 |
| 과설계 | 수백 클래스의 온톨로지가 아무도 못 쓰는 상태로 | 30개 이내로 시작, 질의 로그 기반 확장 |
| LLM 추출의 스키마 불일치 | 온톨로지에 없는 클래스·관계를 LLM이 만들어 냄 | 추출 프롬프트에 스키마 강제 + SHACL 검증 + 미분류 버킷 |
| 표준 스택의 인력 부족 | OWL/SPARQL 경험자가 드묾 | 혼합 전략, 변환 자동화 |
| 그래프 벤더 프레이밍 | "온톨로지 필수"는 그래프 DB 벤더가 강조하는 서사 | 요구 확인 후 채택, 벡터만으로 되는지 먼저 시험 |
| 벤치마크 부재 | 온톨로지 유무에 따른 에이전트 품질 차이의 독립 측정이 드묾 | 자체 골든셋으로 `[실측]` |
