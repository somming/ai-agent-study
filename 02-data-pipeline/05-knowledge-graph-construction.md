# 지식그래프 구축 파이프라인

> **범위**: LLM 기반 엔티티·관계 추출, 엔티티 해소, 온톨로지 정렬, GraphRAG/LightRAG/HippoRAG 인덱싱 비교
> **시각화**: [`assets/html/kg-construction-pipeline.html`](../assets/html/kg-construction-pipeline.html)

## 요약 (3줄)

1. 지식그래프(Knowledge Graph, KG) 구축은 **멀티홉·동일성·설명 요구가 확인된 뒤**에 시작한다. 벡터 검색으로 풀리는 질문에 그래프를 올리면 인덱싱 비용만 늘고 품질은 그대로다. "그래프 RAG의 가치는 질의 복잡도에 달렸다"가 실무자 합의다 `[2차]`.
2. 구축의 품질은 추출 LLM이 아니라 **스키마(온톨로지)와 엔티티 해소**가 결정한다. 스키마 없는 추출은 관계명이 수백 종으로 폭발하고 같은 엔티티가 표기마다 흩어진다. LLM 추출 → 온톨로지 정렬·SHACL 검증 → 엔티티 해소 → 적재의 2단계 구성이 뉴로심볼릭의 대표 패턴이다.
3. 인덱싱 방식(GraphRAG / LightRAG / HippoRAG 2)은 **비용 구조와 증분 갱신 가능성**으로 고른다. 벤치마크 우위 주장은 재분석에서 상당 부분 포맷 효과로 드러났고, 포맷 통제 후 뚜렷한 우위는 최난도 멀티홉(MuSiQue 54.4 vs 40.1)에서만 확인됐다 `[검증]`.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | ① 추출 스키마(허용 클래스·관계·속성) ② 추출 파이프라인(LLM / 규칙 / 하이브리드)과 검증 규칙 ③ 엔티티 해소 규칙과 정규 ID ④ 그래프 저장소와 인덱싱 방식 ⑤ 노드·엣지 → 원문 청크 역참조(근거 경로용) ⑥ 증분 갱신 절차 |
| **언제** (When) | 필요 조건: 멀티홉 질문("A의 담당 부서가 발주한 계약의 공급사"), 소스 간 동일 엔티티 통합, 그래프 경로로 설명해야 하는 규제. **생략**: 단일 문서 내 사실 조회가 대부분. **미뤄도 되는 것**: 커뮤니티 요약(GraphRAG 글로벌 질의)은 "전체 요약" 질문이 실제로 있을 때만 |
| **어떻게** (How) | ① 질의 로그에서 멀티홉·동일성 질문 비율 확인 → ② 경량 온톨로지([06](06-ontology-driven-modeling.md)) 10~30 클래스 → ③ 샘플 200건으로 LLM 추출 품질 `[실측]`(정밀도·재현율, 스키마 위반율) → ④ 검증기(SHACL 또는 코드) + 미분류 버킷 → ⑤ 엔티티 해소(결정론 → 유사도 → LLM 순) → ⑥ 적재 + 청크 역참조 → ⑦ 증분 갱신 경로 확보 후 전체 구축 |
| **왜** (Why) | 스키마 없이 추출하면 "근무한다/일한다/소속/재직" 네 관계가 따로 생기고 "삼성전자/삼성/Samsung"이 세 노드가 된다. 검색은 되지만 경로 탐색·집계·설명이 안 된다. 증분 갱신 없이 구축하면 문서 하나 바뀔 때마다 전체 재구축 비용이 든다 |

## 문제와 맥락

GraphRAG(2024~)는 "LLM으로 문서에서 엔티티·관계를 뽑아 그래프를 만들고, 커뮤니티 요약으로 글로벌 질의에 답한다"는 아이디어로 주목받았다. 운영에서 드러난 문제는 두 가지다.

- **인덱싱 비용**: 모든 청크를 LLM에 통과시켜 추출하고, 커뮤니티마다 요약을 생성한다. Microsoft GraphRAG는 인덱싱 비용 과다로 "brittle and cost-prohibitive"라는 비판을 받았다 `[벤더]` (경쟁사 평가 포함이므로 감안)
- **스키마 부재**: 많은 구현이 온톨로지 없이 임베딩 + 그래프 탐색에 머물러 관계명 폭발·엔티티 분산을 낳았다 `[2차]` (Neo4j NODES 세션 등 그래프 벤더 프레이밍)

이에 대한 대안으로 **LightRAG**(이중 수준 검색 + 증분 업데이트)와 **HippoRAG 2**(Personalized PageRank 기반 연상 검색)가 나왔고, 2026년의 흐름은 "그래프에 스키마와 제약을 되돌려 놓자"는 온톨로지 회귀다. 이 페이지는 그 흐름 위에서 **구축 파이프라인**을 다룬다. 검색 측은 [Part 3/01](../03-agent-workflow-rag/01-rag-architecture-patterns.md), 트렌드 해석은 [Part 6/graphrag-evolution](../06-trends/graphrag-evolution.md).

## 핵심 개념

### 추출 방식 세 가지

| 방식 | 동작 | 강점 | 약점 |
|---|---|---|---|
| **LLM 추출** | 프롬프트에 스키마를 주고 청크에서 (주어, 관계, 목적어, 근거 문장) 추출 | 표현 다양성에 강함, 스키마 변경이 프롬프트 수정 | 비용(청크당 호출), 비결정성, 스키마 위반·환각 관계 |
| **규칙·패턴 추출** | 정규식, 사전, 의존 구문 패턴, 정형 레코드 → 트리플 매핑 | 결정론, 저비용, 설명 가능 | 표현 변형에 약함, 규칙 유지 비용 |
| **하이브리드** | 정형·반정형(표, 레코드, 메타데이터)은 규칙, 서술문은 LLM, 결과를 공통 스키마로 합침 | 비용과 재현율의 균형 | 두 경로 유지, 충돌 해소 규칙 필요 |

현실적 기본값은 하이브리드다. **정형 데이터에서 올 수 있는 트리플을 LLM에게 시키지 않는다.** 조직도·제품 마스터·티켓 필드는 이미 구조화되어 있다.

### 온톨로지 정렬과 검증

추출 결과를 그대로 적재하지 않고 **스키마에 정렬**한다.

1. **클래스 정렬**: 추출된 엔티티 유형을 온톨로지 클래스에 매핑. 매핑 안 되면 미분류 버킷
2. **관계 정규화**: 동의 관계("근무/소속/재직")를 온톨로지 관계 하나로. 허용 목록 밖은 거부 또는 버킷
3. **도메인·레인지 검증**: `employedBy`의 주어는 Person, 목적어는 Organization이어야 함
4. **카디널리티·필수 속성**: SHACL 또는 코드로. 위반은 적재 거부
5. **근거 문장 필수**: 모든 트리플은 원문 청크·문장 ID를 가져야 한다. 없으면 적재 거부 — 이것이 [08](08-grounding-data-design.md)의 트리플 근거 단위의 전제

이 구조가 "LLM 추출 → SHACL/규칙 검증 → 적재"의 뉴로심볼릭 2단계 구성이다 `[2차]`. 상세 온톨로지 설계는 [06](06-ontology-driven-modeling.md).

### 엔티티 해소 (Entity Resolution)

같은 실세계 대상을 가리키는 표기를 하나의 정규 ID로 묶는다. 비용이 싼 순서로 적용한다.

| 단계 | 방법 | 처리 비율(정성) |
|---|---|---|
| ① 결정론 | 정형 ID 매칭(사번, 제품 코드, 사업자번호), 별칭 사전 | 대부분 |
| ② 블로킹 + 유사도 | 같은 클래스·같은 블록 안에서 문자열(정규화·편집 거리)과 임베딩 유사도 | 잔여 다수 |
| ③ 판정 모델 | "이 둘은 같은 것인가" 예/아니오 — 소형 분류기, 결정 모델, 또는 LLM | 소수 |
| ④ 사람 | 저확신 쌍 검토 큐 | 극소수 |

③에서 LLM을 쓰면 쌍 수에 비례해 비용이 든다. 선택지가 닫혀 있는(같다/다르다) 판정이므로 결정 모델·소형 분류기의 자리다([09](09-ai-inside-the-pipeline.md)). 결정 결과는 `sameAs` 링크로 기록해 되돌릴 수 있게 한다(병합은 비가역이므로 피한다).

### 인덱싱 방식 비교: GraphRAG / LightRAG / HippoRAG 2

| 항목 | Microsoft GraphRAG | LightRAG | HippoRAG 2 |
|---|---|---|---|
| 그래프 | 엔티티·관계 + 계층적 커뮤니티 + 커뮤니티 요약 | 엔티티·관계 그래프, 키워드 인덱스 | 구절(passage)·엔티티 노드, 시냅스 유사 연결, Personalized PageRank |
| 검색 | 로컬(엔티티 이웃) / 글로벌(커뮤니티 요약 집계) | 저수준(엔티티) / 고수준(주제) 이중 검색 | 질의 엔티티에서 PPR로 연상 확산 → 구절 순위 |
| 인덱싱 비용 구조 | 추출 + 커뮤니티 요약 생성. 비용 과다 비판 `[벤더]` | 추출 중심, 요약 없음. GraphRAG 대비 대폭 적다는 2차 요약(구체 수치는 `[2차]`라 인용 안 함) | 추출 + 그래프 구성. PPR은 질의 시 계산 |
| 증분 갱신 | 커뮤니티 재계산 필요 → 사실상 재구축 | **지원** (새 문서의 엔티티·관계 병합) | 그래프에 노드 추가 가능, PPR은 질의 시이므로 재인덱싱 부담 작음 |
| 강점 | 전체 코퍼스 요약형 질의 | 비용·증분 | 최난도 멀티홉 |
| 검증 수준 | `[벤더]` `[2차]` | `[2차]` | `[검증]` arXiv 2607.11683 재분석: 장황 답변 프롬프트의 우위는 대체로 포맷 효과, 포맷 통제 후 MuSiQue에서만 뚜렷한 우위(54.4 vs 40.1) |

세 방식 모두 **온톨로지 없이도 동작**하지만, 온톨로지를 주면 엔티티 정규화가 개선된다는 보고가 있다 `[2차]`. 어떤 방식이든 이 페이지의 정렬·해소 단계를 거친 그래프 위에 올리는 것이 전제다.

### 비용 구조

| 비용 항목 | 지배 요인 | 줄이는 방법 |
|---|---|---|
| 추출 LLM 호출 | 청크 수 × 청크 길이 × 모델 단가 | 정형 데이터는 규칙, 추출 대상 문서 유형 제한, 소형 모델 + 검증기 |
| 커뮤니티 요약 (GraphRAG) | 커뮤니티 수 × 계층 | 글로벌 질의가 없으면 생략 |
| 엔티티 해소 | 후보 쌍 수(블로킹 없으면 제곱) | 블로킹, 결정론 우선, LLM은 잔여만 |
| 그래프 저장소 | 노드·엣지 수, 벡터 내장 여부 | 트리플에 근거 ID만 저장, 원문은 청크 저장소 참조 |
| 재구축 | 증분 불가 구조 | 증분 지원 방식 선택, 문서 단위 삭제·재삽입([07](07-freshness-and-sync.md)) |

## 아키텍처 / 파이프라인

[`kg-construction-pipeline.html`](../assets/html/kg-construction-pipeline.html)이 이 흐름을 그린다.

```
청크 (02/03) ─┬─ 서술문 ─▶ LLM 추출 (스키마 프롬프트) ─┐
              └─ 정형·표·메타 ─▶ 규칙 매핑 ──────────────┼─▶ 후보 트리플 (주어, 관계, 목적어, 근거 청크·문장 ID, 추출기 버전)
                                                        ▼
                             온톨로지 정렬 (클래스·관계 정규화) ─▶ SHACL/규칙 검증 ─▶ 거부·미분류 버킷
                                                        ▼
                             엔티티 해소 (결정론 → 유사도 → 판정 모델 → 사람) ─▶ 정규 ID, sameAs
                                                        ▼
                             그래프 적재 (LPG 또는 RDF) + 청크 역참조 ─▶ 인덱싱 (GraphRAG | LightRAG | HippoRAG 2 식)
                                                        ▲
                             증분 갱신 루프: 문서 변경 이벤트 → 해당 문서 유래 트리플 삭제 → 재추출 → 재해소 → 부분 재인덱싱
```

출력은 **근거 ID가 붙은 트리플**과 그 위의 인덱스다. 근거 ID가 없는 트리플은 [08](08-grounding-data-design.md)에서 인용할 수 없으므로 파이프라인이 거부해야 한다.

## 기술 비교표 — 이 단계에서 쓸 수 있는 선택지

| 기술 / 접근 | 적합한 상황 | 부적합한 상황 | 비용·복잡도 | 성숙도 | 검증 수준 |
|---|---|---|---|---|---|
| LLM 추출 (스키마 제약) | 서술형 문서, 표현 다양, 스키마가 자주 바뀜 | 정형 데이터(불필요 비용), 결정론·재현 요구, 수백만 청크 저예산 | 상 (청크당 호출) | 안정 | `[2차]` 스키마 위반·환각 관계 널리 보고 |
| 규칙·패턴 추출 | 정형·반정형, 고정 양식, 설명 가능성·결정론 필요 | 자유 서술문, 표현 변형 많음 | 하(실행) / 중(유지) | 표준 | `[검증]` 전통 IE |
| 하이브리드 추출 | 대부분의 엔터프라이즈(정형 + 비정형 혼재) | 소스가 한 종류뿐 | 중 | 안정 | `[2차]` |
| 스키마 없는 추출 (GraphRAG 기본) | 탐색적 분석, 코퍼스 구조 파악 PoC | 운영, 검증·설명 필요 | 하(초기) / 상(유지) | 안정 | `[2차]` 관계 폭발 문제 |
| 온톨로지 정렬 + SHACL 검증 | 운영, 규제, 멀티 소스 통합 | 온톨로지 없음, 일회성 분석 | 중 (온톨로지 유지) | 표준(W3C SHACL) | `[검증]` 표준 / 효과는 `[2차]` |
| 엔티티 해소 — 결정론·블로킹·유사도 | 정형 ID나 별칭 사전이 있는 도메인 | ID 없는 인명·조직명만 있는 텍스트 | 하~중 | 표준 | `[검증]` 레코드 연계 문헌 |
| 엔티티 해소 — 판정 모델(결정 모델/분류기/LLM) | 잔여 저확신 쌍, 대량 | 전체 쌍에 적용(비용 제곱) | 중 | 신생(결정 모델) / 안정(분류기) | `[벤더]` 결정 모델 / `[2차]` LLM |
| Microsoft GraphRAG 식 인덱싱 | 코퍼스 전체 요약·주제 질의가 핵심, 갱신 드묾 | 잦은 갱신, 비용 민감, 사실 조회 중심 | 상 | 안정 | `[벤더]` `[2차]` 비용 비판 |
| LightRAG 식 인덱싱 | 증분 갱신 필수, 비용 제약, 엔티티·주제 이중 질의 | 전체 요약 질의 | 중 | 신생~안정 | `[2차]` |
| HippoRAG 2 식 인덱싱 | 최난도 멀티홉이 실제 질의의 핵심 | 단순 사실 조회(이점 없음), 포맷 효과를 기대한 채택 | 중~상 | 신생 | `[검증]` MuSiQue에서만 뚜렷한 우위 |

### 선택 가이드

- **멀티홉·동일성 질문이 질의 로그에서 확인되지 않는다면** → 그래프를 올리지 않는다. 이유: 인덱싱 비용만 들고 벡터 대비 이득이 없다 `[2차]` 실무자 합의
- **정형 데이터(조직도·마스터·티켓)가 섞여 있다면** → 하이브리드 추출, 정형은 규칙. 이유: LLM 비용을 서술문에만 쓴다
- **문서가 자주 바뀐다면** → LightRAG 식 증분 지원 인덱싱 + 문서 단위 삭제·재삽입. 이유: GraphRAG 식 커뮤니티 재계산은 사실상 재구축
- **코퍼스 전체 주제 요약 질의가 핵심이라면** → GraphRAG 식 커뮤니티 요약, 단 갱신 주기를 길게. 이유: 글로벌 질의는 커뮤니티 요약 외 대안이 약하다
- **최난도 멀티홉이 핵심이고 그 비율이 높다면** → HippoRAG 2 식 PPR 검색을 평가셋으로 `[실측]`. 이유: 포맷 통제 후 우위가 확인된 유일한 영역이 MuSiQue 급 멀티홉 `[검증]`
- **판단이 어려우면** → 기본값: 경량 온톨로지 + 하이브리드 추출 + SHACL 검증 + LPG 적재 + 증분 지원 인덱싱, 커뮤니티 요약 없음. 이유: 비용을 통제하면서 어느 인덱싱 방식으로도 갈 수 있다

## 설계 시 고려사항 (체크리스트)

- [ ] 질의 로그에서 멀티홉·동일성·설명 요구의 **실제 비율**을 확인했는가
- [ ] 추출 스키마의 클래스가 30개 이내, 관계에 도메인·레인지가 있는가([06](06-ontology-driven-modeling.md))
- [ ] 정형 데이터는 규칙으로, 서술문만 LLM으로 추출하는가
- [ ] 샘플 200건으로 추출 정밀도·재현율·스키마 위반율을 `[실측]`했는가
- [ ] 모든 트리플이 근거 청크·문장 ID를 갖고, 없으면 적재가 거부되는가
- [ ] 스키마 위반·미분류 트리플의 버킷과 주기적 검토 절차가 있는가
- [ ] 엔티티 해소가 결정론 → 유사도 → 판정 모델 → 사람 순이고, 병합 대신 `sameAs` 링크로 가역적인가
- [ ] 문서 변경 시 해당 문서 유래 트리플을 식별·삭제·재추출할 수 있는가(트리플에 출처 문서 ID)
- [ ] 인덱싱 방식 선택 이유가 질의 유형(요약 / 엔티티 / 멀티홉)으로 설명되는가
- [ ] 벤치마크 우위 주장을 자기 평가셋으로 재확인했는가(포맷 효과 주의)
- [ ] 추출기·온톨로지 버전이 트리플 메타데이터에 기록되는가([03](03-metadata-provenance.md))

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 추출 LLM의 환각 관계 | 원문에 없는 관계가 그래프에 들어가 "근거 있는 환각"이 됨 | 근거 문장 필수 + 근거-트리플 정합성 검증(NLI 또는 판정 모델), 저확신 거부 |
| 인덱싱 비용이 서빙 비용을 초과 | 문서 수 증가 시 그래프 유지가 예산을 압박 | 추출 대상 문서 유형 제한, 규칙 우선, 소형 모델, 증분 갱신 |
| 엔티티 해소 오류 (과병합·과분리) | 과병합은 틀린 경로, 과분리는 경로 끊김 | 가역적 `sameAs`, 확신도 기록, 샘플 감사 |
| 벤치마크의 포맷 효과 | 보고된 우위가 자기 환경에서 재현 안 됨 | 재분석 `[검증]` 참고, 자체 평가셋 `[실측]` |
| 그래프와 벡터 인덱스의 불일치 | 문서 갱신이 한쪽에만 반영 | 같은 변경 이벤트가 두 경로를 모두 트리거([07](07-freshness-and-sync.md)) |
| 온톨로지 변경 시 그래프 마이그레이션 | 클래스 분리·관계 개명이 전체 재정렬 요구 | 온톨로지 버전 관리, 매핑 테이블, 점진 마이그레이션([06](06-ontology-driven-modeling.md)) |
| 그래프 벤더 프레이밍 | "온톨로지 필수·GraphRAG 필수" 서사가 벤더 주도 | 요구 확인 후 채택, 벡터만으로 되는지 먼저 시험 |

## 운영 설계 — 확장성 · 안정성 · 유지보수

용어·판단 기준은 [Part 1/07 운영 용어](../01-foundations/07-operations-vocabulary.md). 그래프 경로는 벡터 경로의 **보조 경로**로 운영한다. 그래프가 죽어도 벡터 검색은 살아 있어야 하고, 그래프의 적재 게이트(SHACL·근거 필수)는 Part 2에서 가장 두꺼운 **출력 가드레일**이다. 비용 구조는 [핵심 개념 — 비용 구조] 참조.

### 확장성 — 10배가 되면 무엇이 먼저 깨지는가

| 확장 축 | 10배 시 깨지는 것 | 설계 수단 | 비용이 비례하는 변수 |
|---|---|---|---|
| 데이터 (청크·엔티티 수) | 추출 LLM 비용이 선형으로 늘어 인덱싱이 서빙 비용을 초과. 엔티티 해소 후보 쌍이 블로킹 없으면 제곱. 커뮤니티 요약은 노드 하나 바뀌어도 재계산 | 정형은 규칙 추출, 추출 대상 문서 유형을 설정으로 제한, 추출 모델 티어 하향(소형 모델 + 검증기), 블로킹 키(클래스·이니셜·도메인) 필수, 증분 지원 인덱싱, 커뮤니티 요약은 글로벌 질의가 확인될 때만 | 청크 수 × 길이(추출), 블록 내 엔티티 수²(해소), 커뮤니티 수(요약) |
| 도메인·클래스 수 | 프롬프트에 넣는 스키마가 길어져 추출 위반율↑, 토큰 비용↑ | 문서 유형별 스키마 부분집합 주입, 클래스 ≤ 30([06](06-ontology-driven-modeling.md)) | 클래스 수 × 청크 수 |
| 테넌트 | 공통 엔티티 노드가 테넌트 경계를 흐림, 해소가 테넌트 간 병합 | 엣지·트리플 단위 `tenant_id`, 해소는 테넌트 안에서만 또는 공개 노드만 공유 | 테넌트 수 × 엔티티 수 |

추출·해소 워커는 무상태로 두고 문서 단위로 병렬화한다. 전체 재추출(모델·온톨로지 메이저 변경)은 서빙과 분리된 배치 창에서 문서 유형별 파티션으로 실행하며, 창 안에 못 끝나면 **추출 모델 티어를 낮추거나 대상 유형을 줄이는** 결정을 먼저 한다.

### 운영 안정성 — 장애 모드와 대응

| 장애 모드 | 사용자에게 보이는 증상 | 탐지 신호 | 자동 대응 (폴백·저하) | 사람 개입 기준 |
|---|---|---|---|---|
| 추출 LLM API 다운 (의존 서비스 다운) | 그래프 경로가 새 문서를 모름. 벡터 경로는 정상 | 추출 큐 적체, 호출 오류율 | 큐 보존(백프레셔), 그래프 경로에 `graph_lag` 플래그. Part 3 라우터가 멀티홉 질의에 "그래프 최신성 미보장" 저하 표시 | 적체가 그래프 신선도 SLO(예: 24h) 초과 → 티어 하향 또는 대상 축소 결정 |
| 그래프 저장소 다운·지연 급증 | 멀티홉 답변 실패 또는 지연 | 저장소 가용성·p95, 경로 질의 타임아웃 | 서킷 브레이커 → **그래프 경로 비활성(킬 스위치)**, 벡터 단독으로 저하. 응답에 `retrieval_mode=vector_only` | 비활성 예시 30분 초과 → 온콜 |
| SHACL·근거 검증 위반 폭증 (검증 실패 폭증) | 미분류 버킷 급증, 신규 트리플 적재 정체 | 위반율이 베이스라인 대비 급변(예: 5%p), 위반 유형 분포 | 위반 트리플은 적재 거부 → 버킷. 적재는 계속하되 위반율이 임계 초과 시 해당 문서 유형 추출 **일시 중단** | 프롬프트·모델·온톨로지 중 최근 변경 역추적. 벤더 모델 묵시 업데이트 의심 시 버전 고정 확인 |
| 그래프 ↔ 벡터 불일치 (데이터 불일치) | 같은 질문에 두 경로 답이 다름 | 경로별 신선도 지연 차, 문서별 `pipeline_version` 비교 | 단일 변경 큐([07](07-freshness-and-sync.md))가 구조적 방지. 불일치 문서는 재처리 큐로 | 지연 차가 예시 1h 초과 지속 |
| 엔티티 과병합 (단계 고유) | 다른 사람·조직이 하나로 섞여 틀린 경로 | 샘플 감사 오류율, 노드당 별칭 수 이상치, 사용자 신고 | `sameAs` 링크 해제(가역). 해당 노드 유래 경로를 재계산 | 확신도 임계 하향 또는 블로킹 키 재설계 |
| 환각 관계 유입 (단계 고유) | 원문에 없는 관계가 인용됨 | 근거-트리플 정합성 판정(NLI) 불합격률, 하류 검증기 실패율 | 정합성 미달 트리플 적재 거부 또는 등급 하향([08](08-grounding-data-design.md)) | 특정 관계 유형에 집중되면 프롬프트·스키마 정의 수정 |

SLI 후보: ① SHACL·근거 검증 통과율 ② 추출 정밀도(월 1회 샘플 200건 사람 검수) ③ 그래프 신선도 지연 p95(벡터 지연과 차이) ④ 근거 ID 보유 트리플 비율. SLO 초안(예시): 통과율 ≥ 90%(위반은 버킷으로 가므로 품질 지표), 정밀도 ≥ 85%, 근거 보유 = 100%(게이트 보장), 지연 차 ≤ 1h. 쓰기 행동의 멱등성: 트리플 키는 `(s, p, o, evidence_sentence_id, extractor_version)`, 문서 단위 "엣지 삭제 → 재적재"가 멱등. 노드 병합은 비가역이므로 하지 않고 `sameAs` 링크만. 추출 호출은 `(chunk_id, content_hash, prompt_version, model_version)` 캐시로 재시도 시 재과금 방지, 재시도 상한 예시 3회.

### 유지보수 — 버전·변경·호환

| 버전 관리 대상 | 바꾸면 영향받는 것 | 회귀 테스트 | 함께 배포할 것 (호환) |
|---|---|---|---|
| 추출 프롬프트·스키마 주입 형식 | 추출 결과 분포, 위반율 | 샘플 200건 정밀도·재현율·위반율 | 추출기 버전 태그, 영향 문서 유형 재추출 계획 |
| 추출 모델 (LLM·소형 모델) 버전 | 모든 신규 트리플 | 같은 샘플 골든셋 | 프롬프트-모델 호환 확인, `extractor_version` |
| 온톨로지 버전 ([06](06-ontology-driven-modeling.md)) | 정렬·검증·추출 레이블, 그래프 라벨 | 범위 질문 재검수, 위반율 | SHACL shapes, 매핑 테이블, 마이그레이션 스크립트 |
| SHACL shapes·검증 규칙 | 적재 통과율 | 골든 트리플셋 통과·거부 테스트 | 기존 트리플 재검증 배치(재추출 없음) |
| 엔티티 해소 규칙 (별칭 사전·블로킹 키·임계값·판정 모델 버전) | 노드 정규 ID, 경로 연결성 | 라벨된 쌍 셋 정밀도·재현율 | `sameAs` 재계산 배치 |
| 인덱싱 방식 설정 (GraphRAG / LightRAG / HippoRAG 2 식 파라미터) | 질의 시 검색 동작 | 멀티홉 평가셋 | Part 3 그래프 검색 어댑터 |
| 그래프 저장소 버전 | 질의 문법·인덱스 | 업그레이드 리허설 | 저장소 어댑터 |

롤백 단위는 "프롬프트 + 추출 모델 + 온톨로지 + SHACL" 묶음(트리플 메타데이터에 넷 다 기록). 기술 부채로 기록할 것: 커뮤니티 요약 미도입 결정과 재검토 조건(글로벌 질의 비율), 판정 모델 미검증으로 해소 ③단계를 LLM으로 두는 범위, 블로킹 키가 없는 클래스, 재추출 비용 때문에 구 `extractor_version` 트리플을 유지 중인 문서 유형.

| 변화 유형 | 이 단계에서 바뀌는 것 | 안정적으로 유지할 계약·인터페이스 | 교체 가능한 구현 | 흡수 방식 | 전파 범위 |
|---|---|---|---|---|---|
| **지식** (가장 잦음) | 문서 변경 → 해당 문서 유래 트리플 교체, 새 엔티티 등장 | 트리플 스키마(근거 ID 포함), 정규 ID 체계 | — | 문서 단위 엣지 삭제·재추출·재해소(증분, 재배포 없음). 고아 노드는 배치 정리 | 해당 문서 트리플 + 재해소된 노드의 경로 |
| **도메인 모델** (두 번째) | 클래스·관계 추가·개명·병합·분할 | 상위 클래스, 매핑 테이블, 정규 ID | 라벨 값 | 개명·병합은 매핑 테이블로 **라벨 이전(재추출 없음)**. 분할·레인지 변경은 영향 클래스만 재추출 | 추출 프롬프트 레이블, SHACL, 필터 어휘, 08 경로 렌더 어휘 |
| **모델** | 추출 LLM 교체·벤더 교체, 해소 판정 모델 교체 | `extract(chunk, schema) → [candidate_triple]`, `same_entity(a, b) → {bool, confidence}` 포트 | 추출 어댑터(LLM / 소형 모델 / 규칙), 판정 어댑터(분류기 / 결정 모델 / LLM) | 어댑터 교체 + 섀도(새 모델 결과를 적재 않고 비교) + 골든셋 → 영향 문서 유형 재추출 창 | 재추출 대상 트리플 전체 |
| **규칙·정책** | SHACL 제약 강화, 근거 정합성 임계값, 해소 확신도 임계값 | 검증 인터페이스(`validate(triple, shapes_vN)`) | shapes·임계값 설정 | shapes 버전 + 기존 트리플 재검증 배치(재추출 없음), 불합격은 버킷으로 이동 | 그래프 전체 재검증(저비용) |
| **사용자 환경** | 새 테넌트·도메인 추가, 조직 개편 | 트리플 `tenant_id` | 블로킹·해소 범위 설정 | 테넌트별 해소 범위 설정, 조직은 정형 소스에서 규칙 추출로 자동 갱신 | 해당 테넌트 트리플 |
| **프로토콜** | 그래프 저장소 교체(LPG ↔ RDF), 질의 언어 변경 | 그래프 쓰기·질의 포트 | 저장소 어댑터 | 어댑터 교체 + 전체 마이그레이션 1회 | 저장소 경계 + Part 3 그래프 검색 어댑터 |

가장 자주 바뀌는 것: **지식**(문서) — 문서 단위 증분으로 흡수. 그 다음 **도메인 모델**(온톨로지 변경). 온톨로지 변경을 **재추출 없이 매핑 테이블로 흡수하는 범위**를 최대화하는 것이 이 단계 변화 대응의 핵심이다. 코드 밖 설정으로 둘 것: 스키마 주입 레이블(매핑 테이블에서), SHACL shapes, 별칭 사전, 블로킹 키·임계값, 문서 유형 → 추출 경로(규칙/LLM) 라우팅, 추출 대상 유형 목록, 인덱싱 방식 파라미터. 포트·어댑터 뒤에 둘 외부 의존: 추출 LLM, 해소 판정 모델(결정 모델 포함, [09](09-ai-inside-the-pipeline.md)), NLI 검증기, 그래프 저장소. 시점 재현성: 트리플에 `extractor_version` + 온톨로지 버전 + 근거 문장 ID가 있어야 "그때 그 경로"를 재구성한다.

### 거버넌스 접점 — 정책 · 가드레일 · 승인 · 감사

| 항목 | 이 단계에서의 답 |
|---|---|
| 위험 등급 (1~5, 가역성 × 영향 범위) | 트리플 적재는 **등급 2**(여러 사용자 답변에 영향, 재추출로 가역이나 비용 큼). 노드 **병합**은 부분 가역이라 등급 3이 되므로 하지 않고 `sameAs` 링크(등급 2 유지). 온톨로지 메이저 마이그레이션은 [06](06-ontology-driven-modeling.md)의 등급 3 |
| 가드레일 위치 (입력 / 출력 / 행동) | **출력**: 적재 전 게이트(온톨로지 정렬 → SHACL → 근거 ID 필수 → 정합성). Part 2에서 가장 두꺼운 출력 가드레일. **행동**: 그래프 경로 킬 스위치, 전체 재추출 실행은 승인 게이트(비용 이벤트) |
| 게이트 출력 (통과 / 차단 / 승인 / 저하)과 판정 수단 | 통과 / 차단(SHACL 위반·근거 없음 → 버킷) / 저하(정합성 저확신 → 등급 하향 적재) / 승인(전체 재추출). 판정 수단은 **규칙(SHACL) → 판정 모델(NLI·결정 모델) 순**. LLM이 최종 결정권을 갖지 않는다(Rule ∧ Model) |
| 소유자 (A) | 도메인 소유자(그래프 내용·온톨로지), 데이터 엔지니어링 책임자(파이프라인). 데이터 엔지니어가 R, AI 엔지니어가 C |
| 감사 추적에 남길 필드 | 트리플별 `extractor_version`·프롬프트 버전·온톨로지 버전·SHACL 버전, 근거 청크·문장 ID, 정합성 판정값·수단, 해소 결정(방법·확신도·`sameAs` 링크 이력), 버킷 사유, 재추출 실행 이력(범위·승인자) |

### 운영 준비도 체크
- [ ] 그래프 저장소 다운 시 그래프 경로 킬 스위치가 있고 벡터 단독 저하가 자동인가
- [ ] 적재 게이트가 SHACL·근거 ID·정합성을 순서대로 적용하고 위반은 버킷으로 가는가
- [ ] 트리플 키가 결정론적이고 문서 단위 삭제·재적재가 멱등한가
- [ ] 추출 호출이 `(content_hash, prompt_version, model_version)`으로 캐시되어 재시도 시 재과금되지 않는가
- [ ] 위반율·정밀도 샘플·그래프 신선도 지연이 SLI로 측정되고 임계 초과 시 추출 중단 규칙이 있는가
- [ ] 온톨로지 개명·병합이 매핑 테이블로 재추출 없이 처리되는 범위가 정의되어 있는가
- [ ] 추출·해소 모델 교체가 포트 뒤 어댑터 교체 + 섀도 비교로 가능한가
- [ ] 전체 재추출이 배치 창·파티션·티어 하향 결정 규칙과 함께 승인 게이트를 거치는가
