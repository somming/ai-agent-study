# 접근 제어와 거버넌스

> **범위**: ACL-aware retrieval, PII 마스킹, 멀티테넌시, 데이터 보존 정책
> **시각화**: [`assets/html/data-pipeline-architecture.html`](../assets/html/data-pipeline-architecture.html) — "동기화·ACL" 노드

## 요약 (3줄)

1. RAG의 접근 제어는 "사용자가 볼 수 없는 문서가 **검색 결과에도, 컨텍스트에도, 답변에도** 들어가지 않는다"는 것이다. 셋 중 하나만 막으면 누출이다. 프롬프트로 "권한 없는 내용은 말하지 마"라고 쓰는 것은 접근 제어가 아니다.
2. 강제 지점은 세 가지 패턴(인덱스 분리 / 메타데이터 필터 / 쿼리 시 ACL 조인) 중 하나 이상이고, 어느 패턴이든 **검색 전(pre-filter)에 적용**하고 **렌더 전에 재확인**한다. 소스 권한 변경이 인덱스에 전파되는 경로([07](07-freshness-and-sync.md))가 없으면 모든 패턴이 무의미하다.
3. PII는 **가능한 한 이른 시점**(수집·파싱 직후)에 탐지·분류하고, 마스킹 시점은 용도에 따라 달리한다. 인덱스에 들어간 PII는 임베딩에서도 삭제가 어렵다. 보존·삭제 정책은 "원본 삭제 = 파생물 전체 삭제"가 되게 처음부터 계보를 설계한다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | ① 권한 모델(주체·그룹·테넌트·기밀 등급)과 인덱스 강제 패턴 ② 소스 ACL → 인덱스 ACL 동기화 경로 ③ PII 탐지·분류·마스킹 정책(시점·방식·예외) ④ 멀티테넌시 격리 수준 ⑤ 보존 기간·삭제 요청 처리·삭제 증명 ⑥ 감사 로그(누가 무엇을 검색·열람했나) |
| **언제** (When) | 소스에 권한이 있거나 PII가 있거나 테넌트가 둘 이상이면 **처음부터**. 생략 가능: 전 직원 공개 문서만, 단일 테넌트, PII 없음 — 이 셋을 모두 **확인**했을 때만. 미뤄도 되는 것: 테넌트별 물리 분리(논리 분리로 시작), 삭제 증명 자동화 |
| **어떻게** (How) | ① 소스별 권한 모델 조사(ACL 형태, 그룹 해석 방식, 변경 빈도) → ② 강제 패턴 선택(아래 비교표) → ③ 메타데이터에 `acl`, `tenant_id`, `classification`, `pii_flags` 필수화([03](03-metadata-provenance.md)) → ④ 검색 전 필터 + 렌더 전 재확인(`acl_checked`) → ⑤ PII 탐지를 파싱 직후에, 마스킹 시점·방식 결정 → ⑥ 소스 권한 변경 → 인덱스 전파 경로 → ⑦ 보존·삭제 정책과 계보 기반 파생물 삭제 → ⑧ 감사 로그 + 정기 권한 대조 |
| **왜** (Why) | 권한 없는 문서가 컨텍스트에 들어가면 모델이 "말하지 않아도" 답변에 영향을 주고, 로그에 남는다. 후 필터(post-filter)만 쓰면 결과 수가 모자라거나 순위가 왜곡된다. PII를 인덱싱 뒤에 발견하면 벡터·BM25·그래프·캐시·로그에서 모두 지워야 하는데 임베딩에선 "부분 삭제"가 안 된다 |

## 문제와 맥락

RAG는 **권한 경계를 가로질러 데이터를 모으는** 시스템이다. 인사·재무·고객·개발 문서가 한 인덱스에 들어가고, 한 질문이 모든 컬렉션을 훑는다. 이것이 RAG의 가치이자 위험이다.

- **검색 누출**: 사용자가 못 보는 문서가 top-k에 들어가 컨텍스트로 모델에 전달된다. 모델이 그 내용을 직접 인용하지 않아도 답변에 영향을 주고, 트레이스·로그에 남는다
- **권한 드리프트**: 퇴사·부서 이동·공유 해제가 소스에선 반영됐지만 인덱스의 ACL은 색인 당시 그대로다
- **PII 확산**: 메일·채팅·티켓에 섞인 주민번호·전화번호·계좌가 청크·벡터·캡션·요약·캐시에 복제된다. 삭제 요청이 오면 어디까지 지워야 하는지 모른다
- **테넌트 혼선**: SaaS형 서비스에서 A사 질문에 B사 문서가 유사도로 끌려온다
- **보존 위반**: 보존 기간이 지난 문서가 "검색은 안 되지만 저장소에 남아" 규제 위반이 된다

이 단계는 위 문제를 **데이터 구조와 강제 지점**으로 막는다. [Part 5/01](../05-cross-cutting/01-security-prompt-injection.md)의 인젝션 방어, [Part 5/04](../05-cross-cutting/04-governance-explainability.md)의 규제 대응과 짝을 이룬다.

## 핵심 개념

### 강제 패턴 세 가지

| 패턴 | 동작 | 장점 | 단점 | 적합 |
|---|---|---|---|---|
| **인덱스 분리** | 권한 경계(테넌트·기밀 등급·부서)마다 별도 인덱스/컬렉션. 사용자는 허용된 인덱스만 검색 | 격리가 물리적, 누출 경로 단순, 필터 후 결과 부족 없음 | 인덱스 수 폭발(경계가 많으면), 교차 검색 시 결과 병합, 문서가 여러 경계에 속하면 중복 저장 | 테넌트 격리, 기밀 등급 소수 |
| **메타데이터 필터** | 청크마다 `acl`(허용 주체/그룹 목록) 저장, 검색 시 사용자의 주체 집합과 교집합 조건을 **사전 필터**로 | 단일 인덱스, 문서별 세밀 권한 | 그룹 해석(중첩 그룹)을 색인 시 평탄화해야 함, ACL 변경 시 청크 메타데이터 갱신, 벡터DB 필터 표현력 한계 | 문서별 ACL이 다양한 사내 문서 |
| **쿼리 시 ACL 조인** | 인덱스엔 `doc_id`만, 검색 후보를 권한 서비스(또는 소스 시스템)에 실시간 조회해 걸러냄 | 항상 최신 권한, 소스가 단일 진실 원천 | 지연(후보 수만큼 조회), 후 필터라 결과 부족·순위 왜곡, 권한 서비스 장애 시 검색 불가 | 권한이 매우 자주 바뀌고 지연 허용 |

운영에선 **조합**한다. 테넌트는 인덱스 분리, 테넌트 안의 문서 권한은 메타데이터 사전 필터, 렌더 직전에 소스 권한 재확인(쿼리 시 조인의 축소판). 어느 패턴이든 citation의 `acl_checked`([08](08-grounding-data-design.md))를 렌더 전에 반드시 세운다.

### 사전 필터 vs 후 필터

| | 사전 필터 (pre-filter) | 후 필터 (post-filter) |
|---|---|---|
| 동작 | 권한 조건을 만족하는 벡터만 대상으로 top-k | top-k 뽑은 뒤 권한 없는 것 제거 |
| 결과 수 | 보장 | 권한 없는 것이 많으면 k 미만 |
| 순위 | 왜곡 없음 | 권한 있는 하위 결과가 누락 |
| 누출 | 없음 | 제거 전 후보가 메모리·로그에 존재 |
| 저장소 요구 | 필터 결합 ANN 지원 필요 | 모두 가능 |

후 필터는 **보조**로만 쓴다(사전 필터가 놓친 것의 2차 방어). 주 강제 지점이 후 필터면 설계를 다시 한다.

### PII: 탐지 시점과 마스킹 시점

탐지와 마스킹은 다르다. **탐지는 항상 이르게**(파싱 직후), **마스킹은 용도별로**.

| 마스킹 시점 | 동작 | 장점 | 단점 | 적합 |
|---|---|---|---|---|
| **수집·파싱 직후** | 인덱스에 들어가기 전 마스킹·토큰화. 원본은 별도 보관(또는 폐기) | 인덱스·벡터·캐시·로그 어디에도 PII 없음. 삭제 요청이 단순 | 마스킹된 값으로는 답 못 함("고객 전화번호는?"), 오탐 시 정보 손실 | 대부분. PII가 답변에 필요 없는 경우 |
| **인덱싱 시** | 임베딩·BM25에는 마스킹본, 원문 저장소에는 원본 + 접근 통제 | 검색은 안전, 권한 있는 사용자는 원문 열람 | 원문 저장소가 보호 대상, 렌더 시 권한 확인 필요 | PII가 근거 열람에 필요한 업무 |
| **응답 시** | 인덱스엔 원본, 모델 출력에서 마스킹 | 모델이 PII를 보고 추론 가능 | 인덱스·컨텍스트·로그에 PII 존재. 출력 필터 누락 시 누출 | 권장하지 않음. 규제 검토 후 극히 제한적으로 |

탐지 수단은 규칙(패턴: 주민번호·전화·계좌·이메일) → 전용 NER/PII 모델 → 저확신만 사람([09](09-ai-inside-the-pipeline.md)). 마스킹 방식은 삭제·대체 토큰(`[PHONE]`)·가명화(일관 해시, 동일인 추적 가능)·암호화(복호 권한 분리) 중 용도로 고른다. **임베딩은 마스킹 불가**다. PII가 벡터에 들어가면 그 벡터를 지우는 수밖에 없다.

### 멀티테넌시 격리 수준

| 수준 | 동작 | 격리 강도 | 비용 |
|---|---|---|---|
| 논리 (메타데이터 `tenant_id` 필터) | 단일 인덱스, 모든 쿼리에 테넌트 필터 강제 | 중 (필터 누락 = 누출) | 하 |
| 컬렉션 분리 | 테넌트별 컬렉션/네임스페이스, 같은 클러스터 | 중~상 | 중 |
| 인스턴스·DB 분리 | 테넌트별 인프라 | 상 | 상 |
| 암호화 키 분리 | 위 어느 수준 + 테넌트별 키 | 상 (데이터 거주·삭제 증명 용이) | 중 (키 관리) |

규제·계약이 요구하는 수준으로 정하되, **필터 강제를 애플리케이션 코드 한 곳**(검색 게이트웨이)에 두어 누락이 구조적으로 불가능하게 한다. 그래프는 노드가 테넌트 간 공유될 수 있으므로(공통 엔티티) 엣지·트리플 단위로 `tenant_id`를 둔다.

### 보존·삭제

| 항목 | 규칙 |
|---|---|
| 보존 기간 | 문서 유형 택소노미별로 정의. `valid_to` 또는 `retention_until`로 메타데이터에 |
| 만료 처리 | 톰스톤(검색 제외) → 유예 → 물리 삭제. 규제가 즉시 삭제를 요구하면 유예 없음([07](07-freshness-and-sync.md)). 보존 만료 + 유예 경과 후의 **정책 배치 삭제 = 위험 등급 4**(유예 중 가역, 승인은 정책 승인으로 갈음) |
| 삭제 요청 (정보주체 권리) | 원본 `doc_id` → 계보로 **모든 파생물** 식별(청크·벡터·BM25·트리플·캡션·요약·캐시) → 삭제 → 삭제 증명(무엇을 언제 지웠나). 요청·일괄 **물리 삭제 = 위험 등급 5**(에이전트는 대상 목록 제안만, 실행은 사람) |
| 로그·트레이스 | 컨텍스트에 들어간 근거 텍스트가 트레이스에 남으면 그것도 삭제 대상. 본문 기록은 opt-in으로([Part 5/03](../05-cross-cutting/03-observability-tracing.md)) |
| 백업 | 백업에 남은 PII의 처리 정책(보존 기간 내 자동 만료) |

"원본 삭제 = 파생물 전체 삭제"는 [03](03-metadata-provenance.md)의 계보가 있어야 가능하다. 파생물에 출처 `doc_id`가 없으면 삭제 요청을 이행할 수 없다.

물리 삭제의 위험 등급 라벨은 **이 페이지가 기준**이다: **정책 배치 삭제 = 등급 4**(보존 만료 + 유예 경과, 유예 중 가역, 정책 승인으로 갈음) / **요청·일괄 물리 삭제 = 등급 5**(제안만, 사람 실행). [07](07-freshness-and-sync.md)과 [Part 1/07](../01-foundations/07-operations-vocabulary.md)이 이 구분을 참조한다(불균형 ⑧ 반영).

## 아키텍처 / 파이프라인

```
소스 (ACL, 테넌트, 분류) ─▶ 01 수집: ACL 복사 + 그룹 평탄화 ─▶ 01 파싱 직후: PII 탐지 (규칙 → 모델) ─▶ 마스킹 정책 적용
        ─▶ 03 메타데이터: acl, tenant_id, classification, pii_flags, retention_until (필수, 누락 시 거부)
        ─▶ 04/05 인덱스: [테넌트별 분리] + [메타데이터 사전 필터]
        ─▶ 질의 시: 검색 게이트웨이 (사용자 주체 집합 해석 → 사전 필터 강제) ─▶ 후보 ─▶ 렌더 전 재확인 (acl_checked) ─▶ 08 citation
소스 권한 변경 ─▶ 07 변경 큐 (유형: acl) ─▶ 메타데이터 갱신 / 인덱스 이동
삭제 요청 ─▶ 계보 조회 ─▶ 파생물 전체 삭제 ─▶ 삭제 증명
감사 로그: 누가 · 언제 · 어떤 필터로 · 무엇을 검색·열람
```

검색 게이트웨이가 **단일 강제 지점**이다. 에이전트·툴·배치가 인덱스를 직접 치지 않고 반드시 게이트웨이를 거치게 한다.

## 기술 비교표 — 이 단계에서 쓸 수 있는 선택지

| 기술 / 접근 | 적합한 상황 | 부적합한 상황 | 비용·복잡도 | 성숙도 | 검증 수준 |
|---|---|---|---|---|---|
| 인덱스 분리 | 테넌트 격리, 기밀 등급 소수(3~5), 규제상 물리 격리 | 문서별 ACL이 수백 종, 교차 검색 빈번 | 중 (인덱스 수 관리) | 표준 | `[검증]` 격리 일반론 |
| 메타데이터 사전 필터 | 문서별 ACL 다양, 단일 인덱스 선호, 저장소가 필터 결합 ANN 지원 | 그룹 중첩이 깊어 평탄화 불가, 저장소가 후 필터만 지원 | 중 | 안정 | `[2차]` |
| 쿼리 시 ACL 조인 (권한 서비스 실시간) | 권한 변경 매우 잦음, 지연 허용, 렌더 전 재확인 용도 | 주 강제 지점으로 단독 사용(후 필터 문제), 저지연 | 중~상 (지연·의존) | 안정 | `[2차]` |
| 조합 (테넌트 분리 + 사전 필터 + 렌더 전 재확인) | 대부분의 운영 환경 | 단일 테넌트·전 직원 공개 (과잉) | 중~상 | 안정 | `[2차]` |
| 프롬프트 지시로 권한 통제 | 없음 (안티패턴) | 모든 운영 | 하 | — | `[검증]` 인젝션·확률적 준수 문제 |
| PII 마스킹 — 수집 직후 | PII가 답변에 불필요, 삭제 요청 대응 단순화 | PII가 업무 근거로 필요 | 중 (탐지 품질) | 표준 | `[검증]` 가명처리 일반 |
| PII 마스킹 — 인덱싱 시 (검색은 마스킹본, 원문은 통제 열람) | PII 열람이 권한 있는 업무에 필요 | 원문 저장소 보호 여력 없음 | 중~상 | 안정 | `[2차]` |
| PII 마스킹 — 응답 시만 | 거의 없음 | 인덱스·로그에 PII 잔존 | 하 | — | `[2차]` 누출 사례 |
| PII 탐지 — 규칙 (패턴) | 형식이 고정된 식별자(주민번호·전화·계좌·이메일) | 자유 서술 속 이름·주소·건강 정보 | 하 | 표준 | `[검증]` |
| PII 탐지 — 전용 NER/PII 모델 | 서술 속 개인정보, 한국어 이름·주소 | 사내 고유 식별자(추가 학습) | 중 | 안정 | `[검증]` NER 일반 / 한국어 `[실측]` |
| 테넌트별 암호화 키 | 데이터 거주·삭제 증명·계약 요구 | 단일 테넌트 | 중 (키 관리) | 표준 | `[검증]` |
| 계보 기반 파생물 삭제 | 삭제 요청·보존 만료가 있는 모든 환경 | — (계보 없으면 불가) | 중 | 안정 | `[검증]` PROV 기반 |

### 선택 가이드

- **테넌트가 둘 이상이라면** → 테넌트는 인덱스(컬렉션) 분리, 필터 강제는 게이트웨이 한 곳. 이유: 필터 한 줄 누락이 타사 데이터 누출이 되는 구조를 피한다
- **사내 문서별 ACL이 다양하다면** → 메타데이터 사전 필터(그룹 평탄화) + 렌더 전 소스 재확인. 이유: 인덱스 분리는 ACL 수만큼 폭발하고, 쿼리 시 조인만으로는 결과 부족
- **PII가 답변에 필요 없다면** → 수집 직후 탐지·마스킹, 원본은 폐기 또는 격리 보관. 이유: 인덱스에 들어간 PII는 삭제 비용이 가장 크다
- **PII 열람이 업무 근거로 필요하다면** → 인덱싱 시 마스킹(검색은 마스킹본) + 원문 통제 열람 + 열람 감사 로그. 이유: 검색 경로를 안전하게 두고 열람만 통제
- **판단이 어려우면** → 기본값: 테넌트 분리 + 메타데이터 사전 필터 + 렌더 전 재확인 + 수집 직후 PII 탐지·마스킹 + 계보 기반 삭제 + 게이트웨이 단일 강제. 이유: 모든 패턴의 공통 하한이고, 완화는 쉽지만 강화는 재색인이다

## 설계 시 고려사항 (체크리스트)

- [ ] 소스별 권한 모델(ACL 형태, 그룹 중첩, 변경 빈도)을 조사했는가
- [ ] 강제 패턴을 선택했고 **사전 필터**가 주 강제 지점인가
- [ ] 검색 게이트웨이가 단일 강제 지점이고 인덱스 직접 접근이 차단되는가
- [ ] `acl`, `tenant_id`, `classification`, `pii_flags`, `retention_until`이 필수 메타데이터이고 누락 시 인덱싱이 거부되는가
- [ ] 렌더 전 `acl_checked`가 설정되고 citation에 기록되는가([08](08-grounding-data-design.md))
- [ ] 소스 권한 변경이 변경 큐를 통해 인덱스 ACL과 Reasoning 결과·시맨틱 캐시 무효화까지 전파되는가([07](07-freshness-and-sync.md), 불균형 ② 반영)
- [ ] PII 탐지가 파싱 직후에 실행되고 한국어 식별자·이름·주소를 평가셋으로 `[실측]`했는가
- [ ] 마스킹 시점·방식이 용도별로 정해져 있고 임베딩에는 PII가 들어가지 않는가
- [ ] 삭제 요청 시 계보로 모든 파생물(청크·벡터·BM25·트리플·캡션·캐시·트레이스)을 식별·삭제·증명할 수 있는가
- [ ] 보존 기간이 문서 유형별로 정의되고 만료가 자동 톰스톤되는가
- [ ] 감사 로그가 누가·언제·어떤 필터로·무엇을 검색·열람했는지 기록하는가
- [ ] 트레이스의 본문 기록이 opt-in이고 PII·기밀이 트레이스에 남지 않는가
- [ ] 정기 권한 대조(소스 vs 인덱스)가 있는가

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 그룹 평탄화의 시차 | 그룹 멤버 변경이 청크 ACL에 늦게 반영 | 주체 집합을 질의 시 해석(그룹 → 사용자 매핑은 실시간), 청크엔 그룹 ID만 |
| 벡터DB 필터 표현력 한계 | 복잡 ACL(부정·중첩)을 사전 필터로 못 씀 | 단순 교집합 조건으로 정규화, 복잡 조건은 렌더 전 재확인 |
| 필터 후 결과 부족 | 강한 권한 제약에서 k 미만 | 사전 필터 + 넓은 후보 수, 테넌트 분리 |
| PII 탐지 오탐·미탐 | 오탐은 정보 손실, 미탐은 누출 | 규칙 + 모델 이중, 저확신 사람 검토, 한국어 `[실측]` |
| 임베딩의 부분 삭제 불가 | PII 포함 벡터는 통째로 삭제 | 수집 직후 마스킹으로 애초에 안 넣음 |
| 그래프의 테넌트 간 공유 노드 | 공통 엔티티 노드가 테넌트 경계를 흐림 | 엣지·트리플 단위 `tenant_id`, 노드는 공개 속성만 |
| 트레이스·캐시·로그의 PII 잔존 | 삭제 요청 이행 불완전 | 본문 기록 opt-in, 캐시 TTL, 삭제 범위에 포함 |
| 권한 서비스 의존 | 장애 시 검색 불가 또는 누출 | 장애 시 **거부**(fail-closed) 기본, 캐시된 권한의 TTL 짧게 |
| 규제 해석 | 개인정보·보존 규정이 국가·산업별로 다름 | 법무 검토, 정책을 메타데이터 규칙으로 코드화 |

## 운영 설계 — 확장성 · 안정성 · 유지보수

용어·판단 기준은 [Part 1/07 운영 용어](../01-foundations/07-operations-vocabulary.md). 이 단계는 Part 2에서 **위험 등급이 가장 높은 행동**(권한 노출·PII·물리 삭제)을 다루며, 안정성의 원칙은 하나다 — **fail-closed**. 권한을 확인할 수 없으면 보여주지 않는다. 강제 패턴·마스킹 시점·보존 규칙은 [핵심 개념] 참조.

### 확장성 — 10배가 되면 무엇이 먼저 깨지는가

| 확장 축 | 10배 시 깨지는 것 | 설계 수단 | 비용이 비례하는 변수 |
|---|---|---|---|
| 테넌트 | 인덱스·컬렉션·암호화 키 수 폭발, 테넌트별 정책 분기가 게이트웨이 코드에 쌓임 | 테넌트 레지스트리를 설정으로(컬렉션·키·정책 참조), 게이트웨이는 레지스트리를 읽는 **무상태 단일 코드 경로**, 테넌트 추가 = 레지스트리 행 추가 | 테넌트 수 × (컬렉션 + 키 + 정책) |
| 사용자·그룹 | 질의마다 주체 집합 해석(IdP·권한 서비스 호출) 지연, 청크당 ACL 목록 비대, 강한 필터로 결과 부족 | 청크엔 **그룹 ID만**, 사용자 → 그룹은 질의 시 해석 + 짧은 TTL 캐시(예: 5분), 사전 필터 지원 저장소, 후보 수 확대 | QPS × 주체 해석 비용, 그룹 수 × 청크 수 |
| 데이터 (문서·페이지) | PII 탐지 모델 호출이 페이지 수에 비례, 삭제 요청 시 계보 탐색 시간 | 규칙(패턴) 1차 → 플래그된 소스·유형만 모델, 계보 저장소에 `doc_id` 역인덱스로 파생물 조회를 상수 시간으로 | 페이지 수(PII 모델), 삭제 요청 수 × 파생물 수 |
| 정책·규제 수 | 국가·산업별 규칙이 코드 분기로 | 정책 엔진 또는 정책 테이블(분류 × 보존 × 마스킹 × 시행일) + 규칙 테스트 스위트([Part 1/07](../01-foundations/07-operations-vocabulary.md) 정책 엔진 도입 기준) | 정책 수 × 테넌트 수 |

### 운영 안정성 — 장애 모드와 대응

| 장애 모드 | 사용자에게 보이는 증상 | 탐지 신호 | 자동 대응 (폴백·저하) | 사람 개입 기준 |
|---|---|---|---|---|
| 권한 서비스·IdP 다운 (의존 서비스 다운) | 검색 거부 또는 공개 문서만 | 주체 해석 오류율, 캐시 적중률 급등 | **fail-closed**: TTL 내 캐시된 주체 집합으로만 처리, TTL 만료 후엔 **거부** 또는 `classification=public`만 노출하는 저하 모드. 절대 fail-open 하지 않는다 | 다운이 TTL(예: 5분) 초과 → 온콜. 저하 모드 진입은 보안 책임자에게 통보 |
| 주체 해석 지연 급증 | 검색 지연 | 해석 p95 | 캐시 우선, 캐시 미스는 타임아웃 후 거부 | p95가 SLO(예: 100ms) 3배 지속 |
| ACL·테넌트 필드 누락 거부 폭증 (검증 실패 폭증) | 특정 소스 문서가 색인에서 사라짐 | 소스별 게이트 거부율 급변 | 해당 소스 색인 **중단**(누락 상태로 넣지 않음), 다른 소스 계속 | 소스 ACL 매퍼([01](01-source-ingestion.md)) 고장·소스 권한 모델 변경 확인 |
| 소스 ACL ↔ 인덱스 ACL 드리프트 (데이터 불일치) | 권한 회수된 사용자가 여전히 봄 / 권한 있는 사용자가 못 봄 | 정기 권한 대조 불일치 건수(방향별). 회수된 문서를 인용한 캐시 응답 적중(카나리 질의를 캐시 경로로도 실행) | 노출 방향 불일치는 즉시 보수적 ACL로 덮어쓰기 → 재동기화 이벤트 + Reasoning 캐시 무효화(불균형 ② 반영) | **노출 방향 1건이라도 보안 사고 절차**. 누락 방향은 SLO 내 처리 |
| 게이트웨이 우회 (단계 고유) | 필터 없는 검색 | 인덱스 직접 접근 로그, 카나리(권한 없는 계정으로 기밀 문서 질의 → 0건이어야 함) 실패 | 카나리 실패 시 해당 컬렉션 검색 **킬 스위치** | 즉시. 네트워크 정책·자격 증명 재점검 |
| PII 사후 발견 (단계 고유) | 마스킹 안 된 PII가 검색·답변에 노출 | 출력 가드레일 PII 탐지 적중, 신고 | 인시던트 런북: 해당 `doc_id` 파생물 전부 톰스톤 → 벡터 삭제(부분 삭제 불가) → 캐시·트레이스 퍼지 → 마스킹 후 재수집 | 즉시. 규제 통지 의무 여부는 법무 |
| 삭제 요청 이행 불완전 (단계 고유) | 삭제 증명에 빠진 파생물 | 삭제 증명 vs 계보 파생물 수 불일치 | 불일치 시 삭제 잡 재실행(멱등), 미완 상태로 증명 발급 안 함 | 계보 없는 파생물 발견 시 — 구조 결함이므로 설계 수정 |
| 테넌트 교차 누출 카나리 실패 (단계 고유) | A사 질문에 B사 문서 | 테넌트별 카나리 질의 | 교차 컬렉션 검색 킬 스위치 | 즉시, 보안 사고 절차 |

SLI 후보: ① 권한 대조 불일치 건수(노출 방향 = 0 목표) ② 누출 카나리 통과율 ③ 주체 해석 p95 ④ PII 탐지 재현율(한국어 라벨 샘플) ⑤ 삭제 요청 이행 시간·증명 완전성 ⑥ ACL 회수 이벤트 → 인덱스 ACL 갱신·Reasoning 캐시 무효화 완료 p95(불균형 ② 반영). SLO 초안(예시): 노출 방향 불일치 0건(주 1회 대조), 카나리 100%, 해석 p95 ≤ 100ms, PII 재현율 ≥ 99%(형식 식별자) / `[실측]` 후 설정(서술형), 삭제 요청 ≤ 72h + 증명 100%, 회수 전파 ≤ 15분(캐시 끝점 포함, 캐시 TTL ≤ 주체 해석 TTL 5분). 쓰기 행동의 멱등성: ACL 갱신은 `(doc_id, acl_hash)` 키로 멱등. 삭제는 "삭제 → 계보 대조 → 증명"이며 재실행 시 이미 삭제된 파생물은 건너뛰고 증명만 갱신. 가명화는 결정론적(같은 입력 → 같은 가명)이라 재처리해도 동일인 추적이 유지된다.

### 유지보수 — 버전·변경·호환

| 버전 관리 대상 | 바꾸면 영향받는 것 | 회귀 테스트 | 함께 배포할 것 (호환) |
|---|---|---|---|
| 정책 테이블 (분류 등급 × 보존 기간 × 마스킹 방식 × 시행일) | 모든 문서의 노출·보존·마스킹 | **규칙 테스트 스위트**(허용·거부 케이스), 시행일 전후 시뮬레이션 | `retention_until` 배치 재계산, [08](08-grounding-data-design.md) 등급 규칙 |
| 소스별 ACL 매퍼·그룹 평탄화 규칙 | 청크 ACL 값 | 4종 이벤트 계약 테스트 + 권한 대조 | 전체 권한 대조 1회 |
| 게이트웨이 필터 코드 | 모든 검색 | 카나리 스위트(테넌트·분류·그룹별 음성 테스트) | 메타데이터 `acl` 필드 형식, 주체 해석기 출력 형식 |
| PII 패턴 세트·NER 모델 버전 | `pii_flags`, 마스킹 결과 | 한국어 PII 평가셋 정밀도·재현율 | 영향 소스 재스캔 계획, 플래그 의미 버전 |
| 테넌트 레지스트리 (컬렉션·키·정책 참조) | 격리 경계 | 테넌트 추가·제거 리허설, 교차 카나리 | 암호화 키 관리 |
| 분류 택소노미 | 필터·정책 매칭 | 매핑 적용 후 분포 | [06](06-ontology-driven-modeling.md) 매핑 테이블 |
| 감사 로그 스키마·보존 | 사후 재구성 가능성 | 샘플 재구성 테스트 | 저장소 보존 정책(장기·불변) |

롤백 단위는 "정책 테이블 버전 + 게이트웨이 필터 버전 + ACL 필드 형식". 기술 부채로 기록할 것: 복잡 ACL(부정·중첩)을 렌더 전 재확인으로만 보완하는 범위, 테넌트 논리 분리에서 물리 분리로의 전환 조건, 삭제 증명 자동화 미완, 백업 내 PII 만료 정책, 트레이스 본문 opt-in이 아직 전면 적용되지 않은 경로.

### 변화 대응 — 무엇이 바뀌고, 어느 경계에서 흡수하는가

| 변화 유형 | 이 단계에서 바뀌는 것 | 안정적으로 유지할 계약·인터페이스 | 교체 가능한 구현 | 흡수 방식 | 전파 범위 |
|---|---|---|---|---|---|
| **사용자 환경** (가장 잦음 — 매일) | 입사·퇴사·부서 이동·그룹 변경, 조직 개편, 새 테넌트 | 주체 해석 인터페이스 `principals(user) → set`, 청크의 **그룹 ID 참조** | 주체 해석기(IdP 어댑터), 테넌트 레지스트리 | 멤버 변경은 **질의 시 해석으로 재색인 없이 흡수**. 문서 ACL 변경은 변경 큐의 `acl` 이벤트([07](07-freshness-and-sync.md)). 조직 개편은 그룹 매핑 데이터 변경. 테넌트 추가는 레지스트리 행 | 멤버: 없음 / 문서 ACL: 메타데이터 / 개편: 그룹 매핑 + 대조 1회 |
| **규칙·정책** (두 번째) | 보존 기간, 분류 체계, PII 범주, 마스킹 방식, 규제 신설 | 정책 평가 인터페이스, 게이트 위치(게이트웨이·게이트) | 정책 테이블 값 | 정책 버전 + **시행일** + 규칙 테스트 스위트. 보존 변경은 `retention_until` 배치 재계산. 소급 마스킹은 영향 소스 재처리 | 해당 정책의 문서군. 권한 모델 변경은 ACL 필터·UI 재검증까지 |
| **지식** | 새 소스(새 ACL 모델) 추가, 소스 권한 모델 변경 | ACL 복사 포트 | 소스별 ACL 매퍼 | 매퍼 어댑터 추가·교체 + 권한 대조 | 해당 소스 |
| **도메인 모델** | 분류 택소노미 개명·세분화 | 택소노미 ID 참조 | 라벨 | 매핑 테이블 이전, 세분화 시 재분류 배치 | 정책 매칭·필터 |
| **모델** | PII NER 모델 교체 | `detect_pii(text) → [span, type, confidence]` 포트 | 어댑터(규칙 / NER / 결정 모델) | 어댑터 교체 + 한국어 평가셋 + 영향 소스 재스캔 창 | `pii_flags`·마스킹된 파생물 |
| **프로토콜** | MCP 무상태 코어(세션 없음 → 요청마다 권한 컨텍스트), IdP 프로토콜 변경, 저장소 필터 API 변경 | 게이트웨이 내부 포트 | 프로토콜 어댑터 | 어댑터 교체. MCP 경유 접근도 게이트웨이를 거치게 강제 | 어댑터 경계 + 런북 |

가장 자주 바뀌는 것: **사용자 환경**(멤버·그룹·조직) — 이것을 재색인 없이 흡수하려면 **청크에 사용자가 아닌 그룹 ID를 두고 해석을 질의 시로 미루는** 설계가 전제다. 두 번째는 **규칙·정책**이며, 정책을 코드가 아닌 **시행일 있는 테이블**로 두면 규제 변경이 배포가 아니라 설정 교체 + 테스트가 된다. 권한 회수의 **전파 대상**에는 인덱스 메타데이터뿐 아니라 Reasoning의 결과·시맨틱 캐시([Part 3/01](../03-agent-workflow-rag/01-rag-architecture-patterns.md)·[Part 3/03](../03-agent-workflow-rag/03-retrieval-reranking.md)·[Part 5/02](../05-cross-cutting/02-cost-latency-model-routing.md))가 포함된다. 회수의 시간 상한을 캐시에도 걸기 위해 ① 캐시 키에 **주체 집합 해시**(subject-set hash)를 포함하고, ② 캐시 TTL ≤ 주체 해석 TTL(위 예시 5분)로 묶으며, ③ `acl`·톰스톤 이벤트가 [07](07-freshness-and-sync.md) 변경 큐를 통해 캐시 무효화를 트리거한다. 캐시된 답변의 citation에도 [08](08-grounding-data-design.md)의 `acl_checked` 비영속 원칙이 적용된다(불균형 ② 반영). 코드 밖 설정으로 둘 것: 정책 테이블, 테넌트 레지스트리, 소스 ACL 매핑, 그룹 매핑, PII 패턴, 마스킹 방식표, 캐시 TTL(주체 해석·Reasoning 캐시 공통 상한), 카나리 질의 세트. 포트·어댑터 뒤에 둘 외부 의존: IdP·권한 서비스, PII 모델, 키 관리 시스템, 벡터·그래프 저장소의 필터 API. 시점 재현성: 감사 로그의 **요청 시점 주체 집합 해시 + 정책 버전 + ACL 스냅샷**으로 "그때 그 사용자가 왜 그 문서를 봤나"를 복원한다.

### 거버넌스 접점 — 정책 · 가드레일 · 승인 · 감사

| 항목 | 이 단계에서의 답 |
|---|---|
| 위험 등급 (1~5, 가역성 × 영향 범위) | ACL 사전 필터는 가드레일 그 자체. **정책 변경**(분류·보존·마스킹)은 **등급 3**(여러 사용자, 노출은 비가역) → 보안 책임자 승인 1인 + 규칙 테스트. PII 마스킹 정책 완화는 등급 3~4. 물리 삭제는 두 등급으로 **이 페이지가 정의**한다([07](07-freshness-and-sync.md)·[Part 1/07](../01-foundations/07-operations-vocabulary.md)이 참조): **정책 배치 삭제 = 등급 4** — 보존 만료 + 유예 경과, 유예 중 가역, 정책 승인으로 갈음. **요청·일괄 물리 삭제 = 등급 5** — 정보주체 삭제 요청 이행·정책 밖 일괄 삭제, 2인 승인 + 섀도(대상 목록 사전 검토), **에이전트는 제안만·실행은 사람**(불균형 ⑧ 반영) |
| 가드레일 위치 (입력 / 출력 / 행동) | **입력**: 수집 직후 PII 탐지·마스킹, 소스 ACL 복사 필수. **출력**: 게이트웨이 사전 필터, 렌더 전 `acl_checked`, 출력 PII 2차 탐지, 트레이스 본문 opt-in. **행동**: 정책 변경·테넌트 추가·물리 삭제·마스킹 완화는 승인 게이트. 세 지점이 모두 있어야 가드레일이 "있다" |
| 게이트 출력 (통과 / 차단 / 승인 / 저하)과 판정 수단 | 통과 / 차단(fail-closed: 권한 미확인·필수 필드 누락·카나리 실패) / 저하(`public`만 노출 모드) / 승인(정책·삭제). 판정은 **규칙만**. PII 탐지의 모델 결과도 "마스킹 실행"은 규칙이 최종(저확신은 마스킹 쪽으로) |
| 소유자 (A) | 보안 책임자(ACL·PII·게이트웨이 정책), 데이터 소유자(분류·보존), 서비스 소유자(테넌트). 플랫폼 엔지니어가 게이트웨이 R, 법무 C |
| 감사 추적에 남길 필드 | 질의 로그(요청자·시각·주체 집합 해시·적용 필터·반환 `evidence_id`·저하 모드 여부), ACL 변경(소스 이벤트 ID·이전/이후·반영 시각), PII 탐지 기록(모델 버전·플래그·마스킹 방식), 삭제 증명(`doc_id`·파생물 목록·시각·승인자), 정책 버전·시행일·승인자, 권한 대조·카나리 결과. 저장소는 관측 로그와 **분리**, 장기·불변 보존 |

### 운영 준비도 체크
- [ ] 권한 서비스 다운 시 fail-closed(거부 또는 `public`만)가 기본이고 fail-open 경로가 없는가
- [ ] 청크가 그룹 ID만 갖고 사용자 → 그룹 해석이 질의 시 + 짧은 TTL 캐시로 되는가
- [ ] Reasoning 결과·시맨틱 캐시 키에 주체 집합 해시가 있거나 TTL ≤ 주체 해석 TTL이고, ACL·톰스톤 이벤트가 캐시 무효화를 트리거하는가(불균형 ② 반영)
- [ ] 게이트웨이가 단일 강제 지점이고 인덱스 직접 접근이 네트워크·자격 증명으로 차단되는가
- [ ] 누출 카나리(권한 없는 계정·타 테넌트) 질의가 주기적으로 돌고 실패 시 킬 스위치가 작동하는가
- [ ] 정책 테이블이 코드 밖에 시행일·버전과 함께 있고 규칙 테스트 스위트가 CI에 있는가
- [ ] 삭제 요청이 계보로 파생물 전부를 식별·삭제·증명하고, 증명 불완전 시 발급되지 않는가
- [ ] PII 사후 발견 인시던트 런북(톰스톤 → 벡터 삭제 → 캐시·트레이스 퍼지 → 재수집)이 리허설되었는가
- [ ] 감사 로그가 관측 로그와 분리되어 장기·불변 보존되고 요청 시점 주체 집합·정책 버전을 포함하는가
