# 데이터 파이프라인 결정 매트릭스

> **범위**: 데이터 유형 × 요구사항 × 기술 선택 종합표와 한계
> 이 Part의 모든 단계에 대한 기술 선택을 **한 장**으로 요약한다. 상세 근거는 각 단계 페이지에 있다. 시각화: [`assets/html/data-pipeline-architecture.html`](../assets/html/data-pipeline-architecture.html)

## 1. 결정에 영향을 주는 입력 변수

| 변수 | 값의 범위 | 영향을 받는 단계 |
|---|---|---|
| **데이터 유형** | 정형(DB·API) / 반정형(표·티켓·로그) / 비정형(문서·메일·채팅) / 멀티모달(스캔·도표·이미지) | 01 파서 선택, 02 청킹 기준, 04 sparse 비중, 05 추출 방식(규칙 vs LLM), 08 근거 단위(레코드 vs 청크) |
| **규모** | 문서 수(천 / 십만 / 백만 이상), 갱신 빈도(일 / 시간 / 분) | 04 저장소 유형·양자화, 05 그래프 도입 여부·인덱싱 방식, 07 갱신 전략, 09 판정 수단(LLM 비용) |
| **지연 요구** | 신선도 SLO: 실시간(분) / 대화형(시간) / 배치(일) | 01 수집 방식(CDC vs 폴링), 07 이벤트 vs 배치 |
| **정확도·근거 요구** | 참고용 / 업무 지원 / 규제·감사 대상 | 03 버전·계보 깊이, 08 근거 단위·신뢰도·상충 처리, 10 감사 로그 |
| **질의 유형** | 사실 조회 / 키워드·ID 조회 / 멀티홉·관계 / 집계·비교 / 전체 요약 | 04 hybrid 가중, 05 그래프 도입·인덱싱 방식, 06 온톨로지 필요성 |
| **권한·PII** | 전 공개 / 문서별 ACL / 멀티테넌트 / PII 포함 | 03 권한 축, 10 강제 패턴·마스킹 시점 |
| **언어** | 한국어 단일 / 한·영 혼합 / 다국어 | 01 OCR, 02 토큰 기준, 04 임베딩·토크나이저, 09 결정 모델 `[실측]` 필수 |
| **팀 역량** | 데이터 엔지니어링 / PostgreSQL·검색엔진 운영 / RDF·온톨로지 경험 / MLOps | 04 저장소, 06 경량 vs 정식, 09 소형 모델 운영 가능성 |
| **예산·반출 제약** | 인덱싱 예산, API 반출 허용 여부, 온프레미스 | 01 매니지드 파서, 04 임베딩 API vs 자체 호스팅, 09 결정 모델 API |

## 2. 단계별 선택표

| 단계 | 기본값 (판단 어려울 때) | 조건 A → 선택 | 조건 B → 선택 | 피해야 할 조합 |
|---|---|---|---|---|
| [01 수집·파싱](01-source-ingestion.md) | 직접 구현 커넥터 + Docling 류 레이아웃 파서 + 실패분 격리 큐 | 소스가 운영 DB, SLO 분 단위 → CDC | 스캔·양식·한국어 손글씨 다수 → 벤더 OCR 1차 + 레이아웃 파서 2차 | 샘플 `[실측]` 없이 파서 선택; 좌표·페이지 없는 파서 출력 위에 하이라이트 UI 계획 |
| [02 청킹](02-chunking-strategies.md) | 문서 구조 기반 + 재귀 보정 + parent-child, 맥락 보강 없음 | 유사 문서 많아 출처 혼동, 인덱싱 예산 있음 → contextual 접두 추가 `[검증]` 일관성↑ | 인덱싱 비용 제약 + 장문 임베딩 모델 → late chunking (관련성 저하 `[실측]`) | 글자 수 기준 청크 크기(한국어 토큰 팽창 무시); 표를 중간에서 자르기; 근거 단위 안 정하고 청킹 먼저 |
| [03 메타데이터](03-metadata-provenance.md) | 다섯 축 필수 필드 + 별도 저장소 + 불변 버전(`is_current`) + PROV 어휘 | 규정·계약·가격 → bitemporal(기록 시점 + 유효 시점) | 참고용 챗봇 → 평면 메타데이터, 단 `source_uri`·`content_hash`·`ingested_at`·`locator`는 필수 | 벡터DB 페이로드를 단일 진실 원천으로; 필수 필드 누락을 경고만 하고 통과 |
| [04 임베딩·인덱싱](04-embedding-indexing.md) | hybrid(BM25 + dense + RRF), 기존 인프라에 가장 가까운 저장소, 양자화 없음, 모델 2종 `[실측]` | 코드·ID·고유명사 질의 중심 → BM25 비중↑ + 한국어 형태소 분석기 | 수천만 건 이상 또는 테넌트 격리 핵심 → 전용 벡터DB + 양자화 + 2단계 재순위 | 두 임베딩 모델 벡터를 한 인덱스에 혼합; 공백 분리 BM25로 한국어; 벤더 벤치마크로 저장소 선택 |
| [05 KG 구축](05-knowledge-graph-construction.md) | **질의 로그에서 멀티홉·동일성 요구 확인 전엔 도입 안 함.** 도입 시: 경량 온톨로지 + 하이브리드 추출 + SHACL 검증 + LPG + 증분 지원 인덱싱 | 문서 갱신 잦음 → LightRAG 식 증분 | 최난도 멀티홉이 핵심 비율 → HippoRAG 2 식 PPR `[실측]` (MuSiQue 우위만 `[검증]`) | 스키마 없는 추출을 운영에; 근거 문장 없는 트리플 적재; 정형 데이터를 LLM으로 추출; 사실 조회 중심인데 GraphRAG 커뮤니티 요약 |
| [06 온톨로지](06-ontology-driven-modeling.md) | 범위 질문 30개 → 경량 온톨로지(클래스 ≤ 30) → SHACL → LPG 변환 + 매핑 테이블 → 소유자 지정 | 의료·금융 등 산업 표준 존재 → 하향식 비중↑ + 표준 부분 재사용 + 정식 승격 검토 | 그래프 없고 평면 필터로 충분 → 택소노미(SKOS)만 | 하향식만으로 수백 클래스; 운영 LPG에서 라벨 임의 추가; 범위 질문 없는 클래스 |
| [07 신선도·동기화](07-freshness-and-sync.md) | 증분 배치 + 톰스톤 + 주 1회 전체 대조 + 문서 단위 멱등 재처리 + 블루/그린 절차 | 운영 DB, SLO 분 단위 → CDC + 단일 변경 큐 | 복사본 많은 공유 드라이브·메일 → 정확 중복 제거 + 정본 규칙 | 폴링만으로 삭제 감지 기대; 벡터만 갱신하고 그래프 방치; 모델 교체 시 새 문서만 새 모델 |
| [08 근거 데이터 ★](08-grounding-data-design.md) | 하이브리드(청크 검색 + 문장 검증·렌더) + 코드 규칙 신뢰도 + 메타데이터 결정론 상충 탐지 | 멀티홉 설명·규제 "왜" → 트리플·경로 추가, 근거 문장 필수 | 참고용, 문서 링크면 충분 → 청크 단위 + 최소 필드 | 신뢰도 = 검색 점수; LLM 자가 평가 신뢰도; 생성물(캡션·요약)을 검증 근거로; 진짜 모순에서 답변이 하나를 고름 |
| [09 파이프라인 AI](09-ai-inside-the-pipeline.md) | 규칙으로 거른 뒤 소형 LLM 시작 → 라벨 축적 → 소형 분류기 증류, 결정 모델은 비교군 | 라벨 수천 건 + 카테고리 고정 → 한국어 소형 분류기 | 라벨 적음 + 질문 자주 변경 + 보정 확률 필요 → 결정 모델 vs 소형 LLM 한국어 평가셋 비교 | 닫힌 판정에 대형 LLM; 벤더 수치로 예산; 한국어 `[실측]` 없이 결정 모델 채택; LLM 추출 뒤 검증기 없음 |
| [10 접근 제어](10-access-control-governance.md) | 테넌트 분리 + 메타데이터 사전 필터 + 렌더 전 재확인 + 수집 직후 PII 탐지·마스킹 + 계보 기반 삭제 + 게이트웨이 단일 강제 | PII 열람이 업무 근거 → 인덱싱 시 마스킹 + 원문 통제 열람 + 감사 | 전 직원 공개·단일 테넌트·PII 없음을 **확인** → 최소 구성 | 프롬프트로 권한 통제; 후 필터를 주 강제 지점으로; 응답 시에만 PII 마스킹; 파생물에 출처 `doc_id` 없음 |

## 3. 시나리오별 추천 조합

| 시나리오 | 조합 | 이유 | 알려진 한계 |
|---|---|---|---|
| **A. 사내 문서 QA** (규정·보고서·위키·메일, 문서별 ACL, 한·영 혼합, 업무 지원 등급) → [시나리오 A](../07-appendix-scenarios/01-enterprise-document-qa.md) | 01 직접 커넥터 + Docling 류, 메일·채팅은 경량 파서 / 02 구조 기반 + parent-child, 출처 혼동 시 contextual / 03 다섯 축 + 불변 버전 + 규정은 bitemporal / 04 hybrid + pgvector 또는 기존 검색엔진 / 05 **초기 미도입**, 조직·프로젝트 관계 질의 확인 후 경량 그래프 / 06 택소노미(문서 유형·부서·기밀) 먼저 / 07 증분 배치 + 대조 + 정확 중복 / 08 청크 + 문장 하이라이트, 개정 상충 처리 / 09 문서 유형·기밀 등급은 소형 분류기, 효력일 추출은 규칙 + 소형 LLM / 10 메타데이터 사전 필터 + 렌더 전 재확인, 메일 PII는 수집 직후 마스킹 | 질의 대부분이 단일 문서 사실 조회 → 벡터 + 구조 청킹으로 충분. 권한이 핵심 리스크 → 사전 필터와 ACL 전파가 우선. 개정 규정이 많아 bitemporal과 `superseded_by`가 필수 | 멀티홉("이 프로젝트 담당 부서의 작년 계약")은 그래프 없이는 질의 분해에 의존. 그룹 중첩 깊은 조직은 ACL 평탄화 시차. 한국어 문장 분할 오류가 하이라이트 어긋남으로 |
| **B. 커머스 상품 데이터** (상품 마스터·가격·재고·리뷰·상품 이미지, 분 단위 갱신, 멀티테넌트 가능, 참고~업무 지원) → [시나리오 B](../07-appendix-scenarios/02-commerce-assistant-genui.md) | 01 CDC(상품 DB) + 리뷰는 배치 + 이미지는 VLM 캡션 + 이미지 임베딩 / 02 레코드는 템플릿 직렬화(청킹 최소), 리뷰·상세 설명만 청킹 / 03 가격·재고는 bitemporal 필수, 캡션은 `derived_from` / 04 hybrid, 상품 코드·브랜드명은 BM25 비중↑, 규모 크면 전용 벡터DB + 테넌트 분리 / 05 **규칙 추출 중심** 그래프(상품–카테고리–브랜드–호환–대체), LLM은 리뷰 속 속성만 / 06 상품 온톨로지는 schema.org 부분 재사용 + 카테고리 택소노미 / 07 CDC 이벤트 기반 + 단일 변경 큐, 재고·가격 톰스톤 즉시 / 08 **레코드 근거 단위** + 리뷰는 문장, 가격 상충은 시점으로 해소 / 09 상품 속성 정규화·카테고리 분류는 소형 분류기 → 대량이면 결정 모델 비교, 리뷰 감성·요약은 LLM / 10 테넌트 인덱스 분리, 리뷰 작성자 PII는 수집 직후 마스킹 | 데이터 대부분이 정형 → 레코드가 근거 단위이고 그래프는 규칙으로 거의 공짜. 신선도가 핵심(가격·재고) → CDC와 bitemporal. 상품 코드·브랜드 검색은 dense가 약함 → BM25 비중 | VLM 캡션의 오류가 "근거 있는 환각"(등급 C, 검증 근거 불허로 완화). 리뷰 LLM 처리가 건수에 비례해 비용↑. 테넌트 간 공통 브랜드 노드가 그래프 경계를 흐림(엣지 단위 `tenant_id`) |
| **C. 운영 로그·런북** (인시던트 티켓·알림·런북·아키텍처 문서·채팅, 키워드·ID 질의 많음, 반정형, 분 단위 신선도) → [시나리오 C](../07-appendix-scenarios/03-ops-incident-agent.md) | 01 티켓·알림은 API/웹훅, 런북은 위키 커넥터, 아키텍처 도표는 VLM 캡션 / 02 로그·티켓은 엔트리 단위(줄 번호 보존), 런북은 구조 기반 + 절차 단계 보존 / 03 서비스·컴포넌트·환경 택소노미, 런북 버전 필수 / 04 **BM25 비중 높은 hybrid** + 기존 검색엔진(로그 인프라 재사용), 에러 코드·호스트명 정확 매칭 / 05 **경량 그래프 적극 도입** — 서비스–의존–컴포넌트–담당–런북–과거 인시던트는 CMDB·티켓 필드에서 규칙 추출, LLM은 인시던트 서술의 원인 관계만 / 06 서비스 토폴로지 온톨로지(CMDB 스키마 상향식 + 소수 클래스) / 07 이벤트 기반 + 런북 개정은 `superseded_by`, 해결된 인시던트 톰스톤 아님(이력) / 08 청크 + 문장 + **트리플 경로**("이 서비스 → 의존 → 그 컴포넌트 → 과거 인시던트"), 런북 상충은 버전 / 09 티켓 분류·심각도·중복 인시던트 판정은 소형 분류기 또는 결정 모델(한국어 티켓 `[실측]`), 원인 추출은 LLM + 검증 / 10 환경(prod/stg)·팀별 필터, 로그 속 고객 식별자 PII 마스킹, 트레이스 본문 opt-in | 질의가 "에러 코드 X가 난 서비스의 런북"처럼 ID 중심 + 관계 추적 → BM25와 그래프가 핵심. 정형 토폴로지(CMDB)가 있어 그래프를 규칙으로 구축 가능. 과거 인시던트 연상이 가치라 멀티홉 비율 높음 | 로그 양이 커 전수 임베딩은 비용↑ → 티켓·알림 요약 수준만 임베딩, 원시 로그는 BM25. CMDB가 낡으면 그래프도 낡음(대조 배치). 인시던트 중 서술의 LLM 원인 추출은 환각 위험 → 근거 문장 필수 + 등급 B 이하 |

## 4. 한계 종합

이 Part의 기술들이 공통으로 갖는 한계와, 그 한계가 다음 Part로 넘어가는 지점.

| 공통 한계 | 내용 | 넘어가는 지점 |
|---|---|---|
| **근거 데이터는 환각을 "검증 가능하게" 할 뿐 막지 못한다** | 문장 단위 근거·citation 스키마가 있어도 모델이 근거와 다르게 답할 수 있다 | [Part 3/04 생성과 근거 강제](../03-agent-workflow-rag/04-generation-grounding.md)의 검증기가 `evidence_id` ↔ 답변 문장 함의를 판정해야 완성. 계약은 [08](08-grounding-data-design.md) |
| **멀티홉은 청킹·임베딩으로 풀리지 않는다** | 어떤 청크 크기·임베딩 모델도 여러 문서에 흩어진 답을 한 번의 유사도 검색으로 못 모은다 | 그래프 경로([05](05-knowledge-graph-construction.md)) 또는 [Part 3/02 질의 분해](../03-agent-workflow-rag/02-query-understanding.md)·[Part 3/03 검색과 리랭킹](../03-agent-workflow-rag/03-retrieval-reranking.md)의 반복 검색 |
| **벤치마크가 자기 데이터를 대변하지 않는다** | 임베딩 모델 순위, 파서 정확도, GraphRAG 계열 우위 주장이 도메인·언어·포맷 효과에 좌우됨 (HippoRAG 2 재분석 `[검증]`) | 모든 선택을 자체 평가셋 `[실측]`으로. 평가 설계는 [Part 3/13](../03-agent-workflow-rag/13-evaluation-rag-agents.md), [Part 1/06](../01-foundations/06-evaluation-observability.md) |
| **결정 모델은 아직 벤더 주장 단계다** | 이 Part에서 적용점이 가장 많지만 지연·비용·보정은 `[벤더]`, 영어 중심 학습 → 한국어 미검증 | 판정 추상화 계층으로 교체 가능하게([09](09-ai-inside-the-pipeline.md)). 서빙 경로 배치는 [Part 3/11](../03-agent-workflow-rag/11-decision-layer.md), 트렌드 평가는 [Part 6/decision-models](../06-trends/decision-models.md) |
| **온톨로지·그래프의 효과는 독립 측정이 드물다** | "온톨로지 필수" 서사는 그래프 벤더 프레이밍이 섞여 있음 `[2차]` | 요구(멀티홉·동일성·설명) 확인 후 채택. 추출 위반율·엔티티 분산도를 대리 지표로. 설명가능성 요구는 [Part 5/04](../05-cross-cutting/04-governance-explainability.md) |
| **인덱싱 비용은 문서 수에 비례해 서빙 비용을 넘을 수 있다** | LLM 추출·contextual 접두·커뮤니티 요약·VLM 캡션이 모두 건수 비례 | 규칙 → 소형 모델 → 결정 모델 → LLM 순 배정([09](09-ai-inside-the-pipeline.md)). 비용 모니터링은 [Part 5/02](../05-cross-cutting/02-cost-latency-model-routing.md) |
| **권한·PII·삭제는 데이터 구조로만 막을 수 있고, 모델 단계에서 다시 뚫릴 수 있다** | 사전 필터로 컨텍스트를 깨끗이 해도 간접 인젝션·툴 경유 접근은 별개 | [Part 5/01 보안과 프롬프트 인젝션](../05-cross-cutting/01-security-prompt-injection.md), [Part 3/09 툴과 MCP](../03-agent-workflow-rag/09-tools-and-mcp.md)(MCP 무상태 코어의 권한 컨텍스트 전달), [Part 4/08](../04-dynamic-ui/08-security-sandboxing.md) |
| **citation은 데이터일 뿐, 보여주는 것은 UI다** | 스키마가 완벽해도 렌더가 등급·상충·생성됨을 안 보여주면 사용자는 모른다 | [Part 4/06 HITL UI 패턴](../04-dynamic-ui/06-hitl-ui-patterns.md)의 렌더 계약, [Part 4/05 의도→UI 매핑](../04-dynamic-ui/05-intent-to-ui-mapping.md) |
| **신선도는 파이프라인 안에서만 보장된다** | 소스 변경 → 인덱스 반영 지연은 측정 가능하지만, 모델이 캐시·메모리에 들고 있는 옛 근거는 별개 | [Part 3/08 상태·메모리·컨텍스트](../03-agent-workflow-rag/08-state-memory-context.md), 캐시 무효화는 [Part 5/02](../05-cross-cutting/02-cost-latency-model-routing.md) |

## 운영 설계 요약

각 단계 페이지의 "운영 설계 — 확장성 · 안정성 · 유지보수" 섹션을 한 줄씩 요약한다. 용어는 [Part 1/07](../01-foundations/07-operations-vocabulary.md), 레이어 간 비교는 [Part 5/06](../05-cross-cutting/06-operational-design-matrix.md). 위험 등급은 가역성 × 영향 범위(1~5)이며, 수치는 각 페이지의 "예시"를 따른다.

| 단계 | 10배 시 먼저 깨지는 것 | 핵심 폴백 | 가장 자주 바뀌는 것과 흡수 경계 | 위험 등급 |
|---|---|---|---|---|
| [01 수집·파싱](01-source-ingestion.md) | 전체 폴링 시간이 갱신 주기 초과, 벤더 OCR·VLM 호출 비용, 커넥터 수만큼 늘어나는 운영 부담 | 커넥터별 서킷 브레이커로 소스 단위 격리, 텍스트 레이어 문서는 로컬 파서로 계속, 실패분 격리 큐 | **지식**(문서·소스 양식) → 증분 커서 + 변경 큐; 소스 API → 커넥터 포트 뒤 어댑터; 파서 교체 → `parse()` 어댑터 + 불변 원본 재파싱 | 1 (새 소스 등록 2~3) |
| [02 청킹](02-chunking-strategies.md) | 규칙 변경 시 전체 재청킹·재임베딩 창, contextual 접두 LLM 비용, parent-child 2중 저장 | 파싱 품질 저하 시 재귀 분할 폴백, 접두 LLM 다운 시 접두 없이 색인 후 배치 보강 | **지식** → 문서 단위 재청킹(결정론적 청크 ID); 임베딩 모델 교체 → 크기 설정 새 버전 + 블루/그린 | 1 |
| [03 메타데이터](03-metadata-provenance.md) | 메타데이터 저장소 단일 병목, 불변 버전 저장량, 청크당 ACL 목록 비대, 복제 지연 | 인덱싱 게이트 fail-closed(필수 필드 없이 안 넣음), 복제 지연은 렌더 전 원천 재확인으로 2차 방어 | **지식**(문서 판)·**도메인 모델**(택소노미 값) → 추가 전용 스키마 진화 + 택소노미 버전·매핑, 청크엔 그룹 ID만 | 2 (ACL·분류·유효 기간 수동 수정 3) |
| [04 임베딩·인덱싱](04-embedding-indexing.md) | HNSW 메모리, 전체 재임베딩 시간·API 비용, 강한 필터 후 결과 부족, 톰스톤 누적 | BM25 단독 저하 모드(상태 표시), `ef`/`nprobe` 하향, 모델 불일치 벡터 쓰기 거부, 별칭 즉시 롤백 | **지식** → 증분 upsert; **임베딩 모델**(전파 최대) → `embed()` 포트 어댑터 + 전체 재임베딩 창 + 인덱스 버전 병행·별칭 전환 | 1 (인덱스 전환 2) |
| [05 KG 구축](05-knowledge-graph-construction.md) | 추출 LLM 비용 선형 증가, 엔티티 해소 후보 쌍 제곱, 커뮤니티 요약 재계산 | 그래프 경로 킬 스위치 → 벡터 단독, SHACL 위반 폭증 시 해당 유형 추출 중단·버킷, `sameAs` 해제 | **지식** → 문서 단위 엣지 삭제·재추출; **도메인 모델** → 매핑 테이블로 라벨 이전(재추출 없이), 분할만 재추출 | 2 (병합은 안 함) |
| [06 온톨로지](06-ontology-driven-modeling.md) | 클래스 수 증가로 추출 위반율↑, 매핑 테이블 비대, 팀 간 용어 충돌, 릴리스 검수 시간 | 온톨로지 버전 롤백(매핑 역방향), 운영 계층 직접 쓰기 차단, 미분류 버킷 → 변경 요청 | **도메인 모델 자체** → 소비자는 라벨 아닌 정의 ID 참조; 조직·제품군은 클래스 아닌 택소노미·인스턴스로 두어 데이터 변경으로 | 2 (메이저 릴리스 3) |
| [07 신선도·동기화](07-freshness-and-sync.md) | 전체 대조 배치 창 초과, 변경 큐 적체, 블루/그린 저장 2배, 경로별 지연 불일치 | 대조 배치가 유령·누락 재투입, 우선 레인(삭제·ACL 먼저), 톰스톤 카나리 실패 시 인덱스 차단, 별칭 롤백 | **지식**(변경·삭제·만료) → 단일 변경 큐 + 문서 단위 멱등 재처리; 파이프라인 버전 → 블루/그린 단일 절차 | 1 (톰스톤·전환 2, 물리 삭제 4) |
| [08 근거 데이터 ★](08-grounding-data-design.md) | 문장 오프셋 저장량, 상충 후보 쌍, 질의당 citation 조립 지연 | 필수 필드 못 채우면 근거 제외(fail-closed), 선택 필드 생략 저하, 상충 탐지기 다운 시 메타데이터 결정론만, 분할 실패 시 청크 단위 | **지식** → 문서 판별 재생성; **규칙**(소스 등급·노출 정책) → 등급 매트릭스 설정 교체 + 배치 재계산(재색인 없음) | 2 (`acl_checked`는 규칙만·fail-closed) |
| [09 파이프라인 AI](09-ai-inside-the-pipeline.md) | 판정 호출 수 선형 증가, 검토 큐 범람, 결정 모델 레이트 리밋·가격 변경 | 판정 지점별 보수적 기본값 폴백(`method=fallback`), 2차 수단 전환, 비행동 판정만 임계값 상향 | **규칙·질문 정의**(임계값·라벨), **모델**(벤더·버전) → 판정 추상화 계층 `decide()` 뒤 어댑터 + 설정 교체 + 섀도 | 2 (행동 연결 판정은 그 행동의 등급, Rule ∧ Model) |
| [10 접근 제어](10-access-control-governance.md) | 테넌트별 인덱스·키 수, 주체 해석 지연, PII 탐지 비용, 삭제 계보 탐색 | fail-closed(권한 서비스 다운 시 거부 또는 `public`만), 짧은 TTL 캐시, 누출 카나리 실패 시 킬 스위치 | **사용자 환경**(멤버·그룹·조직) → 청크엔 그룹 ID, 질의 시 주체 해석; **규칙·정책** → 시행일 있는 정책 테이블 + 규칙 테스트 | 3 (정책 변경), 4~5 (물리 삭제·삭제 요청, 에이전트 자동 실행 금지) |

읽는 법: Part 2에서 **가장 자주 바뀌는 것은 지식**이고, 그 흡수 메커니즘은 [07](07-freshness-and-sync.md) 하나로 수렴한다. **전파가 가장 넓은 변화는 임베딩 모델 교체**([04](04-embedding-indexing.md))와 **온톨로지 메이저 변경**([06](06-ontology-driven-modeling.md))이며, 각각 포트·어댑터 + 블루/그린, 정의 ID 참조 + 매핑 테이블로 국소화한다. **위험 등급이 높은 행동은 삭제·PII·ACL**([07](07-freshness-and-sync.md), [10](10-access-control-governance.md))에 집중되어 있고, 나머지 단계는 등급 1~2다.
