# 질의 이해와 라우팅

> **범위**: rewrite, decomposition, HyDE, intent 분류, 결정 모델 기반 라우팅

## 요약 (3줄)

1. 이 단계는 두 가지 다른 일을 한다. **질의 변환**(재작성·분해·HyDE·step-back·멀티 쿼리)은 검색 recall을 높이는 생성 과업이고, **라우팅**(어느 경로·인덱스·툴로 보낼까)은 선택지가 닫힌 판정 과업이다. 둘을 같은 LLM 호출에 섞지 않는다.
2. 라우터는 규칙 → 결정 모델 → 파인튜닝 분류기 → 프롬프트 LLM 순으로 가능한 가장 단순한 수단을 쓴다. 결정 모델(Jev / Decisions API)은 라벨이 적고 경로가 자주 바뀔 때의 새 선택지지만, 영어 중심 학습이라 **한국어 자체 평가셋이 필수**다 `[2차]`.
3. 한국어 질의는 조사·띄어쓰기·영한 혼용 때문에 영어 기준으로 설계한 변환·라우팅이 그대로 작동하지 않는다. 변환 전 정규화와 한국어 평가셋이 없으면 이 단계의 효과를 측정조차 할 수 없다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | ① 정규화·변환된 검색 질의 집합(원 질의 + 재작성본 + 하위 질문) ② 라우팅 결정(경로·인덱스·툴 + 확신도) ③ 추출된 메타데이터 필터(기간·부서·문서 유형) ④ 명확화 필요 여부. 품질 기준은 변환 후 context recall 상승과 라우팅 정확도·보정 |
| **언제** (When) | 라우팅은 경로가 2개 이상이면 항상. 질의 변환은 Naive RAG 기준선에서 어휘 불일치·복합 질의 실패가 측정될 때 추가. 코퍼스가 작고 용어가 통일되어 있으면 변환 생략 가능. 명확화 질문은 모호 질의 비율이 확인된 뒤 |
| **어떻게** (How) | ① 질의 로그 수백 건으로 유형(단순 사실 / 복합 / 멀티홉 / 모호 / 범위 밖) 라벨링 → ② 한국어 정규화(띄어쓰기·조사·영한 혼용 처리) → ③ 규칙으로 처리 가능한 라우팅(키워드·권한·명시적 필터) 분리 → ④ 나머지 라우팅을 결정 모델 또는 분류기로, 확신도 임계값 미만은 명확화 → ⑤ 유형별 변환 전략 배정(복합→분해, 어휘 불일치→재작성·HyDE, 추상→step-back) → ⑥ 변환 전후 recall과 라우팅 정확도 `[실측]` |
| **왜** (Why) | 라우팅을 프롬프트 LLM에 맡기면 요청당 비용의 상당 부분이 판정에 쓰이고 같은 질의가 다른 경로로 가서 디버깅이 불가능하다. 변환 없이 검색하면 사용자 어휘와 문서 어휘의 간극이 그대로 recall 손실이 된다. 범위 밖 질의를 걸러내지 못하면 [04](04-generation-grounding.md)의 "근거 없음" 처리가 작동할 기회가 없다 |

## 문제와 맥락

사용자 질의는 검색에 최적화되어 있지 않다. 짧고, 대명사와 생략이 많고, 이전 대화에 의존하며, 하나의 문장에 여러 질문이 들어 있다. 검색 인덱스는 문서 어휘로 만들어져 있다. 이 간극을 좁히는 것이 질의 변환이고, 질의를 적절한 처리 경로로 보내는 것이 라우팅이다.

이 단계가 없거나 약하면 다음 증상이 나타난다.

- **대화 맥락 소실**: "그럼 작년은?"이 단독 질의로 검색되어 아무것도 못 찾음
- **복합 질의의 부분 답변**: "A의 가격과 B와의 차이는?"에서 A 가격만 답함
- **범위 밖 질의의 환각**: 코퍼스에 없는 주제를 묻는데 가장 유사한 무관 청크로 답을 만듦
- **잘못된 인덱스 조회**: 인사 규정 질의가 기술 문서 인덱스로 감
- **비결정적 경로**: 같은 질의가 오늘은 FAQ 경로, 내일은 복잡 문의 경로로

### 한국어 질의의 특성

영어 기준 RAG 설계가 한국어에서 깨지는 지점은 세 가지다.

| 특성 | 문제 | 대응 |
|---|---|---|
| **조사·어미 변형** | "연차는", "연차를", "연차가"가 BM25에서 다른 토큰. 임베딩은 일부 흡수하지만 희귀 용어에서 실패 | 형태소 분석기 기반 토크나이저로 BM25 인덱싱, 질의도 같은 분석기로 |
| **띄어쓰기 불일치** | "데이터베이스 백업"과 "데이터베이스백업", "DB백업"이 공존 | 띄어쓰기 정규화 또는 n-gram 보조 인덱스, 동의어 사전 |
| **영한 혼용·약어** | "MCP 서버 설정"과 "엠씨피 서버 설정", "PR 리뷰"와 "풀리퀘 리뷰" | 도메인 동의어 사전(온톨로지 레이블에서 생성 가능), 재작성 시 양쪽 표기 생성 |
| **높임·비격식** | "알려주세요"/"알려줘"/"궁금합니다"가 의도 분류기에 노이즈 | 분류·결정 모델 평가셋에 격식 변형 포함 |

결정 모델 Jev는 영어 중심 학습이 명시되어 있어 한국어 라우팅 정확도를 가정할 수 없다 `[2차]`. 분류기든 결정 모델이든 **한국어·혼합 언어·비격식 변형을 포함한 평가셋**으로 `[실측]`한 뒤 채택한다.

## 핵심 개념

### 질의 변환 기법

| 기법 | 동작 | 겨냥하는 실패 | 비용 |
|---|---|---|---|
| **재작성 (rewrite)** | 대화 맥락을 반영해 독립 질의로, 구어를 문서 어휘로 | 맥락 소실, 어휘 불일치 | LLM 1회 (소형 가능) |
| **분해 (sub-question decomposition)** | 복합 질의를 독립적으로 검색 가능한 하위 질문으로 | 복합 질의 부분 답변, 멀티홉 | LLM 1회 + 하위 질문 수만큼 검색 |
| **HyDE (Hypothetical Document Embeddings)** | 가상의 답변 문서를 생성해 그 임베딩으로 검색 | 질의-문서 어휘·형식 간극 | LLM 1회 + 환각된 가상 문서가 검색을 오도할 위험 |
| **Step-back** | 구체 질의를 상위 개념 질의로 추상화해 함께 검색 | 세부 사항만 묻는데 원리·배경 문서가 필요 | LLM 1회 + 검색 1회 추가 |
| **멀티 쿼리** | 같은 의도의 변형 질의 N개를 생성해 결과를 융합(RRF) | recall 부족, 표현 다양성 | LLM 1회 + 검색 N회 |
| **메타데이터 추출** | 질의에서 기간·부서·문서 유형을 구조화 출력으로 추출해 필터로 | 무관 기간·조직 문서 혼입 | LLM 1회(구조화 출력) 또는 규칙 |

변환은 모두 생성 과업이므로 LLM이 맡는다. 단, **어떤 변환을 적용할지**는 판정이므로 라우터가 결정한다. 모든 질의에 모든 변환을 적용하면 지연이 선형으로 누적된다.

### 라우팅의 세 층위

1. **경로 라우팅**: 단순 사실 / 복합 / 멀티홉 / 전역 / 범위 밖 / 명확화 필요 → [01](01-rag-architecture-patterns.md)의 패턴 배정표로 연결
2. **소스 라우팅**: 어느 인덱스·컬렉션·툴·DB로 보낼까 (인사 규정 vs 기술 문서 vs 정형 DB의 Text-to-SQL)
3. **모델 라우팅**: 어느 크기의 모델이 생성을 맡을까 — [Part 5/02](../05-cross-cutting/02-cost-latency-model-routing.md)

세 층위 모두 선택지가 닫혀 있다. 판정 수단의 일반 원칙은 [Part 1/02](../01-foundations/02-system1-vs-system2.md), 배치 설계는 [11](11-decision-layer.md).

### 라우터 수단 비교의 핵심 차이

- **규칙**: 명시적 필터("2025년", "@인사팀"), 권한, 금칙어. 결정론적이고 설명 가능. 의미 판단 불가
- **파인튜닝 분류기**: 라벨 수천 건 이상이면 가장 싸고 빠름. 경로 추가 시 재학습
- **결정 모델**: 상태(질의 + 대화 요약) + 타입드 질문("이 질의의 경로는 {A,B,C,D} 중?") → 선택 + 보정 확률. 경로 변경은 질문 정의 수정. Jev와 Decisions API는 인터페이스는 같지만 내부가 다르다(Jev는 결정 전용 비자기회귀 모델, Decisions API는 gpt-6-luna 출력 제약) `[벤더]` `[2차]`
- **프롬프트 LLM**: 선택지가 아직 안 굳었거나 설명이 함께 필요할 때. 비보정, 비용·지연 큼

## 아키텍처 / 파이프라인

```
원 질의 + 대화 히스토리
   │
   ▼
[정규화] 띄어쓰기·조사·영한 혼용 처리, 명시적 필터 파싱 (규칙)
   │
   ▼
[규칙 라우팅] 권한 없음 → 거부 / 명시적 필터 → 메타데이터 / 금칙 → 가드레일([12])
   │ 통과
   ▼
[판정 라우팅] 결정 모델 또는 분류기: 경로? 소스? 확신도?
   ├─ 확신 < θ 또는 "모호" ──▶ 명확화 질문 생성(LLM) ──▶ 사용자
   ├─ "범위 밖" ──▶ [04] 근거 없음 응답
   └─ 경로 확정 ──▶ [변환] 경로별 전략: 재작성 / 분해 / HyDE / step-back / 멀티 쿼리 (LLM)
                         │
                         ▼
                    검색 질의 집합 + 필터 + 라우팅 결정 + 확신도 ──▶ [03] 검색·리랭킹
```

출력 계약: `{ queries: [...], filters: {...}, route: enum, source: enum, confidence: float, needs_clarification: bool }`. 라우팅 결정과 확신도는 트레이스에 기록한다([Part 5/03](../05-cross-cutting/03-observability-tracing.md)).

## 기술 비교표 — 이 단계에서 쓸 수 있는 선택지

| 기술 / 접근 | 적합한 상황 | 부적합한 상황 | 비용·복잡도 | 성숙도 | 검증 수준 |
|---|---|---|---|---|---|
| 쿼리 재작성 | 멀티턴 대화, 구어·약어 질의, 어휘 불일치 | 단발 질의에 용어가 이미 문서와 일치, 지연 예산 극소 | 하~중 — 소형 LLM 1회 | 표준 | `[2차]` |
| 분해 (sub-question) | 복합·비교 질의, 멀티홉 | 단순 질의(불필요한 검색 N회), 하위 질문 간 의존이 강해 순차 필요 | 중 — LLM 1회 + 검색 N회 | 안정 | `[2차]` |
| HyDE | 질의가 짧고 문서가 서술형, 임베딩 전용 검색 | 코퍼스에 없는 주제(가상 문서가 환각을 검색으로 전파), hybrid로 이미 충분 | 중 — LLM 1회, 오도 위험 | 안정 | `[검증]` 원 논문, 효과 코퍼스 의존 |
| Step-back | 구체 질의에 배경·원리 문서가 필요 | 사실 조회 위주 | 중 — 검색 1회 추가 | 안정 | `[검증]` 원 논문 |
| 멀티 쿼리 + RRF | recall 부족이 주 실패, 표현 다양성 큼 | 지연 예산 빡빡, precision이 더 문제 | 중 — 검색 N회 | 안정 | `[2차]` |
| 라우터: 규칙 | 명시적 필터·권한·금칙, 감사 대상 | 의미 기반 경로 판단 | 하 | 표준 | `[검증]` |
| 라우터: 파인튜닝 분류기 | 라벨 수천 건, 경로 고정, 초저지연·온프레미스 | 경로 자주 변경, 라벨 없음 | 중 — 학습·MLOps | 표준 | `[검증]` |
| 라우터: 결정 모델 (Jev / Decisions API) | 라벨 적음, 경로 자주 바뀜, 보정 확률로 명확화 임계값 필요 | 한국어 미검증 상태로 바로 운영, 판정 사유 설명 필수 | 하(호출) / 중(평가셋) | 신생 | `[벤더]` 지연 70~500ms 주장, `[2차]` 영어 중심 |
| 라우터: 프롬프트 LLM | 프로토타입, 경로 미확정, 설명 동반 필요 | 대량·저지연, 보정 확률 필요 | 중 — 토큰 | 안정 | `[검증]` 비보정 널리 보고 |
| 명확화 질문 생성 | 모호 질의 비율 높음, 대화형 UI | 단발 API, 사용자가 되묻기를 싫어하는 맥락 | 중 — LLM 1회 + 왕복 | 안정 | `[2차]` |

### 선택 가이드

- **경로가 2~3개로 고정이고 라벨 로그가 수천 건 있다면** → 파인튜닝 분류기 + 규칙. 이유: 가장 싸고 빠르며 한국어 데이터로 직접 학습하므로 언어 문제가 없다
- **경로가 자주 바뀌거나 라벨이 적고, 확신도로 명확화를 트리거하고 싶다면** → 결정 모델. 이유: 질문 정의만 수정하면 되고 보정 확률이 임계값 설계에 쓰인다. 단 한국어 평가셋 `[실측]` 선행, 불합격 시 분류기
- **멀티턴 대화형이라면** → 재작성은 항상, 분해는 라우터가 "복합"으로 판정한 경우만. 이유: 재작성 없이는 맥락 소실, 모든 질의 분해는 지연 낭비
- **임베딩 검색만 쓰고 recall이 낮다면** → HyDE보다 먼저 hybrid 검색([03](03-retrieval-reranking.md))을 시도. 이유: HyDE는 범위 밖 질의에서 환각을 검색으로 전파한다
- **판단이 어려우면** → 규칙 + 소형 LLM 라우터 + 재작성으로 시작하고, 라우팅 로그가 쌓이면 분류기 또는 결정 모델로 이전. 이유: 라벨 데이터가 자연스럽게 축적된다

## 설계 시 고려사항 (체크리스트)

- [ ] 질의 로그를 유형별로 라벨링했고 각 유형의 비율을 아는가
- [ ] 한국어 정규화(띄어쓰기·조사·영한 혼용)가 검색 인덱스의 토크나이저와 일치하는가
- [ ] 변환과 라우팅이 분리되어 있는가 (한 프롬프트에 "경로를 고르고 질의를 다시 써라"를 섞지 않았는가)
- [ ] 라우터 평가셋에 한국어·혼합 언어·비격식·오타 변형이 포함되어 있는가
- [ ] 라우팅 확신도 임계값 미만의 경로(명확화 / 보수적 기본 경로 / 사람)가 정의되어 있는가
- [ ] "범위 밖" 경로가 있고 [04](04-generation-grounding.md)의 근거 없음 응답으로 연결되는가
- [ ] 변환된 질의가 아닌 **원 질의**도 검색에 포함되는가 (변환 실패 시 안전망)
- [ ] 하위 질문 수·멀티 쿼리 수에 상한이 있는가
- [ ] 라우팅 결정·확신도·적용된 변환이 트레이스에 기록되는가
- [ ] 라우터 장애 시 폴백 경로(규칙 기반 기본 경로)가 있는가

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 변환이 의도를 왜곡 | 재작성·HyDE가 사용자가 묻지 않은 것을 검색 | 원 질의 병행 검색, 변환 결과를 사용자에게 노출(확인 가능) |
| HyDE의 환각 전파 | 코퍼스에 없는 주제에서 그럴듯한 무관 문서 검색 | 범위 밖 판정을 HyDE 앞에, hybrid 우선 |
| 라우터 오판의 증폭 | 잘못된 경로는 이후 모든 단계를 무효화 | 확신도 임계값, 경로별 품질 모니터링, 오판 로그 리뷰 |
| 결정 모델의 한국어 품질 미검증 | 영어 기준 정확도가 한국어에서 재현되지 않을 수 있음 | 한국어 평가셋 `[실측]`, 비교군으로 분류기 유지 |
| 보정 확률의 보정 여부 미확인 | 명확화 임계값이 무의미 | 신뢰도 다이어그램으로 보정 확인 후 임계값 설정 |
| 지연 누적 | 정규화 + 라우팅 + 변환 + 검색 N회가 직렬이면 체감 지연 큼 | 변환과 검색 병렬화, 단순 경로는 변환 생략 |
| 명확화 피로 | 되묻기가 잦으면 사용자 이탈 | 임계값 조정, 가장 가능성 높은 해석으로 답하되 가정을 명시 |

## 운영 설계 — 확장성 · 안정성 · 유지보수

용어·판단 기준은 [Part 1/07 운영 용어](../01-foundations/07-operations-vocabulary.md). 이 단계는 모든 요청의 **임계 경로 맨 앞**에 있다. 라우터가 느리면 전부 느리고, 라우터가 죽으면 전부 죽는다. 동시에 **입력 가드레일이 실제로 놓이는 자리**다. 레이어 간 종합은 [Part 5/06](../05-cross-cutting/06-operational-design-matrix.md).

### 확장성 — 10배가 되면 무엇이 먼저 깨지는가

| 확장 축 | 10배 시 깨지는 것 | 설계 수단 | 비용이 비례하는 변수 |
|---|---|---|---|
| **요청 수** (중심 축) | 라우터가 프롬프트 LLM이면 모델 API 레이트 리밋이 가장 먼저. 변환(재작성·분해·HyDE)이 요청당 1~3회 LLM 호출을 더함 | 규칙 선처리로 LLM 라우터 호출 비율 축소, 분류기·결정 모델은 자체 서빙 또는 별도 한도로 생성 API 한도와 분리, 정규화 질의 기준 라우팅 결과 캐시, 재작성 결과 캐시(캐시 키에 대화 요약 해시 포함), 변환과 검색 병렬화 | 요청 수 × (라우터 호출 1 + 변환 호출 수) |
| **하위 질문·멀티 쿼리 수** | 검색 N회가 [03](03-retrieval-reranking.md)으로 전파되어 벡터DB·BM25 부하 N배 | N 상한(예시 4), 병렬 실행 | 요청 수 × N |
| **경로·소스 수** | 경로가 늘수록 분류기 재학습 빈도·결정 질문 정의 복잡도 증가, 라우팅 정확도 저하 | 경로 ≤ 6~8, 계층 라우팅(경로군 → 세부), 소스 추가는 라우팅 표만 | 경로 수 × 평가셋 크기(운영 비용) |
| **테넌트** | 테넌트별 소스 매핑·동의어 사전·금칙이 라우팅 표에 분기로 쌓임 | 라우팅 표에 테넌트 차원, 동의어 사전 테넌트 분리, 공통/테넌트 레이어 상속 | 테넌트 수(설정 크기) |

### 운영 안정성 — 장애 모드와 대응

| 장애 모드 | 사용자에게 보이는 증상 | 탐지 신호 | 자동 대응 (폴백·저하) | 사람 개입 기준 |
|---|---|---|---|---|
| 라우터(결정 모델 API·분류기 서빙) 다운·지연 | 모든 요청 지연 또는 실패 | 라우터 오류율·p95, 서킷 브레이커 열림 | 1/07 위험 등급으로 분기. **등급 1 읽기 전용 경로**(기본 소스, 본인 권한 범위 안)는 **규칙 기반 기본 경로**(Advanced 일반 경로)로 계속 + 저하 코드 `routing_fallback`을 계약 ② `degradation[]`([Part 0/01](../00-overview/01-reference-architecture.md))로 전달해 사용자 고지·추적. **권한 경계를 넘거나 행동으로 이어지는 경로**(타 부서 인덱스·정형 DB·툴 실행)는 보수적으로 "범위밖·사람 연결" — 지점별 폴백 방향은 [11](11-decision-layer.md) 폴백 표가 단일 기준 (불균형 ③ 반영) | 폴백 비율 5분간 20% 초과(예시) |
| 변환 LLM 다운·지연 | 멀티턴 맥락 소실("그럼 작년은?" 실패) | 변환 호출 오류율·p95 | 원 질의 + 직전 턴 핵심 명사 결합(규칙)으로 저하, 재작성 생략 플래그 | 10분 지속(예시) |
| 재작성·분해 반복 폭주(Agentic 변형) | 지연·비용 급등 | 요청당 변환 횟수 상한 도달률 | 상한(예시 3회)에서 중단 → 마지막 질의 집합으로 진행 | 상한 도달률 5% 초과(예시) |
| 확신도 분포 드리프트 | 명확화 요청 급증 또는 오판 급증 | 확신도 히스토그램, 명확화 비율, 경로별 abstain 비율([04](04-generation-grounding.md)) 이동 | θ 자동 이동은 **보수적 방향만**(명확화·기본 경로 비율을 늘리는 쪽) + 알림. 완화 방향(자동 비율 확대)은 사람 결정 + 사후 샘플 감사 — [12](12-guardrails-hitl.md) "임시 확대 결정, 사후 감사 대상"과 같은 공통 규칙. 자동 완화는 보정 붕괴를 숨기므로 금지 (불균형 ⑦ 반영) | 명확화 비율이 베이스라인 ±50% 변동(예시) → 평가셋 재측정 |
| 정규화기·형태소 분석기 오류 | BM25 recall 급락 | 토큰 수 0 비율, 분석기 예외율 | 공백 토큰화 + dense 단독으로 저하 | 즉시 |
| 메타데이터 추출 오류(필터로 후보 0) | "관련 문서 없음" 급증 | 필터 적용 후 후보 0 비율 | 메타데이터 필터만 완화해 1회 재검색(ACL은 절대 완화 안 함) → 그래도 0이면 abstain | 비율 10% 초과(예시) |

SLI 후보: 라우팅 정확도(샘플 라벨 대비), 보정 오차(ECE), 라우터 p95, 명확화 비율, 변환 전후 context recall 상승폭, 폴백 비율. SLO 초안(예시): 핵심 경로 라우팅 정확도 ≥ 90%, 라우터 p95 ≤ 300ms, 폴백 비율 < 1%. 서킷 브레이커 위치: 결정 모델 API, 분류기 서빙, 변환 LLM, 형태소 분석기 서비스. 쓰기 행동: 없음(캐시만).

### 유지보수 — 버전·변경·호환

| 버전 관리 대상 | 바꾸면 영향받는 것 | 회귀 테스트 | 함께 배포할 것 (호환) |
|---|---|---|---|
| **라우팅 표**(경로·소스 enum, 임계값 θ, 경로별 변환 전략) — 설정 | 모든 요청의 경로 | 라우터 평가셋 정확도·보정, 경로 분포 비교 | 결정 질문 정의 버전, [01](01-rag-architecture-patterns.md) 패턴 배정표 |
| 결정 질문 정의 / 분류기 모델 버전 | 라우팅 판정과 확신도 분포 | 한국어 평가셋 `[실측]`, 신뢰도 다이어그램 | θ — 모델이 바뀌면 θ는 반드시 재보정 |
| 변환 프롬프트(재작성·분해·HyDE·step-back) | 질의 집합 → recall | 변환 전후 recall 골든셋 | 변환 모델 버전(프롬프트-모델 호환 매트릭스) |
| 정규화 규칙·동의어 사전·형태소 분석기 버전 | BM25 토큰 — [03](03-retrieval-reranking.md) 인덱스와 불일치하면 recall 붕괴 | 토큰화 일치 테스트 | **[03]의 BM25 인덱스 분석기 버전과 반드시 함께**(롤백 단위) |
| 출력 계약 `{queries, filters, route, source, confidence, needs_clarification}` | [03]·트레이스·감사 소비자 | 스키마 호환 테스트 | 추가는 자유, 삭제·의미 변경은 버전 상승(tolerant reader) |

기술 부채로 기록할 것: "라우터는 소형 LLM 프롬프트로 시작, 로그 N건 쌓이면 분류기로", "보정 미확인 상태로 θ 사용 중", "동의어 사전 수동 관리".

### 변화 대응 — 무엇이 바뀌고, 어느 경계에서 흡수하는가

| 변화 유형 | 이 단계에서 바뀌는 것 | 안정적으로 유지할 계약·인터페이스 | 교체 가능한 구현 | 흡수 방식 | 전파 범위 |
|---|---|---|---|---|---|
| **도메인 모델** ★ 가장 빈번 | 경로 추가(새 인덱스·새 패턴), 소스 추가, 메타데이터 필터 어휘 변경 | route/source enum 계약(추가는 자유), 출력 스키마 | 라우팅 표, 결정 질문 정의 | **라우팅 표(설정)만 변경 + 결정 질문 정의 버전 상승** + 평가셋에 신규 경로 샘플 추가. 라우터 코드 불변 | 라우터 평가셋, [01] 패턴 배정표, [03] 소스 매핑 |
| **규칙·정책** | 권한·금칙·명시적 필터 규칙, 범위 밖 정의 | 규칙 평가 인터페이스, 게이트 위치(규칙 라우팅 단계) | 규칙 세트 | 규칙 버전 + 시행일, 규칙 테스트 스위트 | 규칙 라우팅 단계만 |
| **지식** | 문서 어휘 변화 → 동의어 사전, 온톨로지 레이블 | 정규화 인터페이스 | 동의어 사전, 분석기 | 사전 버전(설정), 온톨로지 레이블에서 자동 생성 | [03] BM25 인덱스(재색인 가능성) |
| **모델** | 라우터 수단 교체(분류기 ↔ 결정 모델 ↔ LLM), 변환 LLM 교체 | `route(state, question) → {choice, confidence}` 포트, `generate()` 포트 | 어댑터(Jev / Decisions API / 자체 분류기 / LLM) | 어댑터 교체 + **섀도**(새 라우터 결과를 기록만, 예시 2주) + 보정 재측정 → θ 재설정 → 카나리 | θ, 명확화 비율, 경로 분포 |
| **사용자 환경** | 다국어, 비격식·오타 변형, 테넌트 | 출력 계약 | 언어별 정규화·프롬프트 변형 | 언어·테넌트 키로 설정 분기, 평가셋에 변형 추가 | 평가셋, 동의어 사전 |
| **프로토콜·SDK** | 결정 모델 API 스펙·가격·한도 변경 | 포트 | 어댑터 | 버전 고정 + 업그레이드 창 | 어댑터만 |

가장 자주 바뀌는 것: 라우팅 표(경로·소스 추가, θ)와 동의어 사전 > 변환 프롬프트 > 라우터 모델 > 결정 모델 API 스펙. 코드 밖 설정으로 둘 것: 라우팅 표, θ, 경로별 변환 전략, 동의어 사전, 변환 프롬프트, N 상한. 포트·어댑터 뒤에 둘 외부 의존: 결정 모델 API, 분류기 서빙, 변환 LLM, 형태소 분석기.

### 관측성 — 이 단계에서 무엇을 기록·측정·알림하는가

운영 안정성의 "탐지 신호"가 **실제로 어디서 나오는지**를 설계한다. 기준은 [Part 1/07 관측성 설계 요소](../01-foundations/07-operations-vocabulary.md)와 [Part 5/03](../05-cross-cutting/03-observability-tracing.md). 이 단계는 **판정 속성의 주요 공급원**이다 — 대시보드 ③의 확신도 히스토그램·결정 소스 분포는 대부분 여기서 나온다. 라우터는 오류율 0·p95 정상인 채로 조용히 틀릴 수 있으므로, RED보다 **판정 분포**를 먼저 본다.

| 기록 대상 | 스팬 / 이벤트 (이름, 부모) | 핵심 속성 (버전 키 포함) | 지표 (→ 어느 SLI) | 샘플링 · 보존 · PII |
|---|---|---|---|---|
| 규칙 라우팅(입력 가드레일) | `gate.evaluate input_rules` (부모 `invoke_agent`, 판정 앞) | `agent.decision`(pass/block/out_of_scope/no_permission), `agent.rule_ids[]`, `agent.rules_version`, 차단 사유 코드, `agent.pii_masked` | 규칙 차단률(사유별), 게이트 p95, 범위 밖 비율 | 메타 전수, 차단 건은 질의 본문 전수(마스킹), 통과 건은 해시만 |
| 정규화·형태소 분석 | `routing.normalize` (자식) | `agent.analyzer_version`, `agent.dictionary_version`, `agent.token_count`, 분석기 예외 코드 | 토큰 수 0 비율, 분석기 예외율, 정규화 p95 → 정규화기 오류 | 메타 전수 |
| 경로·소스 판정 | `routing.decide` (부모 `invoke_agent`) | `agent.decision`(route·source), `agent.confidence`(보정 확률), `agent.decision_source`(rule/classifier/decision_model/llm), `agent.threshold`(θ), `agent.question_def_version`, `agent.model_version`(라우터), `agent.needs_clarification`, `agent.outcome`=fallback + `agent.degradation[]`=`routing_fallback`, 폴백 분기(기본 경로 / 범위밖·사람 연결) | **라우터 p95**·오류율, **폴백 비율**(분기별), **명확화 비율**, 확신도 히스토그램(θ 주변 질량), 결정 소스 분포, **라우팅 정확도**·**보정 오차(ECE)**(샘플 라벨, 비동기 라벨링 트레이스를 원 trace에 링크) → 라우터 다운, 확신도 드리프트 | 메타 전수, 저확신(θ ± 0.05 예시)·폴백·명확화 건은 본문 전수 |
| 질의 변환 | `routing.transform {rewrite·decompose·hyde·stepback}` (자식) + 모델 호출 자식(`gen_ai.*`) | `agent.prompt_version`(변환 프롬프트), `agent.model_version`, `agent.query_count`(N), `agent.transform_count`, `agent.limit_hit`, `agent.degradation[]`=`rewrite_skipped`, `agent.cached`(재작성 캐시 히트) | 변환 호출 오류율·p95, 변환 횟수 상한 도달률, N 분포, **변환 전후 context recall 상승폭**(골든셋 오프라인 + 운영 샘플) → 변환 LLM 다운, 변환 반복 폭주 | 메타 전수, 변환 결과 본문 opt-in(대화 요약 포함 — PII 마스킹) |
| 메타데이터 필터 추출 | `routing.extract_filters` (자식) | `agent.filter_keys[]`, `agent.filter_source`(rule/llm), `agent.filter_relaxed`(완화 재검색 여부), 후속 `retrieval.search`의 후보 수를 턴 종료 시 역전파한 `agent.post_filter_candidates` | 필터 적용 후 후보 0 비율, 완화 재검색 비율(ACL 완화는 0건이어야 함) → 메타데이터 추출 오류 | 메타 전수, 필터 값 중 식별자는 해시 |
| 출력 계약 | 이벤트 `routing.output` (부모 `routing.decide`) | 계약 스키마 버전, 스키마 검증 결과, 출력 필드 존재 여부(`queries, filters, route, source, confidence, needs_clarification`) | 출력 스키마 실패율 | 전수 |

| 알림 | 조건 (예시) | 심각도 | 런북 (첫 3단계) |
|---|---|---|---|
| 라우터 폴백 급증 | `routing_fallback` 비율 5분간 20% 초과, 또는 결정 모델·분류기 서킷 열림 | P1 | ① 결정 모델 API·분류기 서빙 상태와 서킷 확인 ② 폴백 분기 분포 확인 — 등급 1 기본 경로 비율 vs 범위밖·사람 연결 비율 ③ 사람 연결로 넘어간 요청의 큐 깊이·대기 시간 확인, 적체 시 접수 제한 |
| 변환 단계 장애 | 변환 호출 오류율이 10분 지속, 또는 `agent.limit_hit`(변환 횟수) 5% 초과 | P2 | ① 변환 LLM 벤더 상태·서킷 확인 ② `rewrite_skipped` 비율과 멀티턴 골든셋 recall 샘플 확인 ③ 반복 폭주면 변환 프롬프트 최근 버전 확인 후 상한 하향 |
| 확신도 분포 드리프트 | 명확화 비율이 베이스라인 ±50%, 또는 ECE 샘플 측정값이 기준 초과, 또는 경로 비율 급변 | P2 | ① 확신도 히스토그램에서 θ 주변 질량 이동 확인 ② 라우터 모델·질문 정의·라우팅 표 버전 변경 이력 확인 ③ 보수적 방향(명확화·기본 경로 확대)으로만 θ 임시 조정, 완화는 사람 결정 + 사후 샘플 감사 |
| 정규화기 오류 | 토큰 수 0 비율 또는 분석기 예외율이 베이스라인 초과(즉시) | P1 | ① 형태소 분석기 서비스 상태·버전 확인 ② [03](03-retrieval-reranking.md) BM25 인덱스 분석기 버전과 일치 여부 확인 ③ 공백 토큰화 + dense 단독 저하가 발동했는지 확인 |
| 필터 후 후보 0 급증 | 후보 0 비율 10% 초과 | P2 | ① 필터 키 분포에서 특정 키·값이 급증했는지 확인 ② 완화 재검색이 ACL은 건드리지 않았는지 확인(`filter_relaxed` 중 ACL 키 0건) ③ 인덱스 신선도·메타데이터 어휘 변경([Part 2/07](../02-data-pipeline/07-freshness-and-sync.md)) 확인 |

대시보드에서 이 단계를 보는 뷰: ① E2E — 폴백률 중 `routing_fallback` 분해, 명확화 비율 / ② Reasoning 패널 "라우팅" — 라우터 p95, 규칙 차단률(사유별), 변환 횟수·N 분포, 후보 0 비율 / ③ 비용·판정 분포 — **확신도 히스토그램·결정 소스 분포(이 단계가 주 공급원)**, 변환 호출 비용 비중.
감사 추적으로 넘기는 필드(관측 로그와 분리): 질의 해시, 정규화 결과, 적용 규칙 ID·버전, route·source·확신도·결정 소스, 라우터 모델·질문 정의 버전, 변환 종류·변환 프롬프트 버전, 폴백 분기, 명확화 여부 — 거버넌스 접점 표와 동일. 질의 원문은 관측 로그(opt-in)에만.
이 단계의 관측이 없으면 못 보는 장애: **조용한 오분류** — 라우터가 죽으면 모두 알지만, 라우터가 틀리면 아무 오류도 없다. 확신도 히스토그램·경로 비율·샘플 라벨 정확도가 없으면 오분류는 몇 단계 뒤 [04](04-generation-grounding.md)의 abstain 급증으로 처음 보이고, 그때는 원인이 라우터인지 검색인지 구분할 수 없다.

### 거버넌스 접점 — 정책 · 가드레일 · 승인 · 감사

| 항목 | 이 단계에서의 답 |
|---|---|
| 위험 등급 (1~5) | **1~2**. 라우팅 자체는 가역·본인 영향(1). 소스 라우팅이 권한 경계를 넘는 소스(타 부서 인덱스, 정형 DB)로 보낼 수 있으면 2 — 권한 규칙 게이트 필수 |
| 가드레일 위치 | **입력 가드레일의 실제 자리**. 인젝션·금칙·범위 밖·권한 없음을 규칙 라우팅 단계에서 처리. 가드레일 설계 상세는 [12](12-guardrails-hitl.md), 인젝션은 [Part 5/01](../05-cross-cutting/01-security-prompt-injection.md) |
| 게이트 출력과 판정 수단 | 통과(경로 확정) / 차단(권한 없음·금칙) / 저하(확신 < θ → 명확화 또는 보수적 기본 경로) / 승인 요청은 해당 없음(행동이 없음). 보안·권한·금칙은 **규칙만**, 경로·소스는 결정 모델·분류기, 명확화 문구 생성만 LLM |
| 소유자 (A) | 라우팅 표·결정 질문 정의: 제품 책임자(A), AI 엔지니어(R). 권한·금칙 규칙: 보안 책임자(A). 동의어 사전: 도메인 소유자(A) |
| 감사 추적에 남길 필드 | 원 질의 해시(PII 고려해 원문은 관측 로그에만), 정규화 결과, 적용된 규칙 ID·버전, 라우팅 판정(route·source)과 확신도, 라우터 모델·질문 정의 버전, 적용 변환 종류와 변환 프롬프트 버전, 폴백 여부, 명확화 여부 |

### 운영 준비도 체크
- [ ] 라우터 장애 시 등급 1 읽기 경로는 규칙 기반 기본 경로로, 권한·행동 경로는 범위밖·사람 연결로 분기되고([11](11-decision-layer.md) 폴백 표), `routing_fallback`이 계약 ②로 전달되며 폴백 비율을 SLI로 보고 있는가 (불균형 ③ 반영)
- [ ] 라우터 p95·라우팅 정확도·보정 오차의 베이스라인이 있고 SLO 초안이 있는가
- [ ] 라우팅 표·θ·변환 전략·동의어 사전이 코드 밖 설정으로 버전 관리되고, 경로 추가가 코드 변경 없이 가능한가
- [ ] 라우터 모델 교체 시 섀도 → 보정 재측정 → θ 재설정 절차가 문서화되어 있는가
- [ ] 정규화기·분석기 버전이 [03] 인덱스 분석기와 같은 롤백 단위로 묶여 있는가
- [ ] 권한·금칙 게이트가 규칙만으로 판정되고 LLM 판정으로 우회할 수 없는가
- [ ] 트레이스에 라우팅 판정·확신도·규칙 버전·질문 정의 버전이 있어 "그때 왜 그 경로였나"를 재구성할 수 있는가
- [ ] `routing.decide`에 확신도·θ·결정 소스·질문 정의 버전이 전수 기록되고, 확신도 히스토그램·명확화 비율 이동에 알림과 런북이 연결되어 있는가
- [ ] `routing_fallback`을 분기(등급 1 기본 경로 / 범위밖·사람 연결)별로 셀 수 있고, 사람 연결 큐 깊이가 함께 보이는가
