# 검색과 리랭킹

> **범위**: hybrid 검색, RRF, cross-encoder/LLM rerank, 컨텍스트 압축

## 요약 (3줄)

1. 검색은 **recall 단계**(넓게 후보를 모음)와 **precision 단계**(리랭킹·압축으로 좁힘)로 나뉜다. 두 단계를 한 번의 벡터 검색으로 때우는 것이 Naive RAG 실패의 대부분이다.
2. 기본값은 hybrid(BM25 + dense) + RRF(Reciprocal Rank Fusion) + cross-encoder 리랭커다. 단독 검색보다 우수하고 리랭커가 난이도 높은 셋에서 추가 이득을 준다는 보고가 누적되어 있다 `[2차]`.
3. 메타데이터 필터와 ACL은 리랭킹 **앞**(검색 시점)에 적용한다. 뒤에서 걸러내면 top-k가 비거나 권한 없는 문서가 리랭킹 점수에 영향을 준다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | [02](02-query-understanding.md)의 질의 집합과 필터를 받아, 권한 내에서, 관련도 순으로 정렬되고 컨텍스트 예산 안에 들어가는 **근거 단위 묶음**(원문 위치·메타데이터·점수 포함)을 [04](04-generation-grounding.md)에 넘긴다. 품질 기준은 context precision·recall([13](13-evaluation-rag-agents.md)) |
| **언제** (When) | RAG를 쓰면 항상. hybrid는 전문 용어·약어·고유명사가 많은 코퍼스에서 필수. 리랭커는 recall 단계의 top-20~50 안에 정답이 있는데 top-5에 없을 때 추가. 압축은 컨텍스트 예산이 빡빡하거나 청크가 길 때. 그래프 탐색 결합은 [01](01-rag-architecture-patterns.md)에서 멀티홉 경로가 확인된 뒤 |
| **어떻게** (How) | ① ACL·메타데이터 필터를 검색 조건으로 변환 → ② BM25(형태소 분석 토크나이저)와 dense를 각각 top-N 조회 → ③ RRF로 융합 → ④ cross-encoder로 top-k 리랭킹 → ⑤ 필요 시 추출형·요약형 압축 → ⑥ 컨텍스트 예산에 맞춰 top-k 확정, 점수·순위 기록 → ⑦ 평가셋으로 recall@N, precision@k `[실측]` |
| **왜** (Why) | dense 단독은 고유명사·숫자·약어에서 실패하고, BM25 단독은 동의어·의역에서 실패한다. 리랭킹 없이 top-k를 늘리면 무관 청크가 컨텍스트를 채워 생성 품질이 떨어진다. ACL을 뒤에 적용하면 권한 없는 문서가 결과를 왜곡하고 데이터 유출 경로가 된다 |

## 문제와 맥락

임베딩 검색은 의미 유사도를 재지만 사용자가 원하는 것은 **관련성**이다. 둘은 다르다. "2025년 3분기 매출"을 물으면 "2024년 3분기 매출" 청크가 의미적으로 가장 유사하지만 관련성은 없다. 고유명사·제품 코드·날짜·숫자는 임베딩이 뭉개는 대표적 신호이고, 정확히 BM25가 잘 잡는 신호다. 반대로 "휴가 이월"과 "미사용 연차 승계"는 BM25가 놓치고 임베딩이 잡는다. hybrid는 이 상보성을 이용한다.

융합된 후보는 수십 개다. 그중 생성에 넣을 수 있는 것은 컨텍스트 예산 안의 몇 개뿐이다. 이 선별을 bi-encoder 점수(질의와 문서를 따로 임베딩)로 하면 정밀도가 낮다. cross-encoder는 질의와 문서를 **함께** 입력받아 관련성을 직접 채점하므로 정밀하지만 후보 수만큼 추론이 필요해 recall 단계에는 못 쓴다. 그래서 "넓게 모으고(bi-encoder·BM25) 정밀하게 고른다(cross-encoder)"는 2단계가 표준이 됐다.

한국어에서는 BM25의 토크나이저가 품질을 좌우한다. 공백 기준 토큰화는 조사가 붙은 어절을 다른 토큰으로 취급한다. 형태소 분석기로 명사·어간을 추출해 인덱싱하고 질의도 같은 분석기로 처리해야 BM25가 제 역할을 한다. 청킹 측 전제는 [Part 2/02](../02-data-pipeline/02-chunking-strategies.md), 인덱스 선택은 [Part 2/04](../02-data-pipeline/04-embedding-indexing.md).

## 핵심 개념

### Recall 단계: hybrid + RRF

RRF는 각 검색기의 순위만 사용해 `score = Σ 1/(k + rank_i)`로 융합한다(k는 보통 60). 점수 스케일이 다른 BM25와 dense를 정규화 없이 합칠 수 있어 구현이 단순하고 튜닝이 거의 없다. 대안인 가중 선형 결합은 점수 정규화와 가중치 튜닝이 필요하지만 코퍼스 특성에 맞출 수 있다. [02](02-query-understanding.md)의 멀티 쿼리 결과도 같은 RRF로 융합한다.

### Precision 단계: 리랭킹

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **cross-encoder** | (질의, 문서) 쌍을 소형 트랜스포머에 넣어 관련성 점수 | 빠름(수십 ms급, 후보 수 비례), 저렴, 보정 가능 | 긴 문서 절단, 학습 도메인 밖에서 약화, 한국어 모델 선택지 제한 |
| **LLM rerank (listwise/pointwise)** | LLM에 후보 목록을 주고 순위 또는 점수를 생성 | 도메인 적응 없이 복잡한 관련성 판단, 설명 가능 | 비용·지연 큼, 위치 편향, 후보 수 제한 |
| **결정 모델 (pointwise)** | 각 (질의, 문서)에 "관련 있는가" 타입드 질문 → 보정 확률 | 생성 없음, 보정 확률로 컷오프 설계 | 신생, 한국어 미검증, 사례 미확인 |
| **ColBERT류 late interaction** | 토큰 수준 다중 벡터로 recall과 precision 사이 | bi-encoder보다 정밀, cross-encoder보다 빠름 | 인덱스 크기, 인프라 지원 제한. [Part 2/04](../02-data-pipeline/04-embedding-indexing.md) |

### 컨텍스트 압축

| 방식 | 동작 | 적합 | 위험 |
|---|---|---|---|
| **추출형** | 청크에서 질의 관련 문장만 골라냄(소형 모델·규칙) | 원문 보존이 중요(citation 정확도), 긴 청크 | 문맥 단절로 의미 왜곡 |
| **요약형** | LLM이 여러 청크를 질의 중심으로 요약 | 중복 많은 청크, 예산 극히 빡빡 | 요약이 환각을 넣음, citation이 원문과 어긋남 |

압축은 [04](04-generation-grounding.md)의 citation 정합성과 충돌한다. 요약형을 쓰면 citation은 요약이 아니라 **원문 위치**를 가리켜야 하므로 근거 단위에 원문 참조를 유지한다.

### 그래프 탐색 결합

벡터·BM25 결과의 엔티티를 시작점으로 지식그래프를 1~2홉 탐색해 관련 노드의 원문 청크를 후보에 추가한다. 멀티홉 질의의 두 번째 홉 문서를 찾는 수단이다. 그래프 탐색 결과도 **원문 청크로 환원**해 같은 리랭킹·citation 경로를 타야 한다. 그래프 구축은 [Part 2/05](../02-data-pipeline/05-knowledge-graph-construction.md), 패턴 선택은 [01](01-rag-architecture-patterns.md).

### top-k 결정

top-k는 상수가 아니다. ① 컨텍스트 예산(토큰), ② 리랭커 점수 분포(점수 급락 지점 컷오프), ③ 질의 유형(단순 사실은 3~5, 종합은 10~15) 세 가지로 결정한다. 고정 k는 단순 질의에 노이즈를, 종합 질의에 누락을 만든다. 점수 임계값 기반 컷오프를 쓰면 "관련 문서 없음"을 자연스럽게 감지해 [04](04-generation-grounding.md)의 근거 없음 처리로 넘길 수 있다.

### 메타데이터 필터와 ACL

[02](02-query-understanding.md)가 추출한 필터(기간·부서·문서 유형)와 사용자의 권한을 **검색 조건**으로 넣는다(pre-filtering). 벡터DB 대부분이 필터 조건부 ANN을 지원한다. post-filtering은 ① top-k가 비고 ② 권한 없는 문서가 융합·리랭킹 점수에 개입하며 ③ 임베딩 유사도만으로 권한 없는 문서의 존재가 노출될 수 있다. ACL 모델링은 [Part 2/10](../02-data-pipeline/10-access-control-governance.md).

### 선택 가이드

- **고유명사·코드·숫자 질의가 많고 recall이 낮다면** → hybrid + RRF. 이유: dense가 뭉개는 신호를 BM25가 잡는다. 한국어는 형태소 토크나이저 필수
- **recall은 충분한데 top-5에 정답이 없다면** → cross-encoder 리랭커. 이유: 비용 대비 precision 향상이 가장 크다. 한국어 모델이 없으면 다국어 모델 `[실측]` 후 결정
- **관련성 판단이 조건부·다단계라면** → LLM rerank를 오프라인 평가나 소수 후보에 한정. 이유: 온라인 경로에 두면 비용·지연이 생성과 맞먹는다
- **멀티홉 실패가 측정으로 확인되고 KG가 있다면** → 그래프 탐색 결합, 결과는 원문 청크로 환원. 이유: 그래프 우위가 `[검증]`된 유일한 영역이다
- **컨텍스트 예산이 빡빡하다면** → 추출형 압축 먼저, 요약형은 원문 참조를 유지할 때만. 이유: citation 정합성을 깨지 않는다
- **판단이 어려우면** → hybrid + RRF + cross-encoder + 점수 컷오프를 기본값으로. 이유: 가장 널리 보고된 조합이고 각 요소를 독립적으로 끄고 켜며 효과를 측정할 수 있다

## 설계 시 고려사항 (체크리스트)

- [ ] BM25 토크나이저가 형태소 분석 기반이고 인덱싱과 질의에 같은 분석기를 쓰는가
- [ ] ACL과 메타데이터 필터가 pre-filter로 모든 검색기(BM25·dense·그래프)에 적용되는가
- [ ] recall 단계의 top-N과 리랭킹 후 top-k가 분리되어 있고 각각 측정하는가 (recall@N, precision@k)
- [ ] 리랭커 점수에 "관련 없음" 임계값이 있고 [04](04-generation-grounding.md)의 근거 없음 처리로 이어지는가
- [ ] top-k가 질의 유형·컨텍스트 예산·점수 분포로 결정되는가 (상수 아님)
- [ ] 압축 후에도 근거 단위가 원문 위치(source_id, span)를 유지하는가
- [ ] 그래프 탐색 결과가 원문 청크로 환원되어 같은 리랭킹·citation 경로를 타는가
- [ ] 리랭커·임베딩 모델의 한국어 품질을 자체 평가셋으로 `[실측]`했는가
- [ ] 멀티 쿼리·하위 질문의 결과 융합이 중복 제거를 포함하는가
- [ ] 검색 점수·순위·필터·적용 여부가 트레이스에 기록되는가 ([Part 5/03](../05-cross-cutting/03-observability-tracing.md))
- [ ] 인덱스 갱신 지연(신선도)이 검색 결과에 미치는 영향을 아는가 ([Part 2/07](../02-data-pipeline/07-freshness-and-sync.md))

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 한국어 리랭커·임베딩 선택지 제한 | 영어 벤치마크 성능이 재현되지 않음 | 다국어 모델 비교 `[실측]`, 필요 시 도메인 파인튜닝 |
| cross-encoder의 문서 절단 | 긴 청크의 뒷부분이 채점에서 빠짐 | 청크 길이 제한([Part 2/02](../02-data-pipeline/02-chunking-strategies.md)), 추출형 압축 선행 |
| LLM rerank의 위치 편향 | 후보 순서에 따라 순위가 흔들림 | 후보 순서 셔플 후 집계, 또는 pointwise |
| 리랭커 점수 비보정 | 임계값이 코퍼스·질의 유형마다 다름 | 유형별 임계값 실측, 신뢰도 다이어그램 |
| 요약형 압축의 환각 | 원문에 없는 내용이 근거로 둔갑 | 원문 참조 유지, [04](04-generation-grounding.md) 정합성 검증기 |
| 두 인덱스의 신선도 불일치 | BM25에는 있고 dense에는 없는 문서(또는 반대) | 인덱싱 파이프라인에서 원자적 갱신, [Part 2/07](../02-data-pipeline/07-freshness-and-sync.md) |
| post-filtering 유출 | 권한 없는 문서가 점수·존재로 노출 | pre-filter 강제, 필터 우회 테스트 |
| 지연 누적 | 검색 2종 + 융합 + 리랭킹 + 압축 직렬 | 검색 병렬화, 후보 수 제한, 단순 경로는 리랭킹 생략 |

## 최신 트렌드 적용 (최근 1년)

| 트렌드 | 이 단계에서의 역할 | 적용 조건 | 검증 수준 |
|---|---|---|---|
| 온톨로지 | 메타데이터 필터의 값 체계(부서·문서 유형·제품)를 온톨로지 클래스로 통일. 그래프 탐색의 관계 타입을 온톨로지로 제약해 무관 홉 억제. 동의어 확장을 온톨로지 레이블에서 | 온톨로지 보유, 그래프 탐색 결합 | `[2차]` |
| 뉴로심볼릭 | ACL·필터는 규칙(기호)이 최종 결정, 관련성은 모델(신경)이 판단하는 이중 구조. 검색 결과가 온톨로지 제약(기간·범위)을 위반하면 규칙이 제거 | 권한·범위 제약이 있는 모든 시스템 | `[2차]` |
| 결정 모델 (Jev / Decisions API) | pointwise 리랭킹("이 문서는 질의에 관련 있는가")과 "검색 결과가 충분한가" 판정을 생성 없이 보정 확률로. Agentic RAG의 재검색 판단에도 | 선택지 닫힘, 한국어 `[실측]` 선행. 사례 미확인 | `[벤더]` `[2차]` |
| Agentic RAG | 검색이 루프 안으로 들어가 "결과 불충분 → 질의 수정 → 재검색"이 자동화. 이 단계가 1회 실행에서 반복 실행으로 | 멀티홉, 비용 상한 관리 가능 | `[2차]` |
| GraphRAG 재평가 | 그래프 탐색 결합의 가치가 최난도 멀티홉으로 한정됨(2607.11683) | 멀티홉 비율 측정 후 | `[검증]` |
| 컨텍스트 엔지니어링 | top-k·압축을 "무엇을 뺄지"의 설계로. 고정 k 대신 예산·점수 기반 동적 선별 | 모든 운영 시스템 | `[벤더]` ADK 프레이밍, [08](08-state-memory-context.md) |
