# 검색과 리랭킹

> **범위**: hybrid 검색, RRF, cross-encoder/LLM rerank, 컨텍스트 압축

## 요약 (3줄)

1. 검색은 **recall 단계**(넓게 후보를 모음)와 **precision 단계**(리랭킹·압축으로 좁힘)로 나뉜다. 두 단계를 한 번의 벡터 검색으로 때우는 것이 Naive RAG 실패의 대부분이다.
2. 기본값은 hybrid(BM25 + dense) + RRF(Reciprocal Rank Fusion) + cross-encoder 리랭커다. 단독 검색보다 우수하고 리랭커가 난이도 높은 셋에서 추가 이득을 준다는 보고가 누적되어 있다 `[2차]`.
3. 메타데이터 필터와 ACL은 리랭킹 **앞**(검색 시점)에 적용한다. 뒤에서 걸러내면 top-k가 비거나 권한 없는 문서가 리랭킹 점수에 영향을 준다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | [02](02-query-understanding.md)의 질의 집합과 필터를 받아, 권한 내에서, 관련도 순으로 정렬되고 컨텍스트 예산 안에 들어가는 **근거 단위 묶음**(원문 위치·메타데이터·점수 포함)을 [04](04-generation-grounding.md)에 넘긴다. 품질 기준은 context precision·recall([13](13-evaluation-rag-agents.md)) |
| **언제** (When) | RAG를 쓰면 항상. hybrid는 전문 용어·약어·고유명사가 많은 코퍼스에서 필수. 리랭커는 recall 단계의 top-20~50 안에 정답이 있는데 top-5에 없을 때 추가. 압축은 컨텍스트 예산이 빡빡하거나 청크가 길 때. 그래프 탐색 결합은 [01](01-rag-architecture-patterns.md)에서 멀티홉 경로가 확인된 뒤 |
| **어떻게** (How) | ① ACL·메타데이터 필터를 검색 조건으로 변환 → ② BM25(형태소 분석 토크나이저)와 dense를 각각 top-N 조회 → ③ RRF로 융합 → ④ cross-encoder로 top-k 리랭킹 → ⑤ 필요 시 추출형·요약형 압축 → ⑥ 컨텍스트 예산에 맞춰 top-k 확정, 점수·순위 기록 → ⑦ 평가셋으로 recall@N, precision@k `[실측]` |
| **왜** (Why) | dense 단독은 고유명사·숫자·약어에서 실패하고, BM25 단독은 동의어·의역에서 실패한다. 리랭킹 없이 top-k를 늘리면 무관 청크가 컨텍스트를 채워 생성 품질이 떨어진다. ACL을 뒤에 적용하면 권한 없는 문서가 결과를 왜곡하고 데이터 유출 경로가 된다 |

## 문제와 맥락

임베딩 검색은 의미 유사도를 재지만 사용자가 원하는 것은 **관련성**이다. 둘은 다르다. "2025년 3분기 매출"을 물으면 "2024년 3분기 매출" 청크가 의미적으로 가장 유사하지만 관련성은 없다. 고유명사·제품 코드·날짜·숫자는 임베딩이 뭉개는 대표적 신호이고, 정확히 BM25가 잘 잡는 신호다. 반대로 "휴가 이월"과 "미사용 연차 승계"는 BM25가 놓치고 임베딩이 잡는다. hybrid는 이 상보성을 이용한다.

융합된 후보는 수십 개다. 그중 생성에 넣을 수 있는 것은 컨텍스트 예산 안의 몇 개뿐이다. 이 선별을 bi-encoder 점수(질의와 문서를 따로 임베딩)로 하면 정밀도가 낮다. cross-encoder는 질의와 문서를 **함께** 입력받아 관련성을 직접 채점하므로 정밀하지만 후보 수만큼 추론이 필요해 recall 단계에는 못 쓴다. 그래서 "넓게 모으고(bi-encoder·BM25) 정밀하게 고른다(cross-encoder)"는 2단계가 표준이 됐다.

한국어에서는 BM25의 토크나이저가 품질을 좌우한다. 공백 기준 토큰화는 조사가 붙은 어절을 다른 토큰으로 취급한다. 형태소 분석기로 명사·어간을 추출해 인덱싱하고 질의도 같은 분석기로 처리해야 BM25가 제 역할을 한다. 청킹 측 전제는 [Part 2/02](../02-data-pipeline/02-chunking-strategies.md), 인덱스 선택은 [Part 2/04](../02-data-pipeline/04-embedding-indexing.md).

## 핵심 개념

### Recall 단계: hybrid + RRF

RRF는 각 검색기의 순위만 사용해 `score = Σ 1/(k + rank_i)`로 융합한다(k는 보통 60). 점수 스케일이 다른 BM25와 dense를 정규화 없이 합칠 수 있어 구현이 단순하고 튜닝이 거의 없다. 대안인 가중 선형 결합은 점수 정규화와 가중치 튜닝이 필요하지만 코퍼스 특성에 맞출 수 있다. [02](02-query-understanding.md)의 멀티 쿼리 결과도 같은 RRF로 융합한다.

### Precision 단계: 리랭킹

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **cross-encoder** | (질의, 문서) 쌍을 소형 트랜스포머에 넣어 관련성 점수 | 빠름(수십 ms급, 후보 수 비례), 저렴, 보정 가능 | 긴 문서 절단, 학습 도메인 밖에서 약화, 한국어 모델 선택지 제한 |
| **LLM rerank (listwise/pointwise)** | LLM에 후보 목록을 주고 순위 또는 점수를 생성 | 도메인 적응 없이 복잡한 관련성 판단, 설명 가능 | 비용·지연 큼, 위치 편향, 후보 수 제한 |
| **결정 모델 (pointwise)** | 각 (질의, 문서)에 "관련 있는가" 타입드 질문 → 보정 확률 | 생성 없음, 보정 확률로 컷오프 설계 | 신생, 한국어 미검증, 사례 미확인 |
| **ColBERT류 late interaction** | 토큰 수준 다중 벡터로 recall과 precision 사이 | bi-encoder보다 정밀, cross-encoder보다 빠름 | 인덱스 크기, 인프라 지원 제한. [Part 2/04](../02-data-pipeline/04-embedding-indexing.md) |

### 컨텍스트 압축

| 방식 | 동작 | 적합 | 위험 |
|---|---|---|---|
| **추출형** | 청크에서 질의 관련 문장만 골라냄(소형 모델·규칙) | 원문 보존이 중요(citation 정확도), 긴 청크 | 문맥 단절로 의미 왜곡 |
| **요약형** | LLM이 여러 청크를 질의 중심으로 요약 | 중복 많은 청크, 예산 극히 빡빡 | 요약이 환각을 넣음, citation이 원문과 어긋남 |

압축은 [04](04-generation-grounding.md)의 citation 정합성과 충돌한다. 요약형을 쓰면 citation은 요약이 아니라 **원문 위치**를 가리켜야 하므로 근거 단위에 원문 참조를 유지한다.

### 그래프 탐색 결합

벡터·BM25 결과의 엔티티를 시작점으로 지식그래프를 1~2홉 탐색해 관련 노드의 원문 청크를 후보에 추가한다. 멀티홉 질의의 두 번째 홉 문서를 찾는 수단이다. 그래프 탐색 결과도 **원문 청크로 환원**해 같은 리랭킹·citation 경로를 타야 한다. 그래프 구축은 [Part 2/05](../02-data-pipeline/05-knowledge-graph-construction.md), 패턴 선택은 [01](01-rag-architecture-patterns.md).

### top-k 결정

top-k는 상수가 아니다. ① 컨텍스트 예산(토큰), ② 리랭커 점수 분포(점수 급락 지점 컷오프), ③ 질의 유형(단순 사실은 3~5, 종합은 10~15) 세 가지로 결정한다. 고정 k는 단순 질의에 노이즈를, 종합 질의에 누락을 만든다. 점수 임계값 기반 컷오프를 쓰면 "관련 문서 없음"을 자연스럽게 감지해 [04](04-generation-grounding.md)의 근거 없음 처리로 넘길 수 있다.

### 메타데이터 필터와 ACL

[02](02-query-understanding.md)가 추출한 필터(기간·부서·문서 유형)와 사용자의 권한을 **검색 조건**으로 넣는다(pre-filtering). 벡터DB 대부분이 필터 조건부 ANN을 지원한다. post-filtering은 ① top-k가 비고 ② 권한 없는 문서가 융합·리랭킹 점수에 개입하며 ③ 임베딩 유사도만으로 권한 없는 문서의 존재가 노출될 수 있다. ACL 모델링은 [Part 2/10](../02-data-pipeline/10-access-control-governance.md).

### 선택 가이드

- **고유명사·코드·숫자 질의가 많고 recall이 낮다면** → hybrid + RRF. 이유: dense가 뭉개는 신호를 BM25가 잡는다. 한국어는 형태소 토크나이저 필수
- **recall은 충분한데 top-5에 정답이 없다면** → cross-encoder 리랭커. 이유: 비용 대비 precision 향상이 가장 크다. 한국어 모델이 없으면 다국어 모델 `[실측]` 후 결정
- **관련성 판단이 조건부·다단계라면** → LLM rerank를 오프라인 평가나 소수 후보에 한정. 이유: 온라인 경로에 두면 비용·지연이 생성과 맞먹는다
- **멀티홉 실패가 측정으로 확인되고 KG가 있다면** → 그래프 탐색 결합, 결과는 원문 청크로 환원. 이유: 그래프 우위가 `[검증]`된 유일한 영역이다
- **컨텍스트 예산이 빡빡하다면** → 추출형 압축 먼저, 요약형은 원문 참조를 유지할 때만. 이유: citation 정합성을 깨지 않는다
- **판단이 어려우면** → hybrid + RRF + cross-encoder + 점수 컷오프를 기본값으로. 이유: 가장 널리 보고된 조합이고 각 요소를 독립적으로 끄고 켜며 효과를 측정할 수 있다

## 설계 시 고려사항 (체크리스트)

- [ ] BM25 토크나이저가 형태소 분석 기반이고 인덱싱과 질의에 같은 분석기를 쓰는가
- [ ] ACL과 메타데이터 필터가 pre-filter로 모든 검색기(BM25·dense·그래프)에 적용되는가
- [ ] recall 단계의 top-N과 리랭킹 후 top-k가 분리되어 있고 각각 측정하는가 (recall@N, precision@k)
- [ ] 리랭커 점수에 "관련 없음" 임계값이 있고 [04](04-generation-grounding.md)의 근거 없음 처리로 이어지는가
- [ ] top-k가 질의 유형·컨텍스트 예산·점수 분포로 결정되는가 (상수 아님)
- [ ] 압축 후에도 근거 단위가 원문 위치(source_id, span)를 유지하는가
- [ ] 그래프 탐색 결과가 원문 청크로 환원되어 같은 리랭킹·citation 경로를 타는가
- [ ] 리랭커·임베딩 모델의 한국어 품질을 자체 평가셋으로 `[실측]`했는가
- [ ] 멀티 쿼리·하위 질문의 결과 융합이 중복 제거를 포함하는가
- [ ] 검색 점수·순위·필터·적용 여부가 트레이스에 기록되는가 ([Part 5/03](../05-cross-cutting/03-observability-tracing.md))
- [ ] 인덱스 갱신 지연(신선도)이 검색 결과에 미치는 영향을 아는가 ([Part 2/07](../02-data-pipeline/07-freshness-and-sync.md))

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 한국어 리랭커·임베딩 선택지 제한 | 영어 벤치마크 성능이 재현되지 않음 | 다국어 모델 비교 `[실측]`, 필요 시 도메인 파인튜닝 |
| cross-encoder의 문서 절단 | 긴 청크의 뒷부분이 채점에서 빠짐 | 청크 길이 제한([Part 2/02](../02-data-pipeline/02-chunking-strategies.md)), 추출형 압축 선행 |
| LLM rerank의 위치 편향 | 후보 순서에 따라 순위가 흔들림 | 후보 순서 셔플 후 집계, 또는 pointwise |
| 리랭커 점수 비보정 | 임계값이 코퍼스·질의 유형마다 다름 | 유형별 임계값 실측, 신뢰도 다이어그램 |
| 요약형 압축의 환각 | 원문에 없는 내용이 근거로 둔갑 | 원문 참조 유지, [04](04-generation-grounding.md) 정합성 검증기 |
| 두 인덱스의 신선도 불일치 | BM25에는 있고 dense에는 없는 문서(또는 반대) | 인덱싱 파이프라인에서 원자적 갱신, [Part 2/07](../02-data-pipeline/07-freshness-and-sync.md) |
| post-filtering 유출 | 권한 없는 문서가 점수·존재로 노출 | pre-filter 강제, 필터 우회 테스트 |
| 지연 누적 | 검색 2종 + 융합 + 리랭킹 + 압축 직렬 | 검색 병렬화, 후보 수 제한, 단순 경로는 리랭킹 생략 |

## 운영 설계 — 확장성 · 안정성 · 유지보수

용어·판단 기준은 [Part 1/07 운영 용어](../01-foundations/07-operations-vocabulary.md). 이 단계의 외부 의존은 벡터DB·BM25·리랭커·그래프DB·ACL 서비스로 Part 3에서 가장 많다. 그중 **ACL 필터는 데이터 접근 통제의 실행 지점**이라 나머지와 다른 장애 정책(fail-closed)을 가진다. 레이어 간 종합은 [Part 5/06](../05-cross-cutting/06-operational-design-matrix.md).

### 확장성 — 10배가 되면 무엇이 먼저 깨지는가

| 확장 축 | 10배 시 깨지는 것 | 설계 수단 | 비용이 비례하는 변수 |
|---|---|---|---|
| **요청 수** (중심 축) | **리랭커 처리량**. cross-encoder는 요청마다 후보 수 N만큼 추론하므로 요청 수 × N으로 GPU가 포화. 벡터DB QPS, BM25 샤드 | 리랭커 복제·배치 추론, 후보 수 축소(예시 50 → 30), 단순 경로는 리랭킹 생략, 결과 캐시(정규화 질의 + 필터 + 인덱스 버전 + **주체 집합 해시** 키, TTL ≤ [Part 2/10](../02-data-pipeline/10-access-control-governance.md) 주체 해석 TTL 예시 5분 — 불균형 ② 반영), 요청 경로 무상태 | 요청 수 × 후보 수 N |
| **데이터** | 벡터 인덱스 메모리, ANN recall 저하, pre-filter 선택도가 낮으면 필터 조건부 ANN 성능 급락 | 파티셔닝·양자화([Part 2/04](../02-data-pipeline/04-embedding-indexing.md)), 필터 카디널리티 설계, 대형 테넌트는 인덱스 분리 | 문서 수 (Part 2 축) |
| **그래프 탐색** | 홉 수·분기도에 따라 후보가 기하급수로 폭발 | 홉 ≤ 2, 노드당 이웃 상한, 관계 타입 허용 목록(온톨로지) | 시작 엔티티 수 × 분기도^홉 |
| **멀티 쿼리·하위 질문** | 검색 N회가 두 인덱스 모두에 N배 부하 | 병렬 + N 상한([02](02-query-understanding.md)), 중복 제거 후 리랭킹 | N |
| **테넌트** | 테넌트 필터 선택도, ACL 조회 지연 | 테넌트 키를 모든 레코드·캐시 키에, ACL 결과 단기 캐시(권한 변경 시 즉시 무효화) | 테넌트 수 × 권한 규칙 수 |

### 운영 안정성 — 장애 모드와 대응

| 장애 모드 | 사용자에게 보이는 증상 | 탐지 신호 | 자동 대응 (폴백·저하) | 사람 개입 기준 |
|---|---|---|---|---|
| 벡터DB 다운·지연 | 의역 질의 recall 급락 | 오류율·p95, 서킷 브레이커 열림 | BM25 단독 저하 + "축소 검색" 플래그 → [04](04-generation-grounding.md)가 확신도를 낮추고 표시 | 5분 지속(예시) |
| BM25 인덱스 다운 | 고유명사·코드·숫자 질의 recall 급락 | 오류율 | dense 단독 저하 + 플래그 | 5분 지속(예시) |
| **리랭커 타임아웃·다운** | 지연 증가 또는 무관 청크 상위 노출 | 리랭커 p95·오류율·타임아웃 카운트 | 타임아웃(예시 300ms) 초과 시 RRF 순위 그대로 top-k, 리랭킹 생략 플래그. θ 컷오프는 적용 불가이므로 고정 k로 | 생략률 20%가 10분 지속(예시) |
| 그래프 탐색 폭발·그래프DB 지연 | 멀티홉 질의 수 초 지연 | 탐색 노드 수·시간 상한 도달률 | 노드·시간 상한에서 절단 → 수집된 후보로 진행, 그래프 생략 플래그 | 상한 도달률 10%(예시) |
| 필터 후 후보 0 / θ 미달 급증 | "관련 문서 없음" 급증 | 후보 0 비율, 최고 점수 분포 이동 | 메타데이터 필터만 1회 완화 재검색 → 그래도 0이면 abstain | 비율 10% 초과(예시) → 인덱스 신선도·임베딩 버전 의심 |
| 두 인덱스 신선도 불일치 | 같은 문서가 한쪽에만 | 인덱스 버전 불일치 알림 | 최신 **공통** 버전으로 질의(버전 핀) | 즉시 — 원인 추적은 [Part 2/07](../02-data-pipeline/07-freshness-and-sync.md) |
| **ACL 조회 서비스 다운** | 유출 위험 | ACL 조회 오류율 | **fail-closed**: 검색 중단 + abstain. 필터 없이 검색하는 폴백은 존재하지 않는다 | 즉시 온콜 |

SLI 후보: recall@N·precision@k(샘플), 검색 단계 p95, 리랭킹 생략률, 후보 0 비율, 인덱스 버전 불일치 건수, ACL 필터 적용률(항상 100%), **삭제 이벤트 → 결과 캐시 제거 p95**(불균형 ① 반영). SLO 초안(예시): 검색 단계 p95 ≤ 800ms, 리랭킹 생략률 < 2%, ACL 적용률 = 100%(위반 1건이 인시던트). 서킷 브레이커 위치: 벡터DB, BM25, 리랭커, 그래프DB, ACL 서비스 — 단 ACL 브레이커가 열리면 "우회"가 아니라 "중단". 쓰기 행동: 없음(캐시만). 결과 캐시는 [Part 2/07](../02-data-pipeline/07-freshness-and-sync.md) 변경 큐 **삭제 레인의 소비자**로 등록해 문서 1건의 톰스톤(인덱스 버전은 그대로)에도 해당 키를 제거하고, ACL 이벤트에도 무효화한다. 캐시 히트 응답도 [Part 2/08](../02-data-pipeline/08-grounding-data-design.md) `acl_checked` 비영속 원칙에 따라 요청 단위로 ACL을 재확인한다 (불균형 ①·② 반영).

### 유지보수 — 버전·변경·호환

| 버전 관리 대상 | 바꾸면 영향받는 것 | 회귀 테스트 | 함께 배포할 것 (호환) |
|---|---|---|---|
| **임베딩 모델 버전** | 전체 재임베딩, dense 결과 전면 변화 | recall@N 골든셋 | **질의 임베딩과 인덱스 임베딩은 같은 모델**이어야 함 — 인덱스 버전과 묶어 블루/그린 전환 |
| **리랭커 모델 버전** | 점수 분포 이동 → θ 무효 | precision@k, 신뢰도 다이어그램 | 컷오프 θ(유형별) 재보정과 함께 |
| 형태소 분석기·사전 버전 | BM25 토큰 → 재색인 필요 | 토큰화 일치 테스트, recall | [02] 정규화기와 동일 버전(롤백 단위) |
| 검색 파라미터(RRF k, top-N, top-k 규칙, θ, 압축 on/off) — 설정 | precision·recall·지연 | 골든셋 | 컨텍스트 예산 ↔ [04] 생성 모델 버전 |
| 그래프 스키마·관계 타입 허용 목록 — 설정 | 멀티홉 후보 | 멀티홉 골든셋 | 온톨로지 버전([Part 2/06](../02-data-pipeline/06-ontology-driven-modeling.md)) |
| 근거 단위 출력 스키마 `{text, source_id, span, score, rank, metadata}` | [04]·Part 4 렌더 | 스키마 호환 | [Part 2/08](../02-data-pipeline/08-grounding-data-design.md) 스키마 버전 |

기술 부채로 기록할 것: "리랭커 θ를 질의 유형별로 미분리", "ACL은 메타데이터 필터로만, 쿼리 조인은 2차", "요약형 압축의 원문 참조 미완".

### 변화 대응 — 무엇이 바뀌고, 어느 경계에서 흡수하는가

| 변화 유형 | 이 단계에서 바뀌는 것 | 안정적으로 유지할 계약·인터페이스 | 교체 가능한 구현 | 흡수 방식 | 전파 범위 |
|---|---|---|---|---|---|
| **지식** ★ 가장 빈번 | 문서 추가·삭제·만료 → 인덱스 갱신 | 근거 단위 스키마, `retrieve(queries, filters, budget) → evidence[]` 포트 | 인덱스 | 증분 인덱싱 + 인덱스 버전 키·**문서 ID 톰스톤**으로 캐시 무효화, 삭제는 삭제 레인을 통해 두 인덱스·결과 캐시에 전파(제거 p95를 SLI로, 불균형 ① 반영) | 캐시, 두 인덱스 동시 |
| **모델** (임베딩 교체) | 임베딩 모델·차원 | 포트 | 임베딩 어댑터 | **전체 재임베딩 창**: 신·구 인덱스 병행 → 섀도 비교 → 블루/그린 전환, 질의 임베딩 동시 전환 | Knowledge 전체([Part 2/04](../02-data-pipeline/04-embedding-indexing.md)) |
| **모델** (리랭커 교체: cross-encoder ↔ LLM ↔ 결정 모델) | 리랭커 | `rerank(query, candidates) → scored[]` 포트 | 어댑터 | 어댑터 교체 + θ 재보정 + 카나리(예시 5%) | θ, [04] abstain 비율 |
| **도메인 모델** | 메타데이터 필터 어휘, 온톨로지 관계 타입 | 필터 어휘 매핑 테이블, 관계 허용 목록(설정) | 필터 변환 규칙 | 매핑 테이블 + 설정 버전 | [02] 필터 추출, 그래프 탐색 |
| **규칙·정책** (ACL 모델 변경) | 권한 규칙·역할 | 모든 검색기 공통 필터 인터페이스 | ACL 조회 어댑터 | 규칙 버전 + 시행일 + 필터 우회 테스트 재실행 | 전 검색기 pre-filter, 캐시 전체 무효화 |
| **사용자 환경** | 다국어 → 다국어 임베딩·언어별 분석기 | 포트 | 언어별 분석기·모델 | 언어 키 설정, 언어별 인덱스 | 언어별 골든셋 |
| **프로토콜·SDK** | 벡터DB 교체·클라이언트 메이저 업 | 포트 | 벡터DB 어댑터 | 어댑터 교체 + 필터 조건부 ANN 의미 차이 검증(pre/post 혼동 금지) | 어댑터 + pre-filter 테스트 |

가장 자주 바뀌는 것: 지식(인덱스 갱신, 일 단위) > 검색 파라미터(N·k·θ) > 임베딩·리랭커 모델(분기~연) > 벡터DB. 코드 밖 설정으로 둘 것: RRF k, top-N, top-k 규칙, 유형별 θ, 압축 on/off, 그래프 홉·이웃 상한·관계 허용 목록, 타임아웃. 포트·어댑터 뒤에 둘 외부 의존: 벡터DB, BM25 엔진, 임베딩 API, 리랭커 서빙, 그래프DB, ACL 서비스.

### 관측성 — 이 단계에서 무엇을 기록·측정·알림하는가

운영 안정성의 "탐지 신호"가 **실제로 어디서 나오는지**를 설계한다. 기준은 [Part 1/07 관측성 설계 요소](../01-foundations/07-operations-vocabulary.md)와 [Part 5/03](../05-cross-cutting/03-observability-tracing.md). 이 단계의 관측에는 다른 단계에 없는 원칙이 하나 있다. **ACL 게이트 스팬이 없는 검색 스팬은 그 자체가 인시던트**다 — 오류가 아니라 "스팬의 부재"를 세어야 하므로, 수집 측에서 `retrieval.search`마다 선행 `gate.evaluate acl_prefilter`가 있는지 턴 종료 시 검증한다.

| 기록 대상 | 스팬 / 이벤트 (이름, 부모) | 핵심 속성 (버전 키 포함) | 지표 (→ 어느 SLI) | 샘플링 · 보존 · PII |
|---|---|---|---|---|
| ACL pre-filter | `gate.evaluate acl_prefilter` (부모 `invoke_agent`, 모든 `retrieval.search` **앞**) | `agent.acl_applied`(항상 true), `agent.subject_set_hash`, `agent.rules_version`(ACL 규칙), `agent.acl_source`(live/cache), ACL 조회 지연, `agent.outcome`=blocked(fail-closed 발동) | **ACL 필터 적용률**(= `acl_prefilter` 스팬을 가진 `retrieval.search` 비율, 항상 100%), ACL 조회 오류율·p95, ACL 캐시 히트율, fail-closed 발동 건수 → ACL 서비스 다운 | **전수**(샘플링 금지), 주체 ID는 해시만 |
| 인덱스별 검색 | `retrieval.search {dense·bm25·graph}` (부모 `invoke_agent`, 병렬 자식) | `agent.index_version`(인덱스별 — 두 인덱스의 값을 턴 종료 시 비교), `agent.embedding_model_version`(질의 임베딩), `agent.candidate_count`, `agent.top_score`, `agent.filter_keys[]`, `agent.circuit_state`, `agent.degradation[]`=`dense_unavailable`·`bm25_unavailable`·`graph_truncated`, `agent.index_pinned_version`(공통 버전 핀) | 인덱스별 오류율·p95, **검색 단계 p95**(병렬 합), **후보 0 비율**, 최고 점수 분포(히스토그램 — 이동 감지), **인덱스 버전 불일치 건수**(dense vs BM25 `index_version` 상이) → 벡터DB·BM25 다운, 신선도 불일치, 후보 0 급증 | 메타 전수, 질의 임베딩·본문은 기록하지 않음 |
| 그래프 탐색 | `retrieval.search graph` 자식 `retrieval.traverse` | `agent.hop_count`, `agent.visited_nodes`, `agent.relation_types[]`, `agent.limit_hit`(nodes/time), `agent.schema_version`(그래프 스키마) | 탐색 노드 수 분포, 노드·시간 상한 도달률 → 그래프 탐색 폭발 | 메타 전수 |
| 리랭킹·컷오프 | `retrieval.rerank` (부모 `invoke_agent`) | `agent.reranker_version`, `agent.input_count`(N), `agent.output_count`(k), `agent.threshold`(유형별 θ), `agent.rerank_skipped`, `agent.degradation[]`=`rerank_skipped`, 점수 요약(최고·p50·θ 미달 수) | 리랭커 p95·오류율·타임아웃 카운트, **리랭킹 생략률**, θ 미달 비율, **precision@k**(샘플 라벨, 비동기 링크) → 리랭커 타임아웃·다운 | 메타 전수, 후보 본문 없음(ID·점수만) |
| 근거 조립·압축 | `retrieval.assemble` (부모 `invoke_agent`) | `agent.evidence_ids[]`, `agent.evidence_count`, `agent.context_tokens`, `agent.compression`(none/extractive/summary), 근거 단위 스키마 버전, 모든 저하 플래그의 합집합(→ [04](04-generation-grounding.md)로 전달) | **recall@N**(샘플 라벨, 오프라인 골든셋 + 운영 샘플), 컨텍스트 예산 초과율, 저하 플래그 전달률(=100%) | ID 전수, 청크 본문 opt-in(예시 1~5%), 후보 0·저하 건은 전수 |
| 결과 캐시 | 이벤트 `cache.lookup` / `cache.invalidate` (부모 `invoke_agent`; 삭제 레인 소비는 배치 `sync.*`) | `agent.cache_hit`, 캐시 키 구성 버전(정규화 질의·필터·인덱스 버전·주체 집합 해시), 무효화 원인(index_version/tombstone/acl_event)·원천 이벤트 ID, 히트 시 ACL 재확인 여부 | 캐시 히트율, **삭제 이벤트 → 결과 캐시 제거 p95**, 히트 응답 ACL 재확인률(=100%) | 전수, 키·질의는 해시만 |

| 알림 | 조건 (예시) | 심각도 | 런북 (첫 3단계) |
|---|---|---|---|
| **ACL 적용률 미달·조회 장애** | `acl_prefilter` 없는 `retrieval.search` 1건 이상, 또는 ACL 조회 오류율 > 0 | **P1 즉시 온콜** | ① fail-closed 동작 확인 — `agent.outcome=blocked` 증가와 필터 없는 검색 스팬 0건을 동시에 확인 ② 적용률 미달이면 해당 요청 ID를 보안 책임자에게 인시던트로 이관(유출 검토) ③ ACL 서비스 상태·캐시 TTL 확인, abstain 고지가 사용자에게 보이는지 확인 |
| 인덱스 저하·그래프 절단 지속 | `dense_unavailable`·`bm25_unavailable` 5분 지속, 또는 그래프 상한 도달률 10% 초과 | P2 | ① 해당 인덱스 서킷 상태·p95 확인 ② 저하 플래그가 `retrieval.assemble`을 거쳐 [04](04-generation-grounding.md)에 전달되는지 확인 ③ 그래프면 홉·이웃 상한 하향, 인덱스면 공통 버전 핀 적용 |
| 리랭킹 생략률 상승 | `rerank_skipped` 비율 20%가 10분 지속 | P2 | ① 리랭커 서빙 p95·포화(요청 수 × N) 확인 ② 후보 수 N 임시 축소(예시 50 → 30) ③ 고정 k 운영 중 precision 샘플 추적, 복구 후 θ 재적용 확인 |
| 후보 0·점수 분포 이동 | 후보 0 비율 10% 초과, 또는 최고 점수 히스토그램이 베이스라인에서 이동 | P2 | ① 임베딩 모델 버전과 인덱스 임베딩 버전 일치 확인 ② [02](02-query-understanding.md) 필터 추출 완화 비율 확인 ③ 인덱스 신선도([Part 2/07](../02-data-pipeline/07-freshness-and-sync.md)) 확인 |
| 인덱스 버전 불일치 | dense·BM25 `index_version` 상이 1건 이상(즉시) | P2 | ① 어느 인덱스가 뒤처졌는지 확인 ② 최신 공통 버전으로 핀이 적용되었는지 확인 ③ 동기화 지연 원인은 [Part 2/07](../02-data-pipeline/07-freshness-and-sync.md) 런북으로 이관 |

대시보드에서 이 단계를 보는 뷰: ② Reasoning 패널의 "검색" 서브패널 — 인덱스별 p95·오류율, 후보 0 비율, 리랭킹 생략률, 최고 점수 히스토그램, **ACL 적용률 게이지(100% 고정이어야 함)**, 인덱스 버전 불일치 카운터 / ① E2E — 저하율 중 검색 저하 코드 분해 / ③ 비용 — 리랭커 추론 수(요청 수 × N) 추이, 캐시 히트율.
감사 추적으로 넘기는 필드(관측 로그와 분리): 적용 필터(주체 집합 해시·ACL 규칙 버전·메타데이터 필터), 인덱스 버전 3종, 임베딩·리랭커 모델 버전, 후보 ID·점수·순위, 컷오프 θ, 저하 플래그, 캐시 히트 여부 — 거버넌스 접점 표와 동일.
이 단계의 관측이 없으면 못 보는 장애: **필터가 조용히 빠진 검색** — 사용자 증상이 없고(답변이 오히려 좋아 보인다) 오류율도 0이다. `gate.evaluate acl_prefilter` 스팬의 **부재**를 세지 않으면 데이터 유출은 사후 감사나 외부 신고로만 발견된다. 그리고 **두 인덱스의 신선도 불일치** — 같은 문서가 한쪽에만 있어도 recall은 조금 낮아질 뿐이라 인덱스별 `index_version` 비교 없이는 영구히 모른다.

### 거버넌스 접점 — 정책 · 가드레일 · 승인 · 감사

| 항목 | 이 단계에서의 답 |
|---|---|
| 위험 등급 (1~5) | 검색 자체는 읽기라 **1**. 단 ACL 필터가 빠지면 여러 사용자·조직 외부 데이터 노출이므로 ACL 경로는 **등급 3 상당의 통제**(fail-closed, 감사, 우회 테스트) |
| 가드레일 위치 | **행동 가드레일에 준함**(데이터 접근 = 행동). pre-filter가 게이트. 출력 측 검증은 [04](04-generation-grounding.md) |
| 게이트 출력과 판정 수단 | 통과 / 차단(권한 없음 → 결과 제외, 존재 자체 비노출) / 저하(리랭킹 생략·단일 인덱스·그래프 절단 — 플래그로 [04]에 전달) / 승인 요청은 해당 없음. ACL은 규칙만, 컷오프는 리랭커 점수(보정 확인 후), 절단은 규칙 |
| 소유자 (A) | 인덱스 **내용·ACL**: 데이터 소유자(A), 데이터 엔지니어(R) — 인덱스 인프라·전환은 데이터 엔지니어링 책임자, 임베딩 모델 선택은 아키텍트([Part 2/04](../02-data-pipeline/04-embedding-indexing.md) 세 행 분리, 불균형 ⑨ 반영). 검색 파라미터·리랭커: 아키텍트(A), AI 엔지니어(R). ACL 모델: 보안 책임자(C) |
| 감사 추적에 남길 필드 | 적용 필터(ACL 주체·규칙 버전·메타데이터 필터), 인덱스 버전(벡터·BM25·그래프), 임베딩·리랭커 모델 버전, 후보 ID·점수·순위, 컷오프 θ, 저하 플래그, 캐시 히트 여부 |

### 운영 준비도 체크
- [ ] ACL 조회 실패 시 fail-closed가 코드로 강제되고 필터 우회 테스트가 CI에 있는가
- [ ] 벡터DB·BM25·리랭커·그래프DB 각각의 타임아웃·서킷 브레이커·저하 경로를 실제로 실행해 봤는가
- [ ] 리랭커 생략률·후보 0 비율·인덱스 버전 불일치가 SLI로 측정되고 알림이 있는가
- [ ] 질의 임베딩과 인덱스 임베딩 모델 버전이 같은 롤백 단위로 묶여 있고 블루/그린 전환 절차가 있는가
- [ ] 리랭커 교체 시 θ 재보정 절차가 있고, 유형별 θ가 설정으로 관리되는가
- [ ] 캐시 키에 테넌트·필터·인덱스 버전·주체 집합 해시가 포함되고, TTL ≤ 주체 해석 TTL이며, 문서 톰스톤·ACL 이벤트가 캐시를 무효화하는가 (불균형 ①·② 반영)
- [ ] 트레이스에 적용 필터·인덱스 버전·후보 점수가 있어 "그때 왜 그 문서가 나왔나"를 재구성할 수 있는가
- [ ] `retrieval.search`마다 선행 `gate.evaluate acl_prefilter` 스팬의 존재를 턴 종료 시 검증하고, 부재 1건이 P1 알림·인시던트가 되는가
- [ ] 인덱스별 `agent.index_version`을 비교해 불일치 건수를 세고, 저하 플래그가 `retrieval.assemble`을 거쳐 [04](04-generation-grounding.md)로 전달되는 비율(=100%)을 측정하는가
