# 워크플로우·RAG 결정 매트릭스

> **범위**: 요구사항 × 패턴 × 프레임워크 종합표와 한계
> 이 Part의 모든 단계에 대한 기술 선택을 **한 장**으로 요약한다. 상세 근거는 각 단계 페이지에 있다. 01~07은 [00-overview](00-overview.md)의 기술 목록을 기준으로 적었다.

## 읽는 법

1. 1절의 입력 변수 10개에 프로젝트의 값을 적는다. 상위 6개(과업 예측 가능성·실패 비용·지연·근거 요구·툴 수·조직 경계)가 대부분의 선택을 결정한다.
2. 2절에서 단계별로 "기본값"을 출발점으로 삼고, 입력 변수가 조건 A/B에 해당하면 그쪽으로 옮긴다. "피해야 할 조합"에 걸리면 설계를 다시 본다.
3. 3절의 세 시나리오 중 가장 가까운 것을 찾아 조합 전체를 참고한다. 상세 근거는 각 단계 페이지의 "선택 가이드"에 있다.
4. 모든 `[벤더]` 항목은 PoC `[실측]` 전까지 잠정이다.

## 4. 한계 종합

이 Part의 기술들이 공통으로 갖는 한계와, 그 한계가 다음 Part로 넘어가는 지점.

- **결정 모델은 아직 `[벤더]` 단계다.** Jev와 Decisions API의 지연·비용·보정은 독립 벤치마크가 없고, 영어 중심 학습이 명시되어 있다. 이 Part의 여러 기본값이 "결정 모델 또는 분류기"로 적힌 이유다. 한국어 `[실측]` 없이 채택하지 않는다.
- **메모리는 기본값이 아니다.** MemTrapBench의 부정 결과 `[2차]`는 메모리를 "추가하면 좋은 것"에서 "검증해야 하는 것"으로 바꿨다. no-memory가 비교군이다.
- **뉴로심볼릭 결합의 V&V는 부분적이다.** 신경·기호 각각은 검증 가능하나 결합 전체의 검증 기법은 미성숙하다(Renkhoff et al. `[검증]`). E2E 골든셋·트래젝토리로 보완하되 한계를 안다.
- **프로토콜·프레임워크는 전환기다.** MCP 2026-07-28 개정, 프레임워크 재편. 프레임워크 밖 모듈을 두껍게 두는 것이 유일한 보험이다.
- **에이전트 평가는 비결정성과 비용의 싸움이다.** 반복 실행·통과율·샘플링으로 흡수하되, 평가 비용이 운영 비용에 근접할 수 있다.
- **인젝션은 프롬프트로 막히지 않는다.** 툴 결과 신뢰 경계와 행동 게이트가 구조적 방어이며, 공격 분류와 전사 방어는 [Part 5/01](../05-cross-cutting/01-security-prompt-injection.md)로 넘어간다.

**다음 Part로 넘기는 것**: 이 Part의 출력은 렌더 가능한 응답 스키마(텍스트 + citation + UI 의도)와 승인 이벤트를 포함한 상태 머신이다. [Part 4](../04-dynamic-ui/00-overview.md)가 이를 소비하고, 비용·관측성·거버넌스는 [Part 5](../05-cross-cutting/00-overview.md)가 가로지른다. 근거 데이터의 품질은 이 Part가 통제할 수 없으며 [Part 2](../02-data-pipeline/99-decision-matrix.md)의 결정에 달려 있다.
