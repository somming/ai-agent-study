# 프론트엔드 통합

> **범위**: React/Next.js, Vercel AI SDK, CopilotKit, 모바일(Flutter/네이티브) 통합. 선택한 패턴([01](01-generative-ui-spectrum.md))·프로토콜([02](02-protocols-ag-ui-a2ui-mcp-apps.md))·레지스트리([03](03-component-registry-schema.md))를 실제 프론트엔드 스택에 어떻게 붙이는지 — 통합 방식과 제약 중심. 제품 성능 수치·벤치마크는 다루지 않는다. 컴포넌트 구현 세부(스타일링, 상태 관리 라이브러리)도 범위 밖.
> **시각화**: [`assets/html/dynamic-ui-architecture.html`](../assets/html/dynamic-ui-architecture.html) — "렌더러(웹/모바일)" 노드

## 요약 (3줄)

1. 프론트엔드 통합의 핵심 질문은 **"컴포넌트 선택(툴 호출)을 어디서 컴포넌트 인스턴스로 바꾸는가"** 다. 클라이언트 레지스트리에서(React + AG-UI/CopilotKit), 서버에서 렌더해 UI 조각을 스트리밍(Vercel AI SDK RSC), 플랫폼 렌더러가 선언적 트리를 해석(A2UI on Flutter/Android/iOS) — 세 위치 중 하나다.
2. 웹은 선택지가 많고 성숙하며, 모바일 네이티브는 **A2UI 렌더러가 사실상 유일한 개방 선택지**이고 v0.9 `[벤더]` 단계다. 기존 앱 임베딩은 위젯(같은 DOM) vs iframe(격리)의 트레이드오프다.
3. 어떤 스택이든 **레지스트리와 이벤트 스키마를 프레임워크 코드에서 분리**해 둔다. 프레임워크·SDK가 반년 단위로 바뀌는 영역이므로, 바뀌지 않는 것(카탈로그, 계약 ②·③)을 중심에 두고 어댑터로 감싼다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** (What) | ① 플랫폼별 렌더러 선택과 통합 방식 ② 레지스트리 → 프레임워크 컴포넌트 바인딩 코드 ③ 이벤트 스트림 → 프레임워크 상태 어댑터 ④ 사용자 이벤트 → 계약 ③ 변환 ⑤ 임베딩 방식(해당 시) |
| **언제** (When) | 패턴·프로토콜·레지스트리 결정 후. 프론트엔드가 이미 정해져 있는 기존 제품에 에이전트를 넣는 경우가 대부분이므로, 실제로는 "우리 스택에서 가능한 패턴은 무엇인가"를 거꾸로 묻게 된다. 그 경우 이 페이지를 먼저 읽고 [01](01-generative-ui-spectrum.md)로 돌아간다 |
| **어떻게** (How) | ① 대상 플랫폼 열거(웹 / iOS / Android / 데스크톱 / 기존 앱 안) → ② 플랫폼별로 선택 가능한 통합 방식 확인(아래 비교표) → ③ 레지스트리 바인딩 계층 작성(카탈로그 `name` → 컴포넌트 참조) → ④ 이벤트 어댑터 작성(스트림 범주 → 프레임워크 상태) → ⑤ 사용자 이벤트 변환기 → ⑥ 폴백(텍스트) 렌더 확인 → ⑦ 접근성·보안 검증([08](08-security-sandboxing.md), [09](09-ux-accessibility.md)) |
| **왜** (Why) | 통합 계층 없이 프레임워크 API를 컴포넌트 안에서 직접 호출하면 ① SDK 버전 변경이 모든 컴포넌트에 번지고 ② 같은 카탈로그를 웹·모바일에서 재사용할 수 없으며 ③ 테스트가 프레임워크 런타임에 묶인다 |

## 문제와 맥락

에이전트 백엔드는 "컴포넌트 `ProductCard`를 props `{...}`로"라고 말한다. 이것이 화면에 그려지려면 어딘가에서 **문자열 이름이 실행 가능한 컴포넌트로** 바뀌어야 한다. 그 "어딘가"가 어디인지가 통합 방식을 가른다.

- **클라이언트 레지스트리**: 브라우저·앱이 이름 → 컴포넌트 맵을 갖고 있다. 백엔드는 데이터만 보낸다
- **서버 렌더 스트리밍**: 서버가 컴포넌트를 렌더해 UI 조각(React Server Components 류)을 보낸다. 클라이언트는 조각을 끼운다
- **플랫폼 렌더러**: 선언적 트리를 각 플랫폼의 렌더러(Flutter 위젯, Android Compose, iOS SwiftUI 등)가 해석한다. A2UI의 모델 `[벤더]`

세 방식은 번들 크기, 백엔드 결합도, 플랫폼 커버리지, 보안 경계가 다르다.

## 핵심 개념

### 통합 방식별 특성

| 방식 | 이름 → 컴포넌트 변환 위치 | 백엔드 결합 | 플랫폼 | 주요 제약 |
|---|---|---|---|---|
| **React + AG-UI 클라이언트** (CopilotKit 류 포함) | 클라이언트 레지스트리 | 느슨(이벤트 스키마만) | 웹 | 레지스트리가 번들에 포함 → 컴포넌트 수가 번들 크기 |
| **Next.js + Vercel AI SDK** (툴 → 컴포넌트) | 클라이언트 레지스트리 또는 서버 | 프레임워크 규약(같은 저장소) | 웹 | 백엔드가 Next.js(또는 호환 런타임)여야 함 |
| **Vercel AI SDK RSC 스트리밍** | 서버 렌더 | 강함(서버가 UI를 앎) | 웹 | 서버 컴포넌트 제약(클라이언트 상호작용은 클라이언트 컴포넌트로 분리), 캐싱·재연결 복잡 |
| **Flutter + A2UI 렌더러** | 플랫폼 렌더러 | 느슨(트리 스키마) | iOS·Android·웹·데스크톱 | "Basic" 세트 밖은 커스텀 위젯 등록, v0.9 변경 추적 `[벤더]` |
| **Android Jetpack / iOS + A2UI** | 플랫폼 렌더러 | 느슨 | 각 OS 네이티브 | Android Jetpack 라이브러리 제공 `[벤더]`, iOS는 렌더러 성숙도 `[실측]` 필요 |
| **기존 앱 임베딩 — 위젯** | 호스트 앱의 DOM/뷰 트리 안 | 호스트와 공유 | 웹·네이티브 | 스타일 충돌, 호스트 CSP·보안 컨텍스트 공유 |
| **기존 앱 임베딩 — iframe** | 별도 문서 | 격리 | 웹 | postMessage 브리지, 높이 동기화, 접근성 트리 분리 ([08](08-security-sandboxing.md)) |

### 레지스트리 바인딩 계층

```ts
// 카탈로그 name → 컴포넌트. 프레임워크 코드는 이 맵 뒤에 숨긴다
const registry: Record<CatalogName, ComponentBinding> = {
  ProductCard: { component: ProductCard, schema: ProductCardProps, version: "2.3.0" },
  ProductComparisonTable: { component: ComparisonTable, schema: ComparisonTableProps, version: "2.3.0" },
  ApprovalCard: { component: ApprovalCard, schema: ApprovalCardProps, version: "2.3.0", actions: ["approval", "rejection", "edit"] },
};
// 렌더 직전: 스키마 검증 → 실패 시 텍스트 폴백. 모르는 name → 텍스트 폴백
```

- `schema`는 [03](03-component-registry-schema.md)에서 생성된 것을 import한다. 손으로 쓰지 않는다
- 이름을 모르거나 버전이 메이저 불일치면 **텍스트 폴백**. 예외를 던지지 않는다
- 바인딩 계층은 프레임워크별로 하나씩(React용, Flutter용). 카탈로그는 공유

### 이벤트 어댑터

스트림 범주(생명주기 / 텍스트 / 툴 호출 / 상태, [04](04-streaming-state-sync.md)) → 프레임워크 상태 저장소로 변환하는 계층. AG-UI SDK나 CopilotKit이 이 어댑터를 제공하지만, **자체 어댑터 인터페이스로 한 번 감싼다.** SDK가 바뀌어도 컴포넌트는 모른다.

역방향(사용자 이벤트 → 계약 ③)도 같은 계층에서. 컴포넌트는 `onAction({type, payload})`만 호출하고, 봉투(`idempotency_key`, `run_id`, `client_state_seq`)는 어댑터가 채운다.

### 서버 컴포넌트 활용의 경계

RSC 류 서버 렌더 스트리밍은 "컴포넌트를 클라이언트 번들에 넣지 않아도 된다"는 장점이 있다. 하지만 에이전트 UI는 대부분 **상호작용**(승인·수정·선택)이 있으므로 그 부분은 결국 클라이언트 컴포넌트다. 실무 배치는 다음과 같다.

- 표시 전용(citation 리스트, 표, 차트의 정적 부분): 서버 렌더 가능
- 상호작용(승인 카드, 인라인 수정, 선택지): 클라이언트 컴포넌트 + 클라이언트 레지스트리
- 재연결·순서 보장([04](04-streaming-state-sync.md))은 서버 렌더 조각에도 적용되어야 하며, 프레임워크가 제공하는 범위를 확인한다

### 기존 앱에 임베딩

| 축 | 위젯(같은 문서) | iframe(격리) |
|---|---|---|
| 디자인 일관성 | 호스트 토큰 공유 가능 | 토큰을 iframe에 전달해야 함 |
| 보안 | 호스트와 같은 신뢰 경계 — 에이전트 UI 결함이 호스트에 영향 | 샌드박스로 격리. Open-ended 패턴은 **반드시** 이쪽 |
| 통신 | 함수 호출 | postMessage + 스키마 검증 |
| 접근성 | 하나의 접근성 트리 | 분리된 트리, 포커스 이동 처리 필요 |
| 적합 | 자사 Controlled 컴포넌트 | 서드파티 UI(MCP Apps), 신뢰 수준이 다른 코드 |

## 아키텍처 / 파이프라인

입력은 [03](03-component-registry-schema.md)의 카탈로그(+ 생성된 스키마), [04](04-streaming-state-sync.md)의 이벤트 스트림·사용자 이벤트 스키마, 플랫폼 목록. 처리는 플랫폼별 바인딩 계층 + 이벤트 어댑터. 출력은 렌더된 화면과 계약 ③ 이벤트. 이 단계 뒤에 [08](08-security-sandboxing.md)의 보안 검증과 [09](09-ux-accessibility.md)의 접근성 검증이 붙는다.

### 선택 가이드

- **Next.js 풀스택 단일 팀이고 웹만이라면** → Vercel AI SDK. 이유: 통합이 끝나 있다. 단 "툴 호출 = 컴포넌트" 구조와 레지스트리 분리는 유지해 AG-UI 전환 여지를 둔다
- **백엔드가 Python/.NET이고 프론트가 React라면** → CopilotKit 또는 AG-UI SDK 직접. 이유: 이벤트 프로토콜이 언어 경계를 넘는다. MS .NET SDK(2026-09-25) `[2차]`로 .NET 쪽 선택지도 생겼다
- **iOS·Android 네이티브 앱에 Declarative UI를 그려야 한다면** → A2UI 렌더러를 `[실측]` 후 채택, 그 전엔 자체 Controlled 렌더러. 이유: 개방 선택지가 A2UI뿐이지만 v0.9이고 멀티플랫폼 주장은 `[벤더]`
- **기존 포털에 서드파티 툴 UI를 넣어야 한다면** → iframe + [08](08-security-sandboxing.md) 샌드박스. 이유: 신뢰 경계가 다르다
- **판단이 어려우면** → React 클라이언트 레지스트리 + 이벤트 어댑터 인터페이스를 먼저 만들고, SDK(Vercel AI SDK 또는 CopilotKit)는 어댑터 뒤에 둔다. 이유: 어댑터만 바꾸면 SDK를 바꿀 수 있다

## 설계 시 고려사항 (체크리스트)

- [ ] 레지스트리 바인딩 계층이 프레임워크 코드와 분리되어 있는가. 컴포넌트가 SDK API를 직접 호출하지 않는가
- [ ] 바인딩의 `schema`가 [03](03-component-registry-schema.md)에서 생성된 것을 import하는가
- [ ] 모르는 컴포넌트·메이저 버전 불일치·스키마 실패가 모두 **텍스트 폴백**으로 떨어지는가(예외 아님)
- [ ] 이벤트 어댑터가 SDK를 감싸고 있어 SDK 교체 시 컴포넌트가 바뀌지 않는가
- [ ] 사용자 이벤트 봉투(`idempotency_key`, `run_id`, `client_state_seq`)를 어댑터가 채우고 컴포넌트는 `type`·`payload`만 아는가
- [ ] 서버 렌더를 쓴다면 상호작용 컴포넌트가 클라이언트 쪽에 있고 재연결·순서 보장이 적용되는가
- [ ] 모바일에서 A2UI를 쓴다면 "Basic" 세트 커버리지와 커스텀 위젯 등록 비용을 확인했는가
- [ ] 임베딩이라면 위젯/iframe 선택 근거(신뢰 경계)가 문서화되어 있는가
- [ ] 번들 크기 — 레지스트리의 컴포넌트가 지연 로딩되는가(컴포넌트 수가 수십 개일 때)
- [ ] 프레임워크·SDK 버전이 고정되어 있고 업그레이드 절차가 있는가 ([Part 5/05](../05-cross-cutting/05-llmops-agentops.md))

## 운영 설계 — 확장성 · 안정성 · 유지보수

용어·판단 기준은 [Part 1/07 운영 용어](../01-foundations/07-operations-vocabulary.md). 이 페이지의 운영 설계는 1/07 "포트와 어댑터" 원칙의 프론트엔드 적용이다 — 바인딩 계층과 이벤트 어댑터가 포트, SDK·프레임워크·플랫폼 렌더러가 어댑터다. 바뀌는 것(SDK)과 바뀌지 않는 것(카탈로그·계약 ②③)을 코드 구조로 분리해야 반년 단위 변경을 견딘다.

### 확장성 — 10배가 되면 무엇이 먼저 깨지는가

| 확장 축 | 10배 시 깨지는 것 | 설계 수단 | 비용이 비례하는 변수 |
|---|---|---|---|
| 컴포넌트 수 (번들) | 초기 로딩 크기, 레지스트리 맵 메모리 | 지연 로딩(의도 그룹별 청크), 서버 렌더는 표시 전용에만 | 컴포넌트 수 × 평균 번들 크기 |
| 플랫폼 수 (웹·iOS·Android·데스크톱·임베딩 호스트) | 바인딩 계층 수, 지원 매트릭스 행, 플랫폼별 QA | **Declarative 영역**: 렌더러 1개 추가 / **Controlled 영역**: 컴포넌트 × 플랫폼 구현. 공통 카탈로그, 플랫폼별 바인딩만 | Controlled: 컴포넌트 수 × 플랫폼 수 / Declarative: 플랫폼 수 |
| 임베딩 호스트 수 (포털·IDE·챗) | 호스트별 CSP·스타일·인증 컨텍스트 차이 | iframe 임베딩으로 호스트 독립, 호스트 설정을 매니페스트로 | 호스트 수 |
| 동시 사용자 (클라이언트) | 클라이언트 측 이벤트 처리·렌더 빈도, 재연결 폭주(배포 직후) | 재연결 지터·백오프, 델타 배치 | 동시 세션 수 |
| 테넌트별 디자인 시스템 | 토큰 번들 수, 테마 전환 비용 | 토큰은 런타임 CSS 변수(웹)/테마 객체(네이티브)로 주입, 컴포넌트 코드 공유 | 테넌트 수(토큰만) |
| SDK·프레임워크 수 (React + Flutter + .NET 백엔드 등) | 어댑터 수, 버전 매트릭스 | 어댑터 인터페이스 하나, 구현 N개, 녹화본 재생 테스트 공유 | SDK 수 × 버전 수 |

### 운영 안정성 — 장애 모드와 대응

| 장애 모드 | 사용자에게 보이는 증상 | 탐지 신호 | 자동 대응 (폴백·저하) | 사람 개입 기준 |
|---|---|---|---|---|
| **렌더 실패** (스키마 통과했으나 컴포넌트 예외·빈 화면) | 빈 영역, 깨진 레이아웃 | 클라이언트 렌더 오류 보고(컴포넌트별), 에러 바운더리 카운트 | 에러 바운더리 → **텍스트 폴백** + 폴백 고지. 예외를 상위로 전파하지 않음 | 특정 컴포넌트 실패율 예시 1% 초과 → 컴포넌트 노출 중단 플래그 |
| **미지원 컴포넌트** (플랫폼 매트릭스 밖, 모르는 `name`) | 해당 컴포넌트 자리에 텍스트 | 모르는 `name` 카운트, 플랫폼별 미지원 카운트 | 텍스트 폴백. 매핑 규칙([05](05-intent-to-ui-mapping.md))이 미리 걸렀어야 하므로 발생 자체를 기록 | 운영 중 발생 → 매트릭스 ↔ 매핑 불일치 |
| 카탈로그 버전 메이저 불일치 (배포 순서) | 모든 UI가 텍스트 | 버전 불일치 비율 | 전체 텍스트 폴백 + 새로고침 안내 배너 | 배포 창 초과 지속 → 배포 순서 절차 |
| SDK 업그레이드 후 이벤트 어댑터 불일치 | 스트림은 오는데 상태 미갱신, 카드 미표시 | 어댑터 "알 수 없는 이벤트" 카운트 | 텍스트 범주만 렌더(저하) | 배포 직후 → 어댑터 롤백 |
| 지연 로딩 청크 실패 (CDN·네트워크) | 컴포넌트 영원히 스켈레톤 | 청크 로드 타임아웃 | 타임아웃(예시 5초) 후 텍스트 폴백, 재시도 1회 | CDN 장애 |
| iframe 임베딩 로드 실패·높이 동기화 실패 | 위젯 공백 또는 잘림 | iframe load 타임아웃, postMessage 높이 메시지 부재 | 제거 + 텍스트 요약([08](08-security-sandboxing.md)) | 제공자별 |
| A2UI 렌더러 세트 불일치 (세트 버전 ≠ 트리 버전) | 트리 일부 노드 미렌더 | 렌더러 "알 수 없는 노드 타입" 카운트 | 노드 단위 생략 → 트리 전체가 의미를 잃으면 텍스트 | 세트 버전 고정 확인 |
| 접근성 런타임 검증 실패 (Declarative) | 비교표 대신 텍스트 | 검증기 불합격 카운트 | 텍스트 폴백 + 고지 | 급증 시 모델·프롬프트 변경 의심 |
| 서버 렌더(RSC) 조각 재연결 불가 | 끊긴 뒤 조각 재조립 실패 | 조각 수신 오류 | 표시 전용 조각이므로 텍스트로 저하 | 프레임워크 범위 확인 |

SLI 후보: 렌더 실패율(컴포넌트·플랫폼별), 미지원 컴포넌트 발생률, 폴백률(원인별), p95 첫 토큰 ~ 첫 컴포넌트 지연(클라이언트 측정), 청크 로드 성공률, 알 수 없는 이벤트 비율. SLO 초안(예시): 렌더 실패율 < 0.5%, 첫 컴포넌트 p95 < 3초(웹), 모르는 `name` 운영 발생 0건. 쓰기 행동 없음 — 어댑터는 봉투를 채워 전달만 하고 멱등성은 서버([04](04-streaming-state-sync.md)).

### 유지보수 — 버전·변경·호환

| 버전 관리 대상 | 바꾸면 영향받는 것 | 회귀 테스트 | 함께 배포할 것 (호환) |
|---|---|---|---|
| 프레임워크·SDK 버전 (React, Vercel AI SDK, CopilotKit, AG-UI SDK, Flutter·A2UI 렌더러) | 어댑터·바인딩 계층 | 어댑터 녹화본 재생, 컴포넌트 렌더 스냅샷 | 프론트 SDK ↔ 백 SDK(프로토콜 버전 일치) |
| 렌더러별 지원 매트릭스 | 매핑 플랫폼 규칙, 폴백 분기 | 플랫폼별 전수 렌더 | 카탈로그 버전 |
| 레지스트리 바인딩 계층 (name → 컴포넌트·schema·version) | 모든 렌더 | 카탈로그 대조(CI), 스냅샷 | **카탈로그 ↔ 바인딩 ↔ 렌더러** — 롤백 단위 |
| 이벤트 어댑터 인터페이스 | 컴포넌트 `onAction` 계약 | 인터페이스 계약 테스트 | 바뀌면 모든 컴포넌트 — 드물어야 함 |
| 디자인 토큰 바인딩 (CSS 변수·테마 객체) | 시각 | 시각 회귀(스크린샷, 테넌트별) | 토큰 세트 |
| 호스트 임베딩 매니페스트 (CSP·출처·높이 정책) | 임베딩 동작 | 호스트별 E2E | 호스트 설정 |

기술 부채로 기록할 것: 어댑터 뒤에 두지 못한 SDK 직접 호출(있다면 목록), iOS A2UI 렌더러 `[실측]` 미완 상태의 자체 렌더러 범위, 지연 로딩 미적용 컴포넌트.

### 변화 대응 — 무엇이 바뀌고, 어느 경계에서 흡수하는가

| 변화 유형 | 이 단계에서 바뀌는 것 | 안정적으로 유지할 계약 | 교체 가능한 구현 | 흡수 방식 | 전파 범위 |
|---|---|---|---|---|---|
| **SDK 메이저 업** (Vercel AI SDK, CopilotKit, AG-UI SDK, Next.js) | 어댑터·바인딩 내부 | **이벤트 어댑터 인터페이스**, `onAction({type, payload})`, 카탈로그 | SDK | 버전 고정 → 업그레이드 창 → 어댑터만 재작성 → 녹화본 재생. 컴포넌트는 변경 없음 | 어댑터 |
| **프로토콜 개정** (A2UI v0.x 세트, AG-UI) | 렌더러·어댑터 | 포트 | 렌더러·어댑터 | [02](02-protocols-ag-ui-a2ui-mcp-apps.md). 세트 개명은 바인딩 계층의 이름 매핑으로 | 어댑터·바인딩 |
| **사용자 환경** (새 플랫폼 — 모바일 네이티브 추가) | 바인딩 계층 1개 추가 | 카탈로그, 계약 ②③ | 렌더러 | **Declarative 영역**: A2UI 렌더러 추가(`[실측]` 후) / **Controlled 영역**: 컴포넌트별 네이티브 구현 + 지원 매트릭스 갱신, 미구현은 매핑에서 제외 → 텍스트 | 바인딩 + 매트릭스 |
| **사용자 환경** (새 임베딩 호스트) | 호스트 매니페스트 | iframe 브리지 스키마 | 호스트 설정 | 매니페스트 추가(데이터) | 설정 |
| **디자인 시스템 개편** | 토큰 값, 컴포넌트 스타일 | 카탈로그 스키마, 바인딩 `name` | 토큰·스타일 | 토큰 교체(런타임 주입이면 배포 없이), 시각 회귀 | 렌더러 스타일만 |
| **컴포넌트 추가·폐기** | 바인딩 항목 | 바인딩 인터페이스 | 컴포넌트 | 추가: 바인딩 + 청크 / 폐기: deprecated 기간 동안 바인딩 유지 + 대체 컴포넌트로 리다이렉트 → 제거 시 모르는 `name` 폴백 | 바인딩 |
| **다국어** | 문자열 리소스, RTL 레이아웃 | 컴포넌트 props(구조화 값) | 리소스·레이아웃 토큰 | 리소스 추가, 논리 속성(start/end) 사용으로 RTL은 코드 변경 없이 | 리소스 |
| **모델 교체** | 없음 — 프론트는 모델을 모름 | — | — | 렌더 실패율·폴백률 변화만 관찰 | — |
| **부하** | 재연결 폭주 | — | — | 지터·백오프, CDN | 인프라 |

가장 자주 바뀌는 것: **SDK·프레임워크 버전**(반년 단위 `[2차]`) > 디자인 토큰 > 컴포넌트 추가 > 플랫폼 추가(연 단위). 코드 밖 설정으로 둘 것: SDK 버전 고정, 지원 매트릭스, 토큰 세트, 호스트 매니페스트, 컴포넌트 노출 플래그. 포트·어댑터 뒤에 둘 외부 의존: 모든 SDK·프레임워크 스트리밍 API·플랫폼 렌더러. 모바일 추가 판단: Declarative 영역이 크면 A2UI 렌더러가 싸고, Controlled 영역이 크면 컴포넌트 수 × 플랫폼 수가 비용이므로 **모바일에 노출할 컴포넌트를 먼저 줄인다**.

### 관측성 — 이 단계에서 무엇을 기록·측정·알림하는가

운영 안정성의 "탐지 신호"가 **실제로 어디서 나오는지**를 설계한다. 기준은 [Part 1/07 관측성 설계 요소](../01-foundations/07-operations-vocabulary.md)와 [Part 5/03](../05-cross-cutting/03-observability-tracing.md). 이 페이지의 탐지 신호는 거의 전부 **클라이언트 보고**다 — 서버는 스키마를 통과시킨 뒤 무엇이 실제로 보였는지 모른다. 그래서 보고 경로 자체가 관측 대상이며, 브라우저·앱 환경의 특수성이 설계를 좌우한다:

- **보고 누락·지연**: 탭 닫힘·앱 백그라운드 전환에서 유실된다. `visibilitychange`·`pagehide` 시점에 `sendBeacon`류로 플러시하고, 로컬 큐 + 재전송을 둔다. 늦게 도착한 보고의 지연은 수신 시각이 아니라 **클라이언트 단조 시계의 상대값**으로 계산한다
- **광고 차단·오프라인**: 수집 엔드포인트가 차단되면 수집률이 브라우저·플랫폼별로 **체계적으로** 낮아진다. 보고는 자사 도메인 same-origin 경로로 보내고, 수집률을 분모 보정 SLI로 둔다. 수집률이 떨어진 구간의 렌더 실패율 알림은 "데이터 부족"으로 전환([10](10-evaluation-genui.md))
- **샘플링은 턴 단위**: 성공 렌더만 샘플링(예시 10%)하되 결정은 서버가 스트림 첫 이벤트에 실어 보낸다 — 클라이언트가 따로 정하면 같은 턴의 서버 스팬은 있는데 클라이언트 스팬이 없는 트레이스가 생긴다. 실패·폴백·승인 카드·`degradation[]` 고지 표시는 샘플링을 무시하고 전수
- **개인정보**: 클라이언트 보고에 props 값·입력값·URL 쿼리·DOM 텍스트를 넣지 않는다. 컴포넌트명·버전·결과·지연·해시만. 오류는 예외 클래스 + 스택 해시(메시지에 PII가 섞인다). 사용자 식별은 세션 토큰 해시

| 기록 대상 | 스팬 / 이벤트 (이름, 부모) | 핵심 속성 (버전 키 포함) | 지표 (→ 어느 SLI) | 샘플링 · 보존 · PII |
|---|---|---|---|---|
| 렌더 결과 | 클라이언트 `ui.render {component}` (부모: 서버 `ui.stream` — 스트림 첫 이벤트로 받은 W3C Trace Context를 전파) | `agent.component`·버전, `agent.render_result`(ok / error / fallback / skipped), `agent.fallback_reason`(`unknown_name` / `unsupported_platform` / `catalog_major_mismatch` / `render_exception` / `chunk_timeout` / `a11y_failed` / `unknown_node`), `agent.platform`, `agent.renderer_version`, SDK 버전, `agent.catalog_version_client`, 첫 컴포넌트 ms | 렌더 실패율(컴포넌트·플랫폼별), 폴백률(원인별), 미지원 발생률, p95 첫 컴포넌트 지연(클라이언트 측정) | 성공 샘플, 실패·폴백 전수. 렌더 트리 본문 없음 |
| 에러 바운더리 | 이벤트 `ui.render.error` (부모 `ui.render`) | 예외 클래스, 스택 해시, 컴포넌트 | 에러 바운더리 카운트 | 전수. 스택 원문은 별도 오류 추적 저장소 참조 |
| 어댑터·렌더러 | `ui.stream.unknown_event`([02](02-protocols-ag-ui-a2ui-mcp-apps.md)), `ui.render.unknown_node`(A2UI 세트), `ui.render.chunk_load` | 세트 버전, 노드 타입 원문(길이 제한), 청크 ID, 로드 ms, 재시도 | 알 수 없는 이벤트·노드 비율, 청크 로드 성공률 | 전수 |
| iframe·RSC 조각 | `ui.render {iframe}` + `ui.bridge.*`([08](08-security-sandboxing.md)), `ui.render {rsc_fragment}` | 로드 ms, 높이 메시지 수신 여부, 조각 수신 오류 | iframe 로드 성공률, 높이 동기화 실패율, 조각 오류율 | 실패 전수 |
| 보고 경로 자체 | 클라이언트 이벤트 `ui.report.flush` + 서버 `ui.map` 발행 수 | 배치 크기, 재시도, 로컬 큐 드롭 수, `agent.report_blocked` 추정 플래그, `agent.platform` | **렌더 보고 수집률** = 클라이언트 `ui.render` 보고 수 / 서버 `ui.map` 발행 수(플랫폼·브라우저별) | 전수 |

| 알림 | 조건 (예시) | 심각도 | 런북 (첫 3단계) |
|---|---|---|---|
| 렌더 실패율 | 컴포넌트별 > 예시 1%, 10분 — 수집률 ≥ 예시 80%일 때만 평가 | **P1** | ① 컴포넌트 × 플랫폼 × 렌더러 버전 분해 ② 배포 마커 ③ 컴포넌트 노출 중단 플래그 |
| 메이저 불일치 지속 | [03](03-component-registry-schema.md)과 동일(배포 창 초과) | **P1** | 배포 순서 런북 |
| 알 수 없는 이벤트·노드 | 비율 > 예시 0.1%, 5분 | P2 | ① SDK·세트 버전 ② 녹화본 재생 ③ 어댑터 롤백 |
| 청크·iframe 로드 | 성공률 < 예시 98%, 10분 | P2 | ① CDN·제공자 분리 ② 지역·네트워크 분해 ③ 재시도 / 제거 저하 동작 확인 |
| 수집률 하락 | 플랫폼별 < 예시 80%, 30분 | P2 (탐지 실명) | ① 보고 엔드포인트 가용성 ② 클라이언트 릴리스·차단 플래그 비율 ③ 다른 알림을 "데이터 부족" 모드로 |

**대시보드에서 이 단계를 보는 뷰**: ① E2E의 첫 컴포넌트 지연·폴백율 / ② Interaction 패널의 "컴포넌트 × 플랫폼 렌더 실패율·수집률".
**감사 추적으로 넘기는 필드(관측 로그와 분리)**: 렌더된 `name`·`version`, 플랫폼·렌더러·SDK 버전, 렌더 결과·원인 — 그중 승인 카드와 `degradation[]` 고지의 렌더 보고는 감사 레코드로 승격(샘플링 불가).
**이 단계의 관측이 없으면 못 보는 장애**: 렌더 실패 자체. 스키마를 통과한 응답은 서버에서 전부 성공이고, 클라이언트 보고 없이 "빈 화면"은 어떤 지표에도 없다 — 그리고 보고가 차단된 플랫폼에서는 실패율이 0으로 보인다.

### 거버넌스 접점 — 정책 · 가드레일 · 승인 · 감사

| 항목 | 이 단계에서의 답 |
|---|---|
| 위험 등급 (1~5) | 렌더는 등급 1. 승인 카드 렌더는 행동 등급을 상속하되 렌더 실패 시의 대응이 [06](06-hitl-ui-patterns.md)에 종속(텍스트 폴백 금지). iframe 임베딩은 샌드박스 전제 |
| 가드레일 위치 | **출력**: 렌더 직전 스키마 검증(바인딩 계층) + 접근성 런타임 검증(Declarative). **행동**: 없음 — 어댑터는 봉투를 채울 뿐, 재검증은 서버 |
| 게이트 출력과 판정 수단 | 렌더(통과) / 텍스트 폴백(저하) / 생략(모르는 노드). 규칙만 |
| 소유자 (A) | 바인딩·어댑터·SDK 버전: 프론트엔드 아키텍트. 플랫폼 렌더러 채택(`[실측]` 판정): 프론트엔드 + 모바일 리드. 토큰: 디자인 책임자 |
| 감사 추적에 남길 필드 | **클라이언트 보고**: 렌더된 컴포넌트 `name`·`version`, 플랫폼·렌더러 버전, 렌더 결과(성공/실패/폴백·원인), SDK·어댑터 버전. 서버는 이 보고 없이는 "무엇이 실제로 보였는지" 모른다 |

### 운영 준비도 체크
- [ ] 컴포넌트가 SDK API를 직접 호출하는 곳이 0개인가(어댑터 인터페이스 뒤)
- [ ] 모르는 `name`·메이저 불일치·스키마 실패·렌더 예외가 모두 텍스트 폴백으로 떨어지고 고지되는가
- [ ] 클라이언트가 렌더 결과(성공·실패·폴백·버전)를 서버에 보고하는가
- [ ] 지원 매트릭스가 매핑 규칙과 같은 원본을 참조하는가
- [ ] SDK 버전이 고정돼 있고 어댑터 녹화본 재생 테스트가 CI에 있는가
- [ ] 컴포넌트 단위 노출 중단 플래그가 배포 없이 동작하는가
- [ ] 디자인 토큰이 런타임 주입이라 개편 시 컴포넌트 코드가 바뀌지 않는가
- [ ] 모바일 추가 시 "Declarative면 렌더러, Controlled면 컴포넌트별" 판단이 문서로 있는가
- [ ] 클라이언트 보고가 턴 단위 샘플링·실패 전수·백그라운드 플러시·PII 금지 규칙을 따르는가
- [ ] 플랫폼별 렌더 보고 수집률이 SLI이고 하락 시 렌더 실패율 알림이 "데이터 부족"으로 바뀌는가
