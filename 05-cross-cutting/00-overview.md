# Part 5. Cross-cutting — 횡단 관심사

> 세 레이어 모두에 걸치는 관심사. Part 2~4의 각 페이지에도 해당 항목이 있지만, 여기서는 **레이어를 가로질러 일관되게** 적용해야 하는 정책을 다룬다.

## 이 Part의 역할

| 질문 | 답 |
|---|---|
| **무엇을** | 보안(특히 프롬프트 인젝션), 비용·지연·모델 라우팅, 관측성, 거버넌스·설명가능성, 운영(LLMOps/AgentOps) |
| **언제** | Part 2~4의 설계가 1차로 나온 직후. 각 레이어 설계를 끝낸 뒤 횡단 검토를 한 번 더 한다 |
| **어떻게** | 각 페이지의 체크리스트를 Part 2~4의 선택에 대입 → 충돌하는 지점 수정 → 운영 지표 정의 |
| **왜** | 레이어별로 최적화하면 "검색은 싸고 빠른데 생성이 비싸다", "UI는 안전한데 툴 결과는 검증 안 한다" 같은 불균형이 생긴다 |
