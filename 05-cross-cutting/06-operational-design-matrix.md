# 운영 설계 종합 매트릭스

> **범위**: Part 2·3·4 모든 단계 페이지(34개)의 "운영 설계" 섹션을 한 장으로 모아, 레이어 간 불균형(어느 단계는 폴백이 있는데 어느 단계는 없음, fail 방향이 단계마다 다름, 한 레이어의 SLO를 다른 레이어가 받지 않음)을 찾는다. 용어는 [Part 1/07](../01-foundations/07-operations-vocabulary.md). 셀은 한 줄 요약이며 상세·수치는 각 페이지가 원본이다. 이 페이지와 페이지가 어긋나면 **페이지를 따른다**.

## 요약 (3줄)

1. 34단계를 다섯 관점(확장성·안정성·유지보수·변화 대응·거버넌스)으로 나란히 놓으면 **각 페이지가 혼자서는 옳은데 레이어를 건너면 어긋나는 지점**이 보인다. 이 페이지의 산출물은 매트릭스가 아니라 그 아래 "불균형 탐지 결과"다.
2. 세 레이어의 공통 패턴은 뚜렷하다. Knowledge는 **지식 변화를 2/07 하나로 수렴**하고, Reasoning은 **규칙·θ를 코드 밖 설정으로**, Interaction은 **SDK를 어댑터로** 흡수한다. 보안·권한·한도 게이트는 34단계 모두 "규칙만"이고 등급 5는 모두 "자동 실행 금지"다 — 여기는 일관되다.
3. 어긋나는 곳은 **레이어 경계를 넘는 신호**다. 삭제 전파 SLO, 캐시 TTL과 권한 회수, 저하 플래그의 표시 끝점, 승인 시한의 단일 소스, 평가 파이프라인 다운 시 배포 게이트, 임계값 자동 조정 방향 — 이 여섯이 2026-10 기준 가장 큰 불일치다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜
| 질문 | 답 |
|---|---|
| **무엇을** (What) | ① 단계 × 관점 매트릭스 5장 ② 변화 유형 × 레이어 교차표("변화가 어디서 멈추는가") ③ 불균형 목록과 수정 제안 ④ 공통 SLO 초안 ⑤ 통합 ORR 체크리스트 |
| **언제** (When) | 각 Part의 운영 설계 섹션이 1차로 채워진 뒤, 그리고 **분기마다**(규칙·모델·SDK가 바뀌면 불균형도 바뀐다). 단계 하나만 설계 중이면 이 페이지가 아니라 그 페이지의 운영 설계 섹션을 본다 |
| **어떻게** (How) | ① 매트릭스에서 같은 열을 세로로 읽는다(예: fail 방향 열) → ② 레이어 경계를 넘는 행(캐시·메모리·승인·삭제·저하 플래그)에서 끝점이 있는지 본다 → ③ 불일치는 "어느 페이지를 기준으로 맞출지"를 1/07 정의로 판정 → ④ 대상 페이지에 수정 제안을 남긴다 → ⑤ 공통 SLO·ORR을 갱신 |
| **왜** (Why) | 레이어별 운영 설계는 각자 완결적일 수 있다. 그러나 삭제가 인덱스에서는 15분 안에 빠지는데 시맨틱 캐시에는 남아 있으면 사용자에게는 "삭제되지 않은 것"이다. 불균형은 단계 페이지 안에서는 보이지 않고 **옆에 놓아야만** 보인다 |
## 문제와 맥락

각 Part의 `99-decision-matrix.md` "운영 설계 요약" 표는 Part 안의 10~14단계를 비교한다. 그러나 운영 사고의 전형은 Part 안이 아니라 **Part 사이**에서 난다 — Knowledge가 톰스톤을 15분 안에 전파했는데 Reasoning의 결과 캐시가 그 문서를 인용한 답을 계속 돌려주는 경우, Reasoning이 `retrieval_mode=keyword_only` 저하 플래그를 냈는데 Interaction에 그것을 표시할 컴포넌트가 없는 경우, 승인 시한이 3/12 매트릭스·4/06 타임아웃·3/08 체크포인트 TTL 세 곳에 따로 적혀 있는 경우. 이 페이지는 세 Part의 요약 표를 하나로 합치고, 거기에 1/07의 "변화 유형별 흡수 지점" 표를 겹쳐 레이어 간 경계를 검사한다.

### 매트릭스 2: 단계 × 운영 안정성 — 죽으면 어떻게 보이는가

fail 방향: **closed** = 확인 못 하면 멈춤·거부·제외, open = 저하 상태를 표시하고 계속.

| 단계 | 대표 장애 모드 | 사용자에게 보이는 증상 | 핵심 폴백·저하 | fail 방향 | SLI 후보 |
|---|---|---|---|---|---|
| 2/01 | 소스·커넥터 다운, 수집 문서 속 인젝션 | 새 문서 미반영 | 커넥터별 서킷 격리, 격리 큐, `suspect_injection` 플래그 | open(격리하고 계속) | 수집 지연 p95, 파싱 성공률 |
| 2/02 | 상류 구조 누락, 접두 LLM 다운 | 색인 지연 | 재귀 분할 폴백, 접두 없이 색인 후 배치 보강 | open | 토큰 한도 준수율, 오프셋 유효율 |
| 2/03 | 저장소 다운, 복제 지연 | 신규 색인 중단, 삭제·권한 회수 지연 | 인덱싱 중단, 렌더 전 원천 재확인 | **closed**(인덱싱) | 필수 필드 완전성, 복제 지연 p95 |
| 2/04 | 임베딩 API 다운, 벡터DB 지연 | 의미 검색 불가 | BM25 단독(`keyword_only`), 파라미터 하향, 모델 불일치 쓰기 거부 | open(표시) / closed(필터 불가) | recall@k, 검색 p95 |
| 2/05 | 추출 LLM·그래프 저장소 다운 | 멀티홉 실패·지연 | 그래프 경로 킬 스위치 → 벡터 단독, 위반 트리플 버킷 | open(벡터 단독) | SHACL 통과율, 그래프 신선도 지연 |

| 2/07 | 큐 다운, 삭제 미전파(유령) | 신선도 지연, 삭제 문서 인용 | 커서 보존 + 대조 재투입, 톰스톤 카나리 실패 시 인덱스 차단 | closed(카나리 실패) | 반영 지연, **삭제 전파 p95**, 유령 수 |
| 2/08 | 메타데이터·ACL 다운 | 필수 필드 미충족 | 근거 제외, 0건이면 답하지 않음 | **closed** | citation 완전성 100%, locator 유효율 |
| 2/09 | 판정 API 다운, 보정 드리프트 | 미분류 쏠림 | 지점별 보수적 기본값(`method=fallback`), 2차 수단 | closed(보수적 기본값) | 검토 비율, ECE, 정밀도 |
| 2/10 | 권한 서비스 다운, 게이트웨이 우회 | 거부 또는 `public`만 | TTL 캐시 후 거부, 카나리 실패 시 킬 스위치 | **closed**(fail-open 금지) | 노출 불일치 0, 카나리 100% |

| 3/02 | 라우터·변환 LLM 다운 | 전부 지연, 맥락 소실 | 규칙 기본 경로(`fallback=true`), 규칙 재작성 | open(기본 경로) | 라우팅 정확도, 폴백 비율 |
| 3/03 | 리랭커 타임아웃, ACL 서비스 다운 | 무관 청크, 유출 위험 | RRF 그대로·단일 인덱스 / ACL은 abstain | open(검색) / **closed**(ACL) | 검색 p95, ACL 적용률 100% |
| 3/04 | 생성 API·검증기 다운 | 응답 없음, 미검증 위험 | 폴백 모델 → 근거 목록만; 등급 1은 규칙 검증만 + 미검증 플래그 | 등급 1 open / 등급 2+ closed | faithfulness, 스키마 실패율 |
| 3/05 | 무한 루프, 체크포인트 다운 | 응답 없음, 재개 불가 | 상한 종료·워크플로우 폴백(킬 스위치), 장기 과업 접수 거부 | closed(장기 과업) | 호출 수 p95, 상한 도달률 |
| 3/06 | 스텝 상한, 툴 오류, 판정 다운 | 응답 없음, 결과 지어냄 | 구조화 오류를 관찰로 주입, 툴 목록에서 제거, 안전 종료 | closed(안전 종료) | 성공률, 상한 도달률 |
| 3/07 | 순환 위임, 핸드오프 실패 | 종료 불능, 의도 유실 | 단일 에이전트 폴백, 원 에이전트 복귀 | open(단일 폴백) | 핸드오프 실패율, 상관 유실 |
| 3/08 | 체크포인트 저장소 장애, 메모리 오염 | 과업 중단, 엉뚱한 선호 | 새 전이 중단, 에피소드 메모리 킬 스위치, 메모리 없이 진행 | closed(상태 없이 진행 안 함) | 쓰기 성공률, 재개 성공률 |

| 3/10 | 검증기 오탐 폭증·다운 | 정당 출력 거부, 행동 중단 | 규칙 세트 자동 롤백(보안·권한·한도 제외), 행동 노드 차단 | 행동 closed / 텍스트(등급 1) open | 검증 실패율, 오탐률 |
| 3/11 | 결정 모델 다운, 보정 드리프트, 벤더 무통보 변경 | 승인·명확화 급증 | 규칙 → 캐시 → 보수적 경로, θ 보수적 이동, 이전 구현체 전환 | closed(승인 필요 쪽) | 가용성, 폴백율, ECE |
| 3/12 | 승인 적체, 승인자 부재, 정책 엔진 다운 | 과업 정지, 행동 중단 | 백프레셔, 만료 = 거부, 행동 게이트 전부 차단 + 읽기 전용 | **closed** | 승인 응답 p95, 만료율, 엔진 가용성 |

| 4/03 | 스키마 실패 폭증, 버전 불일치 | 텍스트만 | 텍스트 폴백, 컴포넌트 노출 중단 플래그 | open(텍스트) | 스키마 실패율, 대조 실패 0 |

세로로 읽으면: **보안·권한·승인·쓰기**가 걸린 곳(2/03·2/08·2/10·3/03 ACL·3/09·3/12·4/04·4/06·4/08)은 전부 closed로 일치한다. open인 곳은 읽기 전용 표시 경로(2/04·3/01·3/02·4/02·4/03·4/07)이며, 모두 "저하 상태를 응답에 표시"를 전제한다 — 그 표시의 끝점이 Interaction에 있는지가 불균형 ④다.

단계 SLI는 각 페이지가 갖는다. 아래는 **레이어 경계를 넘어 한 요청·한 이벤트를 끝까지 재는** E2E SLI이며, 값은 전부 **예시**(베이스라인 측정 후 재설정, 1/07 "SLO를 측정 없이 선언" 리스크)다.

|---|---|---|---|---|

```
                                             불균형 목록 ─▶ 대상 페이지 수정 제안 ─▶ 공통 SLO·ORR 갱신 ─▶ 분기 리뷰([04](04-governance-explainability.md))
```

## 기술 비교표 — 매트릭스를 유지하는 방법
| 기술 / 접근 | 적합한 상황 | 부적합한 상황 | 비용·복잡도 | 성숙도 | 검증 수준 |
|---|---|---|---|---|---|
| 수동 마크다운 표 (이 페이지 현재 방식) | 단계 수 ≤ 40, 분기 1회 갱신, 사람이 읽고 판단하는 용도 | 페이지가 자주 바뀌어 표가 금방 낡음, 셀 ↔ 페이지 불일치를 못 잡음 | 하 (갱신 노동) | 표준 | — |
| 페이지 프론트매터에 운영 메타데이터(`ops: {fail_mode, risk_grade, owner, change_absorber}`)를 두고 스크립트로 생성 | 페이지와 매트릭스의 불일치를 CI에서 검출, 세로 읽기(열 필터) 자동화 | 프론트매터 어휘를 먼저 합의해야 함, 서술형 셀(폴백 설명)은 생성 불가 | 중 (스키마 + 생성기) | 안정(패턴) | `[2차]` 문서 생성 일반 관행 |
| Part별 99 매트릭스만 유지하고 이 페이지는 링크 허브로 | 교차 검토를 Part 담당자가 각자 하는 조직 | 레이어 **간** 불균형이 보이지 않음(이 페이지의 존재 이유 상실) | 하 | 표준 | — |
| 외부 서비스 카탈로그·운영 대시보드에 단계를 서비스로 등록 | 운영 조직이 이미 서비스 카탈로그를 쓰고 SLO·소유자·런북을 거기서 관리 | 단계 ≠ 서비스(한 서비스에 여러 단계), 문서와 카탈로그 이중 관리 | 중~상 | 안정 | `[2차]` |
### 선택 가이드

- **페이지가 월 1회 이상 바뀐다면** → 프론트매터 + 생성. 이유: 수동 표는 한 달이면 어긋난다
- **분기 리뷰 1회가 전부라면** → 수동 표 + 리뷰 체크리스트. 이유: 생성기 비용이 갱신 노동보다 크다
- **판단이 어려우면** → 기본값: 수동 표를 유지하되 fail 방향·위험 등급·소유자 세 열만 프론트매터로 옮겨 CI가 대조. 이유: 불균형의 대부분이 이 세 열에서 나온다

## 설계 시 고려사항 (체크리스트) — 운영 준비도 리뷰(ORR) 통합 항목

세 레이어 공통. 단계별 항목은 각 페이지의 "운영 준비도 체크"에 있고, 아래는 **레이어 경계**를 검사한다.

- [ ] 모든 행동이 1/07 위험 등급표에 놓였고, 등급 5는 코드 구조상 자동 실행이 불가능한가
- [ ] 보안·권한·한도·멱등 게이트가 전부 **규칙만**으로 판정되고 모델 판정으로 우회할 수 없는가
- [ ] 외부 의존(모델·결정 모델·벡터DB·그래프DB·MCP 서버·정책 엔진·ACL 서비스·체크포인트 저장소)마다 독립 서킷 브레이커와 사전 결정된 fail 방향이 있는가
- [ ] fail-open인 경로는 모두 등급 1이고, 저하 플래그가 Interaction 끝점(고지·variant)까지 도달하는가
- [ ] 삭제·권한 회수 이벤트의 소비자에 인덱스뿐 아니라 결과·시맨틱 캐시, 메모리, 트레이스 본문, 골든셋이 등록되어 있는가
- [ ] 결과·시맨틱 캐시 키에 테넌트·인덱스 버전·프롬프트 버전·주체 집합(또는 TTL ≤ 주체 해석 TTL)이 포함되는가
- [ ] 승인 시한의 단일 소스(3/12 매트릭스)가 있고, 체크포인트 TTL·멱등 키 TTL ≥ 최대 승인 시한인가
- [ ] 승인 매트릭스에 개인 이름이 없고, 에스컬레이션 끝 = 만료 = 거부이며, 승인 카드 미표시 시 실행이 멈추는가
- [ ] 임계값(θ) 자동 이동은 보수적 방향만이고, 완화는 사람 결정 + 사후 감사로 기록되는가
- [ ] 쓰기 툴은 모두 멱등 키가 있고, 없는 툴은 재시도 금지 래퍼 또는 배포 불가인가
- [ ] 버전 관리 대상 5종(+규칙·온톨로지)이 모든 트레이스·감사 레코드에 기록되어 시점 재현이 가능한가
- [ ] 레이어를 넘는 롤백 단위 세 개(citation 스키마 ↔ 응답 스키마 ↔ 렌더러 / 승인 이벤트 스키마 ↔ 계약 ③ ↔ 상태 머신 / 임베딩 모델 ↔ 질의 임베딩)가 릴리스 번들에서 함께 바뀌는가
- [ ] 프롬프트·규칙·질문 정의·θ·카탈로그·매핑 테이블·승인 매트릭스·정책 테이블이 코드 밖 설정으로 버전·시행일과 함께 있는가
- [ ] 외부 프로토콜·SDK(MCP·A2A·AG-UI·A2UI·프레임워크)가 전부 포트 뒤 어댑터이고 버전 고정 + 업그레이드 창이 달력에 있는가
- [ ] 프레임워크 hooks 미실행 시에도 툴 실행 포트에서 행동 게이트가 재평가되는가
- [ ] 평가 파이프라인 다운 시 배포 게이트 규칙(등급 1~2 축소 통과 / 3 이상 불가)이 세 레이어에서 같은가
- [ ] 섀도·평가·A/B 환경에서 쓰기 툴은 모의, 승인 이벤트는 실제 큐로 가지 않으며, 등급 3 이상 UI는 실험에서 제외되는가
- [ ] 감사 레코드가 관측 로그와 저장소·보존을 분리하고, 샘플링 없이 규칙 버전·승인 카드 내용·주체 집합 해시를 담는가
- [ ] 공통 SLO 표의 E2E SLI마다 소유 레이어(A)와 런북이 있고, 단계 SLI가 그 구성 요소로 등록되어 있는가
- [ ] 사람 처리량 큐(검토·승인·제공자 리뷰) 네 곳에 길이 상한·백프레셔·피로 알림이 있는가
