# 폐쇄망·망분리 환경에서의 설계: 배포 환경이 바꾸는 단계별 선택

> **범위**: 외부 인터넷과 단절되거나 제한된 환경(폐쇄망, 망분리, 망연계 게이트웨이 경유)에서 에이전트 시스템을 설계할 때 **어느 단계의 어느 선택이 어떻게 바뀌는지**. 배포 환경은 위키의 결정 변수 중 하나이며([0/00 한 페이지 종합](../00-overview/00-design-considerations.md) 2절, [0/02 결정 트리](../00-overview/02-decision-guide.md)), 이 페이지는 그 변수가 "폐쇄망"일 때의 전개다. 특정 국가·산업의 망분리 규제 조항은 다루지 않는다(법무·보안 검토 사항).

## 요약 (3줄)

1. 폐쇄망은 **"외부 API를 쓸 수 없다"가 아니라 "모든 것을 반입·자체 운영·자체 검증해야 한다"** 는 조건이다. 모델, 임베딩, 파서, 벡터DB, 관측 스택, 평가 judge, 프론트엔드 자산, 패키지까지 전부 내부에 있어야 하고, 갱신은 **반입 절차**를 거친다.
2. 가장 큰 설계 변화는 **모델 능력의 하향**이다. 외부 최상위 모델 대신 반입 가능한 오픈 모델을 쓰게 되므로, 위키의 원칙 "판정과 생성을 분리하고 가장 단순한 수단을 쓴다"가 선택이 아니라 **생존 조건**이 된다. 규칙·분류기·검증기의 비중이 커지고, 결정 모델 SaaS(Jev, Decisions API)는 쓸 수 없다.
3. 변화 대응·관측성·거버넌스는 더 쉬워지는 면(데이터 반출 없음, 벤더 묵시 업데이트 없음)과 더 어려워지는 면(모델·규칙·패키지 갱신이 느리고 수동, 외부 벤치마크·커뮤니티 지원 단절)이 공존한다. **반입 주기와 호환 매트릭스**가 운영의 중심이 된다.

## 이 단계에서 무엇을 · 언제 · 어떻게 · 왜

| 질문 | 답 |
|---|---|
| **무엇을** | 배포 환경 등급 판정, 단계별 선택 변경표, 반입 가능한 구성 요소 목록(BOM), 반입·갱신 절차, 외부 의존 0 검증 |
| **언제** | 시나리오 작성 직후, 어떤 기술도 고르기 전. 배포 환경은 **나중에 바꿀 수 없는 변수**다. 퍼블릭 전제로 설계한 뒤 폐쇄망으로 옮기면 모델·임베딩·관측 스택을 전부 다시 고른다 |
| **어떻게** | ① 배포 환경 등급(0~3) 판정 → ② 이 페이지의 단계별 표에서 바뀌는 기본값 적용 → ③ 반입 BOM 작성(모델 가중치, 패키지, 컨테이너 이미지, 프론트 자산, 평가셋) → ④ 반입·갱신 절차와 주기 확정 → ⑤ 외부 의존 0 검증을 CI·ORR에 → ⑥ 모델 하향에 맞춰 판정 수단을 규칙·분류기 쪽으로 재배치 |
| **왜** | 폐쇄망에서 실패하는 프로젝트의 전형은 "PoC는 외부 API로 했는데 운영은 폐쇄망"이다. 모델이 바뀌면 프롬프트·구조화 출력·판정 정확도·비용 구조가 전부 바뀌고, PoC 결과는 아무것도 보장하지 않는다 |

## 문제와 맥락

금융·공공·국방·의료·제조 현장의 상당수가 망분리 또는 폐쇄망 정책 아래 있다. 에이전트 시스템은 전통 소프트웨어보다 **외부 의존이 훨씬 많다**. 모델 API, 임베딩 API, 클라우드 OCR, 매니지드 벡터DB, SaaS 관측 도구, 결정 모델 API, CDN에서 받는 프론트 라이브러리, 패키지 저장소, 모델 허브. 퍼블릭 환경에서는 이것들이 "선택지"지만 폐쇄망에서는 **대부분이 사라지거나 반입 대상**이 된다.

흔한 실패:

- 외부 최상위 모델로 PoC를 통과시킨 뒤 폐쇄망의 소형 오픈 모델로 옮겼더니 구조화 출력 실패율이 급증하고 라우팅 정확도가 떨어졌다
- 임베딩 API를 쓰다 자체 임베딩 모델로 바꾸면서 전체 재임베딩을 했는데, 한국어 품질이 크게 달라 골든셋 recall이 무너졌다
- 관측 스택을 SaaS로 전제해 트레이스가 없는 상태로 운영에 들어갔다
- 모델 가중치 반입에 보안 검토 6주가 걸려, "모델 교체 → 골든셋 회귀 → 카나리" 절차가 분기 1회로 늘어났다
- 프론트엔드가 CDN 폰트·아이콘·차트 라이브러리를 참조해 폐쇄망에서 렌더가 깨졌다

## 핵심 개념

### 배포 환경 등급

폐쇄망은 이분법이 아니다. 네 등급으로 나누고, 등급마다 바뀌는 것이 다르다.

| 등급 | 환경 | 외부 모델 API | 패키지·모델 반입 | 관측·평가 | 대표 상황 |
|---|---|---|---|---|---|
| **0 퍼블릭** | 인터넷 직접 연결 | 가능 | 자유 | SaaS 가능 | 일반 SaaS·스타트업 |
| **1 프라이빗 클라우드 / VPC** | 전용망, 승인된 외부 엔드포인트만 | 승인된 벤더 엔드포인트(프라이빗 링크)만 | 사내 미러 경유 | 자체 또는 승인 SaaS | 대기업 클라우드, 데이터 반출 제한 |
| **2 망연계** | 내부망 + 게이트웨이(망연계 솔루션)로 제한된 외부 통신 | 원칙 불가. 예외 승인 시 게이트웨이 경유, 지연·용량 제약 | 반입 심사 후 게이트웨이로 | 자체 운영 필수 | 금융·공공의 업무망 |
| **3 완전 폐쇄망** | 물리적 단절 | 불가 | 매체 반입 + 보안 검토 | 자체 운영 필수 | 국방, 핵심 인프라, 일부 제조 |

이 페이지의 "폐쇄망"은 등급 2~3을 뜻한다. 등급 1은 퍼블릭 설계에 **데이터 반출 통제**를 더한 것이라 변화가 작다.

### 폐쇄망이 바꾸는 다섯 가지 전제

| 전제 | 퍼블릭 | 폐쇄망 (등급 2~3) | 설계 함의 |
|---|---|---|---|
| **모델 능력** | 벤더 최상위 모델, 분기마다 개선 | 반입 가능한 오픈 모델, GPU 용량에 맞는 크기, 갱신은 반입 주기 | 판정은 규칙·분류기로, 생성은 짧고 구조화되게. 모델 능력에 기대는 설계(긴 추론 체인, 자유 생성 UI) 회피 |
| **외부 서비스** | 임베딩·OCR·벡터DB·관측·결정 모델 API | 전부 자체 운영 | 운영 팀 역량·GPU·스토리지가 설계 제약. 구성 요소 수를 줄인다 |
| **갱신 속도** | 즉시 | 반입 심사(주~월 단위), 매체 반입 | 호환 매트릭스·롤백 단위가 더 중요. 한 번 반입에 "모델 + 프롬프트 + 평가셋"을 묶는다 |
| **데이터 경계** | 반출 통제가 설계 과제 | 반출 자체가 불가능해 통제가 단순 | 보안 설계의 초점이 반출 → **내부 권한·감사**로 이동 |
| **외부 지식** | 모델 웹 검색, 외부 API, 최신 벤치마크 | 내부 데이터만. 벤치마크·커뮤니티 해법 접근 제한 | 자체 골든셋·자체 벤치마크 필수. 조사 노트의 `[벤더]`·`[2차]` 수치는 더욱 의미 없음 |

### 모델 하향이 설계 전체에 미치는 영향

폐쇄망의 핵심 변수는 **어떤 크기의 모델을 어떤 GPU에서 돌릴 수 있는가**다. 모델이 작아지면:

- **구조화 출력**: 스키마 보장 모드가 없을 수 있다 → 자체 서빙에서 **제약 디코딩**(grammar)을 켠다([1/01](../01-foundations/01-llm-fundamentals.md)). 폐쇄망에서는 이것이 오히려 장점이다(100% 스키마 준수)
- **판정**: 소형 모델의 라우팅·분류 정확도가 낮다 → **파인튜닝 분류기**(라벨 데이터 확보 가능) 또는 **규칙**이 1순위. 결정 모델 SaaS는 불가. 이 위키의 System 1/2 분리([1/02](../01-foundations/02-system1-vs-system2.md))가 비용 최적화가 아니라 **품질 확보 수단**이 된다
- **생성**: 긴 컨텍스트·복잡 추론이 약하다 → 검색 k를 줄이고 리랭킹·압축으로 **컨텍스트 품질**을 올린다. Agentic RAG의 다단계 루프보다 **Advanced RAG의 결정론적 파이프라인**이 안정적
- **검증**: LLM-as-judge의 신뢰도가 낮다 → **규칙·NLI 소형 모델·사람 샘플링** 비중 상승. 뉴로심볼릭 검증기([1/04](../01-foundations/04-neuro-symbolic-ai.md))가 더 중요
- **UI**: 의도→UI 매핑을 LLM 툴 호출에 맡기면 오선택이 는다 → **규칙·분류기 매핑** + 닫힌 카탈로그. Open-ended는 완전히 배제

즉 폐쇄망 설계는 위키의 "가장 단순한 형태에서 시작, 판정과 생성 분리, 근거는 강제하고 검증" 원칙을 **극단으로 밀어붙인 것**이다.

### 반입 BOM과 갱신 절차

폐쇄망에서는 **무엇을 반입해야 하는지의 목록**(Bill of Materials)이 설계 산출물이다.

| 반입 대상 | 포함 | 갱신 주기(예시) | 검토 항목 |
|---|---|---|---|
| 모델 가중치 | LLM(생성·판정용 티어별), 임베딩, 리랭커, NLI, 분류기, OCR/VLM | 분기 | 라이선스, 출처 해시, 악성 코드(pickle 등), 한국어 평가셋 통과 |
| 서빙 런타임 | 추론 서버, 제약 디코딩 엔진 | 반기 | 취약점, GPU 드라이버 호환 |
| 패키지·이미지 | 파서, 프레임워크, 벡터DB, 그래프DB, 정책 엔진, 관측 스택 컨테이너 | 월~분기 | SBOM, CVE, 라이선스 |
| 프론트엔드 자산 | 폰트, 아이콘, 차트·UI 라이브러리, 렌더러 SDK | 반기 | CDN 참조 0 검증 |
| 지식 | 외부 문서·표준·온톨로지(schema.org 등) 스냅샷 | 필요 시 | 저작권, 버전 |
| 평가 자산 | 공개 벤치마크 스냅샷, 자체 골든셋 | 분기 | — |

갱신 절차는 **"반입 묶음 = 롤백 단위"** 로 설계한다. 모델만 바꾸면 프롬프트·구조화 출력·판정 임계값이 흔들리므로, 한 번의 반입에 모델 + 호환 프롬프트 + 재측정 평가셋 + 임계값을 함께 넣고, 반입 전 **외부 스테이징(등급 1 환경)에서 전체 회귀**를 돌린 결과를 첨부한다. 상세: [5/05 LLMOps](05-llmops-agentops.md).

### 외부 의존 0 검증

폐쇄망에서 가장 흔한 운영 장애는 **몰랐던 외부 호출**이다. 설계·CI·ORR에 다음을 넣는다.

- 빌드 시: 패키지 lock 파일의 모든 소스가 사내 미러인지, 프론트 번들에 외부 URL(CDN·폰트·분석 스크립트)이 없는지 정적 검사
- 런타임: 아웃바운드 네트워크를 기본 차단하고, 시도 자체를 알림(`agent.outbound_attempt` 이벤트, P1)
- 모델 서빙: 토크나이저·모델 로더가 허브에 접속하지 않도록 오프라인 모드 강제
- 관측: 트레이스 익스포터가 내부 수집기만 가리키는지

## 아키텍처 / 파이프라인

```
[외부 스테이징: 등급 1]                      ‖ 반입 게이트 ‖        [폐쇄망 운영: 등급 2~3]
모델 후보 평가 → 한국어 골든셋 회귀 →        ‖ 보안 검토   ‖   서빙(제약 디코딩) ─ 판정(규칙·분류기) ─ 검색(자체 임베딩·벡터DB)
프롬프트·임계값 호환 매트릭스 → 반입 묶음 생성 ‖ 해시·SBOM  ‖   ─ 생성 ─ 검증기(규칙·NLI) ─ 게이트 ─ UI(Controlled, 내부 자산)
                                              ‖ 매체/게이트웨이‖   관측 스택(자체 OTel 수집기·저장소) · 감사 저장소 · 평가 파이프라인(내부 judge)
                                                                  아웃바운드 기본 차단 + 시도 알림
```

## 단계별 선택 변경표 — 폐쇄망(등급 2~3)에서 바뀌는 기본값

열 "퍼블릭 기본값"은 각 Part 99 매트릭스의 값, "폐쇄망 기본값"이 이 페이지의 제안이다. 바뀌지 않는 단계는 표에서 뺐다.

### Knowledge ([Part 2](../02-data-pipeline/00-overview.md))

| 단계 | 퍼블릭 기본값 | 폐쇄망 기본값 | 이유·주의 |
|---|---|---|---|

### 선택 가이드

- **등급 3이라면** → 완전 자체 운영 + 소형 모델·규칙 중심 + 외부 스테이징 이중 환경. 이유: 선택지가 없고, 스테이징 없이는 갱신 회귀를 돌릴 곳이 없다
- **등급 2이고 특정 과업만 고품질이 필요하다면** → 망연계 예외 호출을 **비식별 가능한 과업에 한정**해 검토. 이유: 전체를 외부 모델에 걸면 망연계가 병목이 되고 규제 리스크가 커진다
- **라벨 데이터를 만들 수 있다면** → 판정은 전부 파인튜닝 분류기로. 이유: 폐쇄망은 내부 데이터가 풍부해 분류기가 유리하고, 결정 모델 SaaS는 불가
- **판단이 어려우면** → Advanced RAG + 분류기 라우팅 + 제약 디코딩 + Controlled UI + 자체 OTel. 이유: 모델 하향에 가장 둔감한 조합

## 설계 시 고려사항 (체크리스트)

- [ ] 배포 환경 등급(0~3)을 시나리오 1절에 적었고, PoC 환경과 운영 환경이 같은 등급인가 (다르면 PoC 결과를 신뢰하지 않는다)
- [ ] 반입 BOM이 있는가 (모델·런타임·패키지·이미지·프론트 자산·외부 지식·평가 자산)
- [ ] 반입 가능한 모델로 **한국어 골든셋**을 돌렸는가. 임베딩·리랭커·NLI·분류기 각각
- [ ] 판정 지점 목록에서 결정 모델 SaaS를 전제한 곳이 없는가. 전부 분류기·규칙으로 대체됐는가
- [ ] 구조화 출력이 제약 디코딩으로 보장되는가
- [ ] 외부 의존 0 검증이 빌드·런타임·서빙·관측 네 층에 있는가. 아웃바운드 시도 알림이 P1인가
- [ ] 관측 스택·감사 저장소·평가 파이프라인이 내부에 있고 설계 초기에 포함됐는가
- [ ] 반입 묶음 = 롤백 단위이고, 외부 스테이징 회귀 결과가 반입 서류에 포함되는가
- [ ] GPU 용량 계획(피크 동시성, 배치 창, 재임베딩 창)이 있고 백프레셔가 설계됐는가
- [ ] 외부 문서·온톨로지의 신선도 SLO가 반입 주기와 일치하는가
- [ ] 공급망 무결성(가중치 해시, SBOM, 라이선스)이 반입 심사 항목인가
- [ ] 레이어 간 정합성: Knowledge는 자체 임베딩인데 Reasoning 평가가 외부 judge를 전제하지 않는가

## 한계와 리스크

| 한계 | 영향 | 완화책 |
|---|---|---|
| 모델 능력 격차가 계속 벌어짐 | 퍼블릭 대비 품질 열위가 고착 | 판정·검증을 모델 밖으로 최대한 빼는 설계, 반입 주기 단축 협상 |
| 오픈 모델 한국어 품질 편차 | 임베딩·생성 모두 영어 대비 열위 가능 | 반입 전 한국어 골든셋 필수, 한국어 특화 오픈 모델 후보 포함 |
| 반입 심사 지연 | 보안 패치·모델 교체가 분기 단위 | 반입 묶음 최소화, 긴급 반입 경로(break-glass) 사전 합의 |
| 운영 인력·GPU 비용 | 구성 요소마다 운영 책임 | 구성 요소 수 최소화, 매니지드 대체 불가 항목만 반입 |
| 외부 벤치마크·커뮤니티 단절 | 문제 해결·비교 정보 부족 | 자체 벤치마크, 외부 스테이징에서 조사 |
| "폐쇄망이라 안전" 오해 | 내부 권한·감사 소홀 | 위험 등급표·감사 추적은 동일하게 적용 |
| 망연계 예외 호출의 규제 리스크 | 비식별 실패 시 반출 사고 | 비식별 검증을 규칙 게이트로, 호출 건별 감사 |
| 이 페이지의 규제 서술 부재 | 국가·산업별 조항은 미반영 | 법무·보안 검토 사항으로 명시. 조항·시행일은 쓰지 않음 |

## 운영 설계 — 확장성 · 안정성 · 유지보수

이 페이지는 횡단 변수이므로 단계별 운영 설계는 각 단계 페이지의 소절에 있다. 폐쇄망에서 **추가로** 달라지는 것만 적는다.

### 확장성
GPU가 고정비이자 상한이다. 10배가 되면 토큰 비용이 아니라 **큐 대기**가 는다. 배치(인덱싱·재임베딩·컴파일)와 온라인(질의)의 GPU 풀을 분리하고, 온라인 피크에 배치를 양보하는 스케줄, 백프레셔(큐 상한·거부 응답)를 둔다.

### 운영 안정성

| 장애 모드 | 증상 | 탐지 신호 | 자동 대응 | 사람 개입 |
|---|---|---|---|---|
| 모델 서빙 노드 다운 | 전체 응답 불가(폴백 모델도 내부) | 서빙 헬스체크, 큐 적체 | 소형 티어로 저하, 규칙 경로만 유지 | 즉시(P1). 예비 GPU 노드 |
| 반입 묶음 호환 깨짐 | 배포 후 구조화 출력·라우팅 정확도 급락 | 골든셋 회귀(내부), 스키마 실패율 | 반입 묶음 단위 롤백 | 반입 전 스테이징 회귀 미실시 원인 분석 |
| 몰랐던 외부 호출 | 특정 기능 타임아웃·실패 | `agent.outbound_attempt` 이벤트 | 해당 경로 차단 유지(기본 차단) | P1. 의존 제거 후 재배포 |
| 평가 judge 신뢰도 저하 | 지표는 좋은데 사용자 불만 | judge-사람 일치율 하락 | 사람 평가 비율 상향 | 분기 보정 |
| 외부 문서 신선도 초과 | 오래된 법령·표준 인용 | 반입 주기 대비 경과일 | `stale` 플래그·고지 | 긴급 반입 |

SLI 후보: 서빙 가용성, 큐 대기 p95, 외부 호출 시도 0, 반입 묶음 회귀 통과율, 외부 문서 경과일.

### 유지보수 · 변화 대응
가장 자주 바뀌는 것은 **규칙·분류기 라벨·내부 지식**이고(반입 불필요, 내부에서 갱신), 가장 느린 것은 **모델·패키지**(반입 주기)다. 따라서 변화를 **반입이 필요 없는 쪽으로 밀어 넣는 설계**가 핵심이다. 프롬프트·규칙·임계값·카탈로그·온톨로지는 코드·모델과 분리된 설정으로 두어 반입 없이 갱신한다. 반입이 필요한 것은 묶음으로, 호환 매트릭스와 함께.

### 관측성
자체 OTel 수집기·저장소. 추가 스팬·이벤트: `agent.outbound_attempt`(P1), `serving.queue_wait_ms`, `import.bundle_version`(모든 스팬의 버전 키에 반입 묶음 ID 추가). 대시보드 ③에 GPU 사용률·큐 깊이 패널.

### 거버넌스 접점
반입 심사가 모델 리스크 관리의 공식 단계가 된다. 모델 카드에 반입 일자·출처 해시·검토자·한국어 평가 결과. 망연계 예외 호출은 **건별 감사 + 비식별 규칙 게이트**. 위험 등급표는 퍼블릭과 동일하게 적용(폐쇄망이 등급을 낮추지 않는다).

### 운영 준비도 체크
- [ ] 외부 의존 0 검증 통과(빌드·런타임·서빙·관측)
- [ ] 반입 BOM과 묶음 버전이 트레이스 버전 키에 포함
- [ ] 예비 GPU·소형 티어 저하 경로 시험 완료
- [ ] 외부 스테이징 회귀 결과가 반입 서류에 첨부
- [ ] 내부 judge-사람 일치율 측정 완료
