# 뉴로심볼릭 ★

> **범위**: 최근 1년 뉴로심볼릭 동향과 기업 적용 사례

> **한 줄 정의**: 신경망(LLM)의 생성·인식 능력과 기호 체계(규칙·온톨로지·제약 솔버·프로그램 실행)의 검증·추론 능력을 결합하는 **뉴로심볼릭 AI(Neuro-Symbolic AI, NSAI)**. 최근 1년에는 연구 범주가 아니라 "LLM 출력을 기호 검증기로 걸러 운영에 넣는 2단계 구성"이라는 **기업 적용 패턴**으로 재조명되었다.
> **레이더 위치**: **시험** — 검증기·변환기 패턴은 이미 많은 운영 시스템이 쓰고 있어 실질은 "채택"에 가깝다. 그러나 "뉴로심볼릭"이라는 이름으로 묶인 주장(Gartner NSAI 벤더 식별, 산업 적용 사례)은 `[벤더]`이고, 결합 시스템 전체의 검증 방법론이 미성숙하다는 `[검증]`된 결론이 있어 범주 전체는 "시험"에 둔다.

## 무엇이 바뀌었나 (최근 1년)

| 시점 | 사건 | 검증 수준 |
|---|---|---|
| 2024 (기반) | Renkhoff et al., IEEE TAI, 뉴로심볼릭 V&V 서베이(arXiv 2401.03188): 신경·기호 부분을 **따로** 검증하는 기법은 부분적으로 충분, **결합 전체**는 미성숙 | `[검증]` |
| 2026-02 | arXiv **2602.00731**: 예지보전(predictive maintenance) 분야 뉴로심볼릭 리뷰. 산업 도메인별 리뷰가 나올 만큼 적용 사례가 축적 | `[검증]` |
| 2026-03 | arXiv 2604.00555: 온톨로지 제약 신경 추론 아키텍처, 스스로 neural[symbolic]로 분류 | `[검증-단일저자, 독립 재현 없음]` |
| 2026-04 | Gartner 보고서가 NSAI 벤더를 식별했다는 벤더 전언 | `[벤더]` |
| 2026-06 | Franz Inc. 발표가 위 Gartner 식별을 인용하며 지식그래프를 NSAI 시맨틱 레이어로 포지셔닝 | `[벤더]` |
| 2026 | o9 Solutions, Kognitos 등이 "엔터프라이즈 뉴로심볼릭"을 표방 ([Part 1/04](../01-foundations/04-neuro-symbolic-ai.md) 참고 문헌) | `[벤더]` |

바뀐 것은 기술이 아니라 **명명과 범위**다. 구조화 출력 + JSON Schema 검증, Text-to-SQL + 실행, 규칙 엔진 게이트는 2024년부터 흔한 구성이었다. 2026년에는 이것들이 "뉴로심볼릭"이라는 이름 아래 하나의 범주로 묶였고, 시장 조사 회사와 벤더가 그 범주에 이름표를 달았다. 분류 체계(Kautz)와 네 가지 실무 패턴은 [Part 1/04](../01-foundations/04-neuro-symbolic-ai.md)가 기반 지식으로 다룬다.

## 왜 주목받나

LLM을 운영에 넣은 조직이 공통으로 부딪힌 문제가 있다: **생성물이 그럴듯하지만 틀릴 때 누가 잡는가.** 사람 전수 검토는 비용이 맞지 않고, LLM-as-judge는 같은 종류의 오류를 공유한다. 기호 검증기는 다음 성질 때문에 세 번째 답이 된다.

- **결정론적**: 같은 입력에 같은 판정. 재현·감사 가능
- **설명 가능**: "필수 속성 누락", "한도 초과"처럼 거부 사유가 구조화되어 나온다
- **독립적 오류 모드**: LLM이 틀리는 방식과 다르게 틀리므로 결합 시 보완

여기에 두 가지 외부 요인이 겹쳤다. ① **구조화 출력의 보편화**로 검증기 패턴의 진입 장벽이 사라졌다(스키마 보장 모드가 1차 검증을 사실상 공짜로) `[벤더]`. ② **거버넌스 압력**이 "모델이 그렇게 판단했다" 이상의 근거를 요구한다 ([Part 5/04](../05-cross-cutting/04-governance-explainability.md)). 뉴로심볼릭은 이 둘에 동시에 답하는 서사로 채택되었다.

## 핵심 메커니즘

[Part 1/04](../01-foundations/04-neuro-symbolic-ai.md)의 네 패턴(검증기 · 변환기 · 접지 · 게이트)이 메커니즘이다. 여기서는 **2026년 기업 적용 서사에서 어느 패턴이 중심인지**만 짚는다.

| 패턴 | 2026 기업 적용에서의 위상 | 전형적 기호 체계 | 비고 |
|---|---|---|---|
| **검증기 (Generate → Verify)** | **중심**. "엔터프라이즈 뉴로심볼릭"이라 불리는 것의 대부분 | JSON Schema → SHACL → 규칙 엔진 | 벤더 자료가 설명하는 것은 거의 이 패턴 `[벤더]` |
| 변환기 (Translate → Execute) | 안정. Text-to-SQL/Cypher로 이미 보편화되어 따로 "뉴로심볼릭"이라 부르지 않는 경우가 많음 | DB·쿼리 엔진 | 실행 오류가 곧 검증 |
| 접지 (Ground → Generate) | 상승. [ontology-renaissance](ontology-renaissance.md)와 결합 | 온톨로지·지식그래프 | 2604.00555의 주장 영역 |
| 게이트 (Rule ∧ Model) | 상승. 행동하는 에이전트가 늘며 "최종 허가는 규칙"이 기본 설계로 | 정책 엔진(OPA 등), 코드 | 결정 모델과 결합 시 "확신 낮음 → 사람"까지 처리 ([decision-models](decision-models.md)) |

**검증기 패턴의 핵심 루프**: LLM 생성 → 기호 검증 → (불합격) 구조화된 오류를 LLM에 되돌려 재생성(self-correction) 또는 폴백 → (합격) 다음 단계. 재생성 루프의 비용·지연 상한과 "스키마는 맞지만 의미가 틀린" 출력에 대한 2차 검증([Part 3/04](../03-agent-workflow-rag/04-generation-grounding.md))이 설계의 요점이다.

## 한계와 미해결 질문

| 한계 / 질문 | 왜 문제인가 | 현재 상태 |
|---|---|---|
| **결합 전체의 V&V 미성숙** | 신경 부분과 기호 부분을 따로 검증해도 결합 시스템의 실패 모드(검증기가 통과시킨 의미 오류, 재생성 루프의 수렴 실패)는 다른 문제 | Renkhoff 서베이 결론 `[검증]`. E2E 골든셋 외 방법론 없음 |
| **마케팅화** | 벤더가 단순 규칙 필터를 NSAI로 포장. 범주의 변별력이 떨어짐 | 패턴·기호 체계를 구체적으로 묻는 것으로 대응 |
| **기호 체계 유지 비용** | 규칙·온톨로지가 현실과 어긋나면 올바른 출력을 거부 | 거부 로그 리뷰, 소유자 지정 |
| **규칙 폭발** | 규칙 수백 개 시 우선순위·모순 관리 불가 | 규칙 엔진 + 규칙 테스트 스위트 |
| **재생성 루프 비용** | 검증 실패가 잦으면 요청당 LLM 호출이 배수로 | 실패 패턴을 프롬프트·스키마에 반영, 상한 설정 |

| 결정 모델과의 결합 | 게이트 패턴의 "모델" 자리를 결정 모델이 맡을 때 보정 확률 + 규칙의 설계 | 사례 미확인 `[2차]` |

## 우리 프로젝트에서의 채택 기준

검증기·변환기 패턴은 이미 운영에 들어가 있을 가능성이 높으므로, "채택"의 대상은 패턴 자체가 아니라 **"뉴로심볼릭 구성이 품질을 개선했다"는 주장**이다. 다음이 `[실측]`되어야 한다.

1. **검증기 효과 `[실측]`**: 검증기 없이 / 있이 두 구성에서 골든셋의 최종 정답률·유해 출력률을 비교한다. 검증기가 걸러낸 것의 정밀도(실제 오류 비율)와 재현율(놓친 오류 비율, 샘플링 사람 리뷰)을 측정한다.
2. **거부율과 비용 `[실측]`**: 검증기 거부율, 재생성 횟수 분포, 요청당 추가 지연·토큰. 거부율이 높으면서 정밀도가 낮다면 기호 체계가 현실과 어긋난 것이다.
3. **의미 오류 누출률 `[실측]`**: 스키마·규칙을 통과했지만 틀린 출력의 비율을 샘플링으로 측정한다. 이것이 Renkhoff 서베이가 말하는 "결합 전체" 실패 모드의 우리 수치다.
4. **E2E 골든셋 상시 운영**: 단계별 검증기 지표가 아니라 과업 완료율을 최상위 지표로 두고, 검증기 변경마다 재측정한다 ([Part 1/06](../01-foundations/06-evaluation-observability.md)).
5. **패턴 명세**: 우리 시스템의 각 검증 지점이 네 패턴 중 무엇이고 어떤 기호 체계를 쓰는지 문서화되어 있다. "뉴로심볼릭을 썼다"가 아니라 "이 지점은 SHACL 검증기, 저 지점은 OPA 게이트"로 말할 수 있어야 한다.
6. **벤더 플랫폼 도입 시**: 위 1~3을 벤더 플랫폼에 대해서도 동일하게 측정한다. 벤더 사례 수치는 `[벤더]`로 남긴다.
