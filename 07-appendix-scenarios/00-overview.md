# Part 7. Appendix — 시나리오 기반 설계 예시

> 위키 본문이 "선택지와 기준"이라면 이 부록은 **"적용 예시"** 다. 구체적 상황을 주고, 데이터 파이프라인 → 에이전트 구성 → Generative UI까지 **각 단계에서 무엇을 왜 선택했는지** 단계별로 보여준다. 프로젝트 착수 시 가장 가까운 시나리오를 골라 차이점만 수정하는 식으로 쓴다.

## 이 Part의 역할

| 질문 | 답 |
|---|---|
| **무엇을** | 서로 다른 요구 프로파일을 가진 시나리오 3개의 End-to-End 설계와, 각 선택의 근거 페이지 링크 |
| **언제** | 결정 트리를 돌렸는데도 조합이 머릿속에 그려지지 않을 때. 또는 설계 리뷰에서 "왜 이 조합인가"를 설명해야 할 때 |
| **어떻게** | [시나리오 템플릿](../_templates/scenario.md)을 따른다. 상황 설정 → 결정 변수 추출 → 단계별 선택/대안/이유/근거 → 전체 아키텍처(HTML) → 진행 순서 → 평가 → 한계 |
| **왜** | 기술 비교표는 "일반적으로 A가 B보다 낫다"를 말하지만, 실제 선택은 변수들의 조합에서 나온다. 조합을 보여줘야 가이드가 된다 |

## 시나리오 세 개를 고른 기준

세 시나리오는 **세 레이어의 비중**과 **트렌드 세 축의 역할**이 서로 다르도록 골랐다.

| 시나리오 | 주된 레이어 | 데이터 특성 | 자율성 | UI 통제 수준 | 트렌드 축의 역할 |
|---|---|---|---|---|---|
| [A. 사내 문서 QA 어시스턴트](01-enterprise-document-qa.md) | **Knowledge** 중심 | 비정형 문서 多, 권한 복잡, 갱신 느림 | 낮음(워크플로우형 RAG) | Controlled, citation 렌더 중심 | 온톨로지: 부서·문서 유형 택소노미 / 뉴로심볼릭: 근거-답변 정합성 검증 / 결정 모델: 문서 분류·질의 라우팅 |
| [B. 커머스 상담 + Generative UI](02-commerce-assistant-genui.md) | **Interaction** 중심 | 정형 상품 데이터 + 리뷰, 갱신 빠름 | 중간(툴 호출 에이전트) | Controlled → 일부 Declarative | 온톨로지: 상품 온톨로지 → 컴포넌트 매핑 / 결정 모델: 의도→UI 선택 / 뉴로심볼릭: 추천 제약(재고·정책) 검증 |
| [C. 운영 인시던트 대응 에이전트](03-ops-incident-agent.md) | **Reasoning/Action** 중심 | 로그·메트릭 스트림 + 런북, 실시간 | 높음(멀티 에이전트, 툴 실행) | HITL 승인 UI 중심 | 결정 모델: 심각도·승인 필요 게이팅 / 뉴로심볼릭: 런북 규칙 + LLM 진단 / 온톨로지: 서비스 의존성 그래프 |

## 각 시나리오가 답하는 공통 질문

1. 근거 단위는 무엇인가 (청크 / 트리플 / 레코드)
2. 어디까지 워크플로우로 고정하고 어디부터 모델에 맡기나
3. 어떤 판정을 결정 모델·규칙에 맡기고 어떤 것을 LLM에 맡기나
4. 사용자는 결과를 읽나, 조작하나, 승인하나
5. 실패하면 어떻게 보이고 누가 개입하나
6. 무엇을 측정해서 "잘 된다"고 판단하나
