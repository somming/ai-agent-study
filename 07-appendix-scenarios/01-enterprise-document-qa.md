# 시나리오 A: 사내 문서 QA 어시스턴트

> **범위**: 데이터 파이프라인 → RAG → 근거 표시 UI까지 End-to-End 구성 예시
> **시각화**: [`assets/html/scenario-document-qa.html`](../assets/html/scenario-document-qa.html)
> **성격**: [Part 7 개요](00-overview.md)의 비교표대로 **Knowledge 중심**, 자율성 낮음(워크플로우형 RAG), UI는 Controlled·citation 렌더 중심. 세 시나리오 중 가장 단순하며, "사용자가 읽기만 하는" 시스템의 기준선이다.

## 1. 상황 설정

가상 조직이다. 아래 규모 수치는 모두 **설계 가정**이며, 실측값이 아니라 "이 정도 규모면 어떤 선택이 달라지는가"를 보여 주기 위한 값이다.

| 항목 | 내용 |
|---|---|
| 업무 도메인 | 임직원 약 4,000명 규모의 제조 기업. 사내 규정·지침, 업무 매뉴얼, 회의록, 계약서·협약서, 감사 보고서를 대상으로 한 질의응답 |
| 사용자 | 전 임직원이 잠재 사용자. 주 사용자는 경영지원·인사·법무·구매 담당자와 현장 관리자. 하루 수백 명, 동시 사용 수십 명 수준(설계 가정). 사용자는 **답을 읽고 원문을 확인**하며, 시스템을 통해 무언가를 실행하지 않는다 |
| 데이터 | **유형**: 비정형 문서가 대부분(PDF·오피스 문서·위키 페이지), 일부 메일·채팅 발췌. 스캔 문서는 소수. **규모**: 문서 수십만 건, 청크로는 수백만 건(설계 가정). **갱신**: 하루 수십~수백 건 신규·개정, 규정은 연 수회 개정되어 **개정 이력이 쌓인다**. **언어**: 한국어 중심, 계약·기술 문서는 한·영 혼합. **권한**: 부서별 ACL + 기밀 등급 3단계(공개·부서 한정·임원 한정), 그룹 중첩이 깊다 |
| 핵심 요구 | **정확도**: 업무 지원 등급 — 틀리면 사용자가 수정할 수 있지만 수정 비용이 있다. **근거**: 모든 사실 주장에 citation 필수, 원문 위치 하이라이트, "어느 개정판 기준인지" 표시. **지연**: 대화형(수 초 이내). **규제**: 외부 규제 대상은 아니지만 내부 감사가 "권한 밖 문서가 답에 섞이지 않았는가"를 점검한다 |
| 제약 | **팀**: 백엔드 2, 데이터 1, 프론트 1, PM 1의 단일 팀. RDF·온톨로지 경험 없음, PostgreSQL 운영 경험 있음. **예산**: 중간 — 인덱싱에 LLM을 전수 적용할 예산은 없음. **기존 시스템**: 사내 포털(React), 문서 저장소·위키·그룹웨어, 사내 ID 제공자(그룹 정보 제공). 외부 LLM API 호출은 허용하되 **임원 한정 등급 문서는 반출 불가** |

## 2. 요구사항 → 결정 변수 추출

[종합 결정 트리](../00-overview/02-decision-guide.md)의 입력 변수 V1~V15에 값을 채우고, 질문 Q1~Q15를 돌린 경로를 적는다.

| # | 변수 | 이 시나리오의 값 | 움직이는 선택 |
|---|---|---|---|
| V1 | 데이터 유형 | 비정형 문서 多, 반정형(메일·채팅) 소수, 멀티모달 거의 없음 | 레이아웃 파서, 청크가 근거 단위 |
| V2 | 규모·갱신 빈도 | 문서 수십만 / 갱신 일 단위 / 트래픽 소량 | pgvector 류, 증분 배치 |
| V3 | 지연 요구 | 응답 대화형(<5s), 신선도 시간~일 | 리랭커 허용, CDC 불필요 |
| V4 | 정확도·근거 요구 | 업무 지원, **citation 필수** | 문장 하이라이트, 후검증 |
| V5 | 규제·감사 | 내부 감사(권한 밖 근거 점검), 문서별 ACL·PII 있음 | bitemporal, 사전 필터, 감사 리포트 |
| V6 | 멀티홉·동일성·설명 | **미측정** — 단일 문서 사실 조회가 대부분으로 추정 | 그래프 미도입, 택소노미만 |
| V7 | 과업 예측 가능성 | 고정 절차(질의 → 검색 → 답변) | 워크플로우 |
| V8 | 실패 비용 | 업무 지원(수정 비용) | 승인 불필요, 사후 샘플링 |
| V9 | 행동 유무 | 읽기 전용 툴 1~2개, 부수효과 0 | 네이티브 함수 |
| V10 | 사용자 행위 | **읽기 + 근거 확인** | Part 4 대부분 불필요 |
| V11 | 플랫폼 | 웹(사내 포털 임베딩) | 내장 스트리밍, 위젯 |
| V12 | 조직 경계 | 단일 팀·단일 스택 | 멀티 에이전트·MCP·A2A 불필요 |
| V13 | 팀 역량 | PostgreSQL 운영 있음, RDF 없음, Python·TS | pgvector, 택소노미, 경량 프레임워크 |
| V14 | 예산·반출·종속 | 인덱싱 예산 제한, 외부 API 허용(임원 등급 문서는 불허), 벤더 종속 허용 | contextual 보류, 반출 불가 등급은 자체 호스팅 경로 |
| V15 | 언어 | 한·영 혼합 | 형태소 BM25, 임베딩 2종 `[실측]`, 결정 모델 한국어 평가셋 |

**질문 트리 경로**: Q1 읽기만 → **예**(Knowledge + Reasoning, citation 렌더만, 계약 ②③은 정의) · Q2 행동 → **아니오** · Q3 정형 중심 → **아니오**(청크 근거 단위, 레이아웃 파서) · Q4 분 단위 SLO → **아니오**(증분 배치) · Q5 citation 필수 → **예**(bitemporal, 근거 문장, 후검증) · Q6 멀티홉 `[실측]` → **아니오**(택소노미만, Advanced RAG) · Q7 ACL·PII → **예**(사전 필터 + 재확인 + 마스킹) · Q8 예측 가능 → **예**(라우팅 워크플로우) · Q9 당사자 둘 이상 → **아니오**(네이티브 함수, 단일 에이전트) · Q10 결정 모델 한국어 `[실측]` → **아니오**(규칙 + 소형 LLM/분류기, `decide()` 먼저, 결정 모델은 섀도) · Q11 쓰기 툴 또는 LLM 추출 적재 → **아니오**(3/10은 규칙 게이트 수준, 단 Q5의 후검증은 유지) · Q12 멀티세션 → **아니오**(no-memory) · Q13~14 건너뜀(단 citation 렌더를 위해 4/06·4/07 최소 선택) · Q15 벤더 종속 → **예**(경량·직접 구현, 밖 모듈 먼저).

## 3. 단계별 설계 결정

각 행의 "선택 이유"는 해당 페이지의 선택 가이드 조건을 인용한다. 선택은 세 결정 매트릭스의 시나리오 A 행과 일치시켰다.

### 3.1 데이터 파이프라인 (Part 2)

| 단계 | 선택 | 고려한 대안 | 선택 이유 | 근거 페이지 |
|---|---|---|---|---|
| 수집·파싱 | 직접 구현 커넥터(문서 저장소·위키·그룹웨어) + Docling 류 레이아웃 파서, 메일·채팅은 경량 파서, 실패분 격리 큐 | 매니지드 커넥터; 벤더 OCR 전면 | 2/01 선택 가이드: "텍스트 PDF·오피스 문서가 대부분이고 로컬 실행이 필요하다면 → Docling 류 기본 + 실패분만 벤더 OCR". 표 복원·좌표가 하류 하이라이트의 전제. 소스가 3~4종이라 매니지드 커넥터의 이득이 작다 | [2/01](../02-data-pipeline/01-source-ingestion.md) |
| 청킹 | 문서 구조 기반(제목 계층) + 재귀 보정 + parent-child. 맥락 보강 없음, 출처 혼동이 측정되면 contextual 접두 추가 | late chunking; 처음부터 contextual | 2/02 선택 가이드: "문서에 제목 계층이 있다면 → 구조 기반 + parent-child"와 기본값 "맥락 보강 없음, 출처 혼동이 보이면 contextual". 규정·매뉴얼은 제목 계층이 뚜렷하고, 인덱싱 예산이 제한적 | [2/02](../02-data-pipeline/02-chunking-strategies.md) |
| 메타데이터·출처 | 다섯 축 필수 필드 + 별도 저장소 + 불변 버전(`is_current`) + PROV 어휘, **규정·계약은 bitemporal**(기록 시점 + 유효 시점), `superseded_by` | 평면 메타데이터 | 2/03 선택 가이드: "권한이 있거나 운영 서비스라면 → 구조화 스키마 + 별도 저장소 + 불변 버전", "규정·계약처럼 시점이 중요하다면 → bitemporal". "그 시점 기준 답"을 요구받는다 | [2/03](../02-data-pipeline/03-metadata-provenance.md) |
| 임베딩·인덱싱 | hybrid(BM25 + dense + RRF), 한국어 형태소 분석기, pgvector 류(기존 PostgreSQL), 임베딩 모델 2종 `[실측]` 후 확정, 버전 고정 | 전용 벡터DB; 기존 검색엔진 | 2/04 선택 가이드: "데이터가 수백만 건 이하이고 PostgreSQL을 운영 중이라면 → pgvector 류 + 애플리케이션 RRF. ACL 조인을 SQL로 처리". 한·영 혼합·사내 고유명사라 sparse 병행 필수 | [2/04](../02-data-pipeline/04-embedding-indexing.md) |
| 지식그래프 | **초기 미도입**. 질의 로그에서 조직·프로젝트 관계 질의(멀티홉)가 유의미한 비율로 확인되면 경량 그래프 검토 | LightRAG 식 그래프 즉시 도입 | 2/05 선택 가이드: "멀티홉·동일성 질문이 질의 로그에서 확인되지 않는다면 → 그래프를 올리지 않는다". 인덱싱 비용만 들고 벡터 대비 이득이 없다 `[2차]` 실무자 합의 | [2/05](../02-data-pipeline/05-knowledge-graph-construction.md) |
| 온톨로지 | **택소노미(SKOS)만**: 문서 유형 × 부서 × 기밀 등급 × 주제. 정식 온톨로지 보류 | 경량 온톨로지(클래스 ≤ 30) | 2/06 선택 가이드: "그래프도 없고 필터가 평면 분류로 충분하다면 → 택소노미만. 온톨로지 유지 비용을 정당화할 질문이 없다". 팀에 RDF 경험이 없고, 택소노미만으로 필터 어휘·분류 enum·기밀 정책이 코드화된다 | [2/06](../02-data-pipeline/06-ontology-driven-modeling.md) |
| 근거 데이터 설계 | **하이브리드(청크 검색 + 문장 검증·렌더)**, 코드 규칙 신뢰도 등급(소스 택소노미 기반), 개정 상충은 `superseded_by`·유효 시점으로 결정론 해소 — **계약 ①** | 청크 단위 + 최소 필드; 트리플 추가 | 2/08 선택 가이드: "업무 지원 이상이고 UI에 근거 하이라이트가 있다면 → 하이브리드. 검증기와 UI 계약을 동시에 만족하는 최소 구성". 트리플은 그래프 도입 시 추가 | [2/08](../02-data-pipeline/08-grounding-data-design.md) |
| 동기화 | 증분 배치(시간 단위) + 톰스톤 + 주 1회 전체 대조 + 정확 중복 제거·정본 규칙 + 블루/그린 | CDC + 변경 큐 | 2/07 선택 가이드: "소스가 문서 저장소·위키이고 SLO가 시간 단위라면 → 증분 배치 + 주 1회 전체 대조", "복사본이 많다면 → 정확 중복 제거 + 정본 규칙" | [2/07](../02-data-pipeline/07-freshness-and-sync.md) |
| 파이프라인 내부 AI | 문서 유형·기밀 등급은 규칙 → **한국어 소형 분류기**(LLM 초기 라벨 → 사람 검수 → 증류), 효력일·개정 번호 추출은 규칙 + 소형 LLM, 결정 모델은 **섀도 모드 비교군** | 결정 모델 즉시 채택; 대형 LLM 전수 | 2/09 선택 가이드: "라벨이 수천 건 있고 카테고리가 고정이라면 → 한국어 소형 분류기", 기본값 "결정 모델은 비교군으로 평가". 임원 등급 문서는 외부 API 반출 불가이므로 자체 호스팅 분류기가 필수 조건 | [2/09](../02-data-pipeline/09-ai-inside-the-pipeline.md) |
| 접근 제어 | 메타데이터 **사전 필터**(그룹 평탄화된 ACL 태그 + 기밀 등급) + **렌더 전 소스 재확인** + 게이트웨이 단일 강제 + 메일 PII 수집 직후 마스킹 + 계보 기반 삭제, 권한 서비스 장애 시 fail-closed | 인덱스 분리; 후 필터만 | 2/10 선택 가이드: "사내 문서별 ACL이 다양하다면 → 메타데이터 사전 필터(그룹 평탄화) + 렌더 전 소스 재확인. 인덱스 분리는 ACL 수만큼 폭발". "PII가 답변에 필요 없다면 → 수집 직후 마스킹" | [2/10](../02-data-pipeline/10-access-control-governance.md) |

### 3.2 에이전트 워크플로우 / RAG (Part 3)

| 단계 | 선택 | 고려한 대안 | 선택 이유 | 근거 페이지 |
|---|---|---|---|---|

| **뉴로심볼릭** | **근거-답변 정합성 검증기**(3/04·3/10). 규칙(기호)이 citation 존재·권한·개정 상충·숫자 일치를 결정론으로 판정하고, NLI 모델(신경)이 "이 문장이 이 근거에 함의되는가"를 판정. 규칙이 최종 결정권, NLI 저확신은 abstain 또는 샘플링 리뷰. 데이터 파이프라인 쪽에서는 소형 분류기(신경) 출력에 규칙 검증(기밀 등급은 상향만 허용)을 붙이는 2/09 패턴 | 시험 — 규칙 게이트는 즉시, NLI는 faithfulness 측정 후 | 한국어 NLI 모델 `[실측]`, 결합 전체의 V&V 미성숙 인지(Renkhoff et al. `[검증]`) |
| **결정 모델(Jev / Decisions API)** | 판정 지점 2곳이 후보 — **문서 분류**(유형·기밀 등급, 2/09)와 **질의 라우팅**(FAQ / 복잡 문의 / 범위 밖, 3/02·3/11). 둘 다 선택지가 닫혀 있어 적합하지만 `[벤더]` 수치뿐이고 영어 중심 학습이 명시돼 있다. 따라서 **섀도 모드로 시작**: `decide()` 인터페이스 뒤에서 소형 분류기와 결정 모델이 같은 입력을 받고, 운영 판정은 분류기가, 결정 모델은 로그만 남긴다. 같은 한국어 평가셋에서 정확도·ECE·지연을 비교해 `[실측]`이 분류기 이상이면 교체. 임원 등급 문서는 외부 API 반출 불가이므로 그 분류는 어떤 경우에도 자체 호스팅 분류기 | 섀도 / 비교군 | 한국어 평가셋 정확도·보정 곡선 `[실측]`, 가격·지연 재확인(소스 충돌, [연구 노트](../_meta/research-notes-2026-10.md)) |

## 4. 전체 아키텍처

시각화: [`assets/html/scenario-document-qa.html`](../assets/html/scenario-document-qa.html) — 선택한 노드만 진하게, 뺀 노드(KG 구축, 오케스트레이션, 승인 UI 등)는 흐리게. 번호는 아래 흐름과 같다.

사용자 질의 1건("출장비 정산 기한이 며칠인가요? 작년 규정과 달라졌나요?")이 끝까지 흐르는 경로:

1. **[Interaction]** 사용자가 포털 위젯에 질문 입력. 프론트가 `query` 이벤트(사용자 ID·세션·질의문)로 백엔드에 전송. 게이트웨이가 ID 제공자에서 사용자의 그룹 집합을 해석해 요청 컨텍스트에 붙인다.
2. **[Reasoning]** 입력 가드레일 — 규칙 1층(인젝션 패턴, 범위 밖 키워드, 길이).
3. **[Reasoning]** 질의 이해 — 한국어 정규화 → 멀티턴 재작성 → 라우터 `decide("route")`: 운영은 소형 분류기, 결정 모델은 섀도. 판정 "문서 QA", 확신도 기록. 라우터가 "복합"으로 판정하면 질의 분해(여기서는 "현행 기한" + "개정 전후 차이" 두 하위 질의).
4. **[Reasoning → Knowledge]** 검색 — **ACL 사전 필터**(그룹 ACL 태그 ∩ 기밀 등급 ≤ 사용자 등급, 유효 시점 조건) → BM25 + dense → RRF → cross-encoder → 컷오프 → parent 확장. Knowledge 레이어가 **근거 단위(계약 ①)** 묶음을 반환: `evidence_id`, 청크·문장 본문과 오프셋, `source_uri`·섹션 경로·페이지 좌표, 개정판·유효 시점·`superseded_by`, ACL 태그, 신뢰도 등급.
5. **[Reasoning]** 생성 — 구조화 출력: 문장별 `evidence_id` 배열, `abstain` 플래그, 개정 전후 비교는 두 개정판 근거를 각각 인용.
6. **[Reasoning]** 뉴로심볼릭 검증 — 규칙 게이트(모든 사실 문장에 citation 존재, 인용된 `evidence_id`의 권한 재확인, 날짜·일수 숫자가 원문에 존재, 개정 상충 시 유효 시점 표기 여부) → NLI 함의 판정(2단계) → 불합격 시 재생성 상한 2회 → 그래도 실패면 abstain. 출력 가드레일(PII·외부 URL).
7. **[Reasoning → Interaction]** **렌더 가능한 응답(계약 ②)**: `text`, `citations[]`(계약 ① 참조), `ui_intent`(규칙 매핑 결과: `CitationList` + `EvidenceHighlight`), 확신도, `excluded_by_acl_count`(권한 밖이라 제외된 근거 건수), 승인 필요 여부 = false.
8. **[Interaction]** 의도→UI 매핑(규칙) → React 위젯이 답변 텍스트, 출처 카드(제목·섹션·개정판·유효 시점·등급), 원문 하이라이트, "권한 밖 근거 N건 제외" 안내를 렌더. SSE로 텍스트 델타 스트리밍.
9. **[Interaction → Reasoning]** 사용자가 피드백 바에서 "근거가 틀림 / 오래된 개정판 / 도움 됨" 이유 코드를 선택 → **사용자 이벤트(계약 ③)**: 유형 `feedback`, 대상 응답 ID·citation ID, 페이로드(이유 코드), 사용자·시각. 상태 저장소에 기록되고 평가 큐로 들어간다. 명확화(`OptionChips`) 선택 이벤트는 상태 머신 입력으로 3단계부터 재진입.
10. **[Cross-cutting]** 전 과정의 스팬(경로 판정·확신도, `evidence_id` 목록, 검증 결과, 섀도 결정 모델 판정, 토큰·지연)이 트레이스에 기록되고, 실패·abstain·저확신·피드백 건은 100% 보존되어 주간 샘플링 리뷰로 간다.

## 7. 예상되는 한계와 2차 과제

**이 설계가 해결하지 않는 것**

- **멀티홉 질의**("이 프로젝트 담당 부서의 작년 계약 조건"). 그래프 없이 질의 분해에 의존하므로 recall이 떨어진다. 질의 로그에서 비율을 측정해 유의미하면 경량 온톨로지 → 경량 그래프(LightRAG 식 증분) 순으로 도입한다([2/05](../02-data-pipeline/05-knowledge-graph-construction.md) 한계 "멀티홉은 청킹·임베딩으로 풀리지 않는다").
- **그룹 중첩이 깊은 조직의 ACL 평탄화 시차**. 그룹 멤버 변경이 청크 ACL에 늦게 반영될 수 있다. 완화는 청크에 그룹 ID만 두고 사용자→그룹 해석을 질의 시 실시간으로 하는 것([2/10](../02-data-pipeline/10-access-control-governance.md) 한계).
- **한국어 문장 분할 오류 → 하이라이트 어긋남**. 분할 실패 시 청크 단위 하이라이트로 폴백한다([2/08](../02-data-pipeline/08-grounding-data-design.md) 한계).
- **근거가 있어도 모델이 다르게 답하는 문제**를 검증기가 완전히 막지는 못한다. 검증기도 틀리며, 결합 전체의 V&V는 미성숙하다(Renkhoff et al. `[검증]`). 사후 샘플링 리뷰가 마지막 층이다.
- **코퍼스 전체 요약형 질의**("올해 바뀐 규정을 전부 알려줘")는 Advanced RAG로 구조적으로 답할 수 없다. 범위 밖으로 라우팅하고 안내한다.

**규모 10배(문서 수백만, 사용자 수만)가 되면 바뀌는 것**

- pgvector → 전용 벡터DB + 양자화 + 2단계 재순위 검토(2/04 조건 B). 필터 후 결과 부족이 커지면 기밀 등급별 인덱스 분리.
- contextual 접두·NLI 전수 적용의 인덱싱·검증 비용이 서빙 비용을 넘을 수 있다 → 고가치 컬렉션에만 적용, 판정은 규칙 → 분류기 → 결정 모델 순으로 재배정(5/02).
- 라우팅·검증 판정 건수가 커지면 결정 모델의 비용 이점이 의미 있어지므로 섀도 결과가 중요해진다.
- 단일 팀 운영 한계 → 데이터 파이프라인과 QA 체인의 팀 분리, 계약 ①을 스키마 저장소로 승격.

**트렌드 축을 채택으로 올리기 위해 필요한 `[실측]`**

| 축 | 필요한 실측 | 판단 기준 |
|---|---|---|
| 결정 모델 | 한국어 라우팅·문서 분류 평가셋에서 정확도·ECE·p95 지연·건당 비용 (분류기와 동일 셋) | 분류기 대비 정확도 동등 이상 + ECE ≤ 분류기 + 비용 이점 확인. 가격·날짜 소스 충돌은 벤더 문서 재확인 |
| 뉴로심볼릭(NLI) | 한국어 함의 판정 정밀도·재현율, 거짓 합격률 | faithfulness 개선폭이 재생성 비용 증가를 정당화 |
| 온톨로지 | 멀티홉 질의 비율, 택소노미 필터 사용률, 추출 위반율(그래프 도입 시) | 멀티홉이 유의미한 비율이고 그래프 도입 결정이 날 때만 |

## 9. 운영 계획 — 이 시나리오를 운영 상태로 유지하기

용어는 [Part 1/07](../01-foundations/07-operations-vocabulary.md), 단계별 상세는 각 페이지의 "운영 설계" 섹션, 종합은 [Part 5/06](../05-cross-cutting/06-operational-design-matrix.md). 이 시나리오는 **행동이 없는 읽기 전용 시스템**이므로 운영의 무게중심은 승인·게이팅이 아니라 **데이터 신선도와 ACL 정합성**에 있다. 팀이 5명(백엔드 2·데이터 1·프론트 1·PM 1)이라는 제약도 운영 설계에 그대로 반영한다 — 온콜은 백엔드 2명 교대, 사내 업무시간 중심, 야간은 저하 모드를 허용한다. 아래 수치는 모두 **예시**이며 10주차 2주 실측 뒤 재설정한다.

### 9.1 E2E SLO와 레이어별 SLI (예시값)

| 지표 (사용자 관점) | 목표 (예시) | 측정 위치 — 받치는 레이어·단계 SLI | 위반 시 런북 (한 줄) |
|---|---|---|---|
| **답변 p95 지연** | ≤ 5초 (첫 토큰 ≤ 2초) | Knowledge: 2/04 벡터 검색 p95 ≤ 300ms, 2/10 주체 해석 p95 ≤ 100ms · Reasoning: 3/03 리랭커 p95, 3/04 생성 첫 토큰 · Interaction: 4/04 SSE 첫 델타 | 리랭커 비활성(피처 플래그) → k 축소 → BM25 단독 모드 순으로 저하, 각 단계 p95 분해표로 병목 단계 식별 |
| **근거 부합률** (문장 ↔ 인용 근거 함의, 샘플 리뷰) | ≥ 95%, 재생성률 ≤ 10% | Reasoning: 3/04 citation 존재 규칙 통과율, 3/10 NLI 검증 통과율·재생성률 · Knowledge: 2/08 문장 분할 오류율(하이라이트 어긋남) | 재생성률 급등 → 번들 매니페스트에서 직전 프롬프트·모델 버전으로 롤백, 골든셋 faithfulness 재실행 |
| **권한 밖 근거 노출** | **0건** (주 1회 내부 감사 리포트) | Knowledge: 2/10 권한 대조 불일치(노출 방향) = 0, 누출 카나리 통과율 100% · Reasoning: 3/04 권한 재확인 게이트 차단 건수(0이 정상 — 1건이라도 사전 필터 결함) · Interaction: `excluded_by_acl_count` 표시율 | 카나리 실패 또는 노출 1건 → 해당 컬렉션 검색 **킬 스위치** + 보안 사고 절차 + 감사 레코드로 과거 노출 건 역추적 |
| **신선도** — 신규·개정 반영 / 삭제·권한 회수 전파 | 신규·개정 p95 ≤ 4시간 / 삭제·ACL 변경 ≤ 1시간(우선 레인) / 대조 후 유령 0건 | Knowledge: 2/07 소스 변경 → 검색 반영 지연 p95, 삭제 레인 지연, DLQ 크기, 톰스톤 카나리 · 2/10 ACL 평탄화 잡 지연 | 삭제 레인 지연 초과 → 신규 색인 레인 일시 정지하고 삭제·ACL 먼저 소진. 기밀·PII 철회 문서는 배치를 기다리지 않고 **수동 톰스톤 런북** |
| **과업 완료율 / abstain 정확도** | 완료율 ≥ 70%(원문 확인 후 추가 질의 없이 종료), 답해야 할 때 거부 ≤ 5% | Reasoning: 3/02 라우팅 정확도·ECE, 3/04 abstain 정확도 · Interaction: 4/06 피드백 이유 분포("근거가 틀림"·"오래된 개정판") | 오거부 급증 → 라우터 분류기 직전 버전 롤백, 범위 밖 판정 샘플 리뷰. "오래된 개정판" 피드백 급증 → `superseded_by`·유효 시점 필터 점검 |
| **가용성** (업무시간 09–18시 기준) | 99.5% — 저하 모드(키워드 검색만·공개 문서만)는 가용으로 집계하되 **저하 상태 표시 필수** | 전 레이어 헬스체크 + `retrieval_mode`·`degrade_mode` 플래그 비율 | 저하 비율이 1시간 중 20% 초과 → 온콜 호출. 야간 저하는 다음 업무일 처리 |

오류 예산: 월 가용성 예산을 소진하면 임베딩 모델·청킹·프롬프트 변경을 동결하고 안정화 작업만 한다(5/05).

### 9.2 장애 시나리오 3개 — 무엇이 죽으면 사용자에게 어떻게 보이고 누가 뭘 하나

이 시나리오의 행동은 전부 등급 1(답변 표시)이지만, **권한 밖 문서 노출은 "되돌릴 수 없는 유출"**이라 장애 대응의 원칙은 하나다 — 확신이 없으면 **덜 보여준다**(fail-closed). 세 장애는 2/10·2/04·2/07의 장애 모드를 이 시나리오의 규모(단일 PostgreSQL, 시간 단위 배치, 5인 팀)에 맞춘 것이다.

| 장애 | 증상 (사용자에게) | 자동 대응 | 사람 개입 | 복구 후 |
|---|---|---|---|---|
| **① 권한 서비스·ID 제공자 다운** (그룹 집합 해석 불가) | "현재 공개 문서만 검색됩니다" 안내 또는 검색 거부. 답변은 나오되 `excluded_by_acl_count`가 평소보다 큼 | **fail-closed** (2/10): TTL(예시 5분) 내 캐시된 그룹 집합으로만 처리 → TTL 만료 후엔 `classification=public` 문서만 노출하는 저하 모드 → 그것도 불가하면 거부. **절대 fail-open 하지 않는다.** 저하 진입 즉시 사내 보안 책임자에게 자동 통보 | 다운이 TTL 초과 → 백엔드 온콜. 포털 공지(저하 사유). 임원 한정 등급은 저하 모드에서도 **노출 0** 확인 | 복구 후 저하 구간의 질의 로그에서 "공개 문서만으로 답한 건"을 표시해 사용자에게 재질의 안내. 캐시 TTL이 적절했는지 재검토(너무 길면 권한 회수 지연, 너무 짧으면 저하 잦음) |
| **② 임베딩 API 다운** (외부 벤더) | 의미 검색 불가 → 동의어·유사 표현 질의의 recall 하락. 신규 문서가 색인에 늦게 반영 | 검색: **BM25 단독 모드**로 저하, 응답에 `retrieval_mode=keyword_only` → 위젯이 "키워드 검색만 가능" 배지 표시(2/04). 색인: 임베딩 단계만 큐에 보존(백프레셔), 파싱·메타데이터·ACL 태그는 계속 진행. 서킷 브레이커 개방 시 트레이스에 `fallback=true` | 예시 10분 초과 → 온콜이 벤더 상태 확인. **임원 한정 등급 경로는 자체 호스팅 임베딩**이라 영향 없음 — 단 다른 모델 벡터를 섞어 폴백하지 않는다(모델 혼재 금지) | 큐 적체분 색인 재개(upsert 키 `(chunk_id, embedding_model)`로 멱등). 저하 구간의 recall 영향을 골든셋으로 사후 측정하고 벤더 SLA 대비 기록 |
| **③ 삭제·권한 회수 미전파** (유령 문서) | 삭제·철회된 문서, 또는 권한이 회수된 사용자에게 과거 문서가 **여전히 인용됨**. 사용자는 알아채지 못한다 — 가장 위험 | 탐지: 톰스톤 문서로 카나리 질의(2/07), 주 1회 전체 대조의 유령 건수, 2/10 권한 대조(노출 방향). 카나리 실패 시 해당 인덱스 검색 **차단**, 대조 배치가 톰스톤 이벤트 재투입. 노출 방향 불일치는 즉시 보수적 ACL로 덮어쓰기 | **노출 방향 1건이라도 보안 사고 절차**(2/10): 데이터 담당 + 보안 책임자. 기밀·PII·철회 문서면 계보 기반 전파 삭제 런북 즉시 수동 실행 — 청크·벡터·parent·캐시·트레이스 본문까지 | 삭제 증명(계보 파생물 수 = 삭제 수) 발급. 미전파 원인(DLQ 체류·배치 실패·소스 ACL 매퍼 고장)을 2/07 장애 모드 목록에 환류. 삭제 레인 SLO를 조정하거나 배치 주기 단축 결정 |

세 장애 모두 **킬 스위치가 배포 없이** 작동해야 한다(컬렉션별 검색 차단, 리랭커·dense 끄기). 5인 팀에서는 런북이 길면 안 지켜지므로, 각 장애의 런북은 "확인할 지표 3개 → 누를 스위치 1개 → 알릴 사람 1명" 한 장으로 둔다.

### 9.3 변화 시나리오 — 1년 안에 일어날 변화와 흡수 경계

이 시나리오에서 가장 자주 바뀌는 것은 **지식(문서) > 권한·조직 > 프롬프트·임계값 > 모델** 순이다. 계약 ①(근거 단위)·②(렌더 가능한 응답)·③(사용자 이벤트)은 고정하고 그 뒤의 구현을 바꾼다.

| 예상 변화 (구체적 사건) | 유형 | 어디서 흡수 (안정 계약 / 가변 구현) | 재배포 여부 | 다시 돌릴 평가 |
|---|---|---|---|---|
| **규정집 전면 개정** — 취업규칙·출장·구매 규정 수백 건이 같은 시행일로 일괄 개정, 구판 질의도 계속 들어옴 | 지식 | 계약 ① 불변. 2/03 bitemporal(기록·유효 시점) + `superseded_by` + 불변 버전이 흡수. 증분 배치가 개정판을 신규 버전으로 적재, 구판은 `is_current=false`로 보존 | **없음** (데이터) | 개정 상충 골든셋(구·신판 동시 인용, 유효 시점 질의), "어느 개정판 기준" 표시율, 중복 제거 오탐(개정판이 하나로 묶임) 점검 |
| **조직 개편 — 부서 코드 체계 변경 + 그룹 재편** (본부 신설, 부서 통폐합) | 사용자 환경 · 도메인 모델 | 택소노미(SKOS) 버전 + 구→신 부서 매핑 테이블. 청크에는 그룹 ID만 있으므로 ACL 평탄화 잡 재실행으로 재태깅. 필터 어휘·분류기 enum은 매핑 테이블 경유 | **없음** (택소노미·매핑 데이터) — 단 분류기 enum이 바뀌면 분류기 재학습 | 권한 대조 **전수**(노출·누락 양방향), 누출 카나리, 택소노미 필터 어휘 테스트, 골든셋의 권한 조건 재라벨 |
| **임베딩 모델 교체** (한국어 성능 개선 모델로, 2종 `[실측]` 재비교) | 모델 | 2/04 포트 뒤 어댑터 교체. 컬렉션 메타의 허용 모델 1종 원칙 → **전체 재임베딩**을 그린 인덱스에 수행 후 블루/그린 전환, 1세대 보존 | **인덱스 재구축** (번들 매니페스트의 임베딩 모델 버전 상승) | 골든셋 recall@10 (베이스라인 -2%p 이내가 전환 조건), 하이라이트 회귀, 권한 밖 0건 재확인, 비용 분해표 |
| **LLM 벤더 버전 교체·가격 변경** (구조화 출력 동작 변화 포함) | 모델 | 모델 게이트웨이 + 프롬프트-모델 호환 매트릭스. 카나리(사내 부서 1곳)로 비교 | **설정 교체** + 프롬프트 호환 수정 시 번들 | 전체 골든셋(faithfulness·citation·abstain), 구조화 출력 스키마 실패율, 재생성률 |
| **결정 모델 섀도 → 라우팅 운영 승격** (한국어 평가셋에서 분류기 이상 확인 시) | 모델 · 규칙 | `decide("route")` 구현체 설정 교체, 임계값은 코드 밖 설정. 폴백은 기존 분류기 | **없음** (설정) | 라우팅 정확도·ECE·세 갈래 비율, 폴백율, p95 지연·건당 비용. 불합격이면 설정 한 줄로 복귀 |
| **기밀 등급 3 → 4단계 확대** (내부 감사가 "협력사 공유 가능" 등급 신설 요구) | 규칙·정책 | 택소노미 enum 추가(추가는 자유) + 2/10 사전 필터 규칙 버전 + 시행일. 분류기는 "상향만 허용" 규칙 유지한 채 재학습 | 분류기 **국소 재배포**, 필터 규칙은 설정 | 분류 정확도(새 등급), 권한 밖 0건 리포트, 규칙 테스트 스위트(등급 비교 연산) |
| **모바일 포털 출시** (현장 관리자 수요) | 사용자 환경 | 계약 ② 불변. 4개 컴포넌트의 모바일 렌더러 추가, 하이라이트는 모바일에서 청크 단위 폴백. 계약 ③ 이벤트 유형 불변 | **프론트만** 재배포 | 계약 ②③ 호환 테스트, 접근성 기본 점검, citation 클릭률(모바일 분리) |
| **문서 10배** (계열사 통합으로 수백만 건) | 규모 | 계약 ① 뒤에서 pgvector → 전용 벡터DB 어댑터 교체 검토(2/04 조건 B), 기밀 등급별 인덱스 분리, 증분 배치 창 재설계 | 저장소 교체 시 **인덱스 마이그레이션** | recall·p95 재측정, 필터 후 결과 부족률, 색인 지연 SLO, 비용이 문서 수에 비례하는지 확인 |

여덟 변화 중 코드 재배포가 필요한 것은 둘뿐이고, 그마저 어댑터·렌더러에 국한된다. 반대로 **계약 ①의 필드 삭제·의미 변경**(예: `valid_at` 의미 변경)은 검증기·UI·감사 레코드까지 번지므로 버전 상승 + 호환 매트릭스 갱신이 필수다.

### 9.4 거버넌스 — RACI, 위험 등급표, 승인 매트릭스, 감사 필드

**RACI** — 5인 팀이라 A(책임)가 PM에 몰리는 것이 현실이다. 대신 **권한·기밀 관련 A는 팀 밖**(사내 보안 책임자, 문서 소유 부서)에 둔다. 사람 이름이 아니라 역할로 적는다.

| 대상 | R (실행) | A (책임) | C (자문) | I (통보) |
|---|---|---|---|---|
| 프롬프트·라우팅 질문 정의·임계값 | 백엔드 | PM (제품 책임자) | 도메인 검수자(인사·법무 담당) | 데이터·프론트 |
| LLM·임베딩 모델 버전, 번들 매니페스트 | 백엔드 | PM (아키텍트 겸) | 사내 보안(외부 반출 범위) | 전체 |
| 택소노미(문서 유형·부서·기밀 등급)와 기밀 정책 | 데이터 | **문서 소유 부서장**(데이터 소유자) | 내부 감사, 사내 보안 책임자 | 백엔드 |
| ACL 매핑·권한 서비스 연동·사전 필터 규칙 | 데이터 | **사내 보안 책임자** | 내부 감사 | PM |
| 인덱스·동기화·삭제 전파·블루/그린 | 데이터 | PM | 사내 보안(삭제 증명) | 백엔드 |
| 입력·출력 가드레일 규칙(인젝션·PII·외부 URL) | 백엔드 | 사내 보안 책임자 | PM | 프론트 |
| 컴포넌트 4개·계약 ②③ 스키마 | 프론트 | PM | 사내 포털팀(접근성) | 백엔드 |
| 골든셋·주간 샘플링 리뷰·감사 리포트 | PM + 도메인 검수자 | PM | 데이터 | 전체 |

**위험 등급표** — 1/07의 가역성 × 영향 범위 축에 이 시나리오의 행동을 놓는다.

| 등급 | 이 시나리오의 행동 | 필수 통제 |
|---|---|---|
| 1 | 답변·citation 표시, 명확화 `OptionChips`, 피드백 저장, 문서 메타 조회 툴 | 출력 가드레일 + 로그 |
| 2 | 프롬프트·라우팅 규칙·임계값 배포, 인덱스 블루/그린 전환(별칭 롤백 가능), 재심 일회 허용 | 골든셋·recall 회귀 게이트 + 감사 |
| 3 | 부서 한정 문서 청크의 외부 LLM API 전송(조직 외부·전송 후 비가역) — **승인은 런타임이 아니라 벤더 계약·반출 정책으로 사전 충족**, 런타임은 등급별 라우팅 규칙 / 임베딩 모델 교체(전체 재임베딩) / 문서 삭제 전파(유예 후 물리 삭제) | 규칙 게이트 + 사전 승인 기록 + 폴백(자체 호스팅 경로) |
| 4 | 기밀 등급 정책·ACL 매핑 규칙 변경(틀리면 노출을 되돌릴 수 없음, 전 사용자 영향) | 2인 승인 + 권한 대조 섀도 기간 |
| 5 | **임원 한정 문서의 외부 API 전송** — 에이전트 경로 자체가 없다(규칙 deny, 자체 호스팅 경로 강제) | 자동 실행 금지 |

**승인 매트릭스** — 3/12 형식. 런타임 승인은 없고, 매트릭스는 **변경 관리 행동**을 다룬다. 등급 3 이상에 빈 행이 없는지 CI에서 확인한다.

| 행동 유형 | 영향 범위 | 요청자 역할 | 승인자 (역할) | 승인 수 | 시한 → 에스컬레이션 | 만료 시 | 등급 |
|---|---|---|---|---|---|---|---|
| 질의·답변 표시 (런타임) | 요청자 본인 | 임직원 | 없음 (출력 가드레일 + 로그) | 0 | — | — | 1 |
| 임원 한정 문서 외부 API 전송 (런타임) | 조직 외부 | — | **에이전트 금지** — 규칙 deny, 자체 호스팅 경로로 라우팅 | — | — | — | 5 |
| 프롬프트·라우팅 규칙·임계값 배포 | 전 사용자 | 백엔드 | PM + 골든셋 회귀 통과 | 1 | 1영업일 → 없음 | 배포 안 함 | 2 |
| 인덱스 블루/그린 전환 | 전 사용자 | 데이터 | PM + recall 게이트(-2%p 이내) | 1 | 1영업일 → 없음 | 전환 안 함 | 2 |
| 임베딩 모델 교체(전체 재임베딩) | 전 사용자 | 데이터 | PM + 사내 보안(반출 범위 재확인) | 2 | 3영업일 → 없음 | 교체 안 함 | 3 |
| 기밀 등급 정책·ACL 매핑 규칙 변경 | 전 사용자·기밀 | 데이터 | **사내 보안 책임자 + PM** + 권한 대조 섀도 통과 + 시행일 | 2 | 3영업일 → 보안팀장 | 적용 안 함 | 4 |
| 기밀·PII 문서 긴급 퍼지(계보 전파 삭제·캐시·트레이스) | 여러 사용자 | 데이터·보안 | 사내 보안 책임자 (해당 문서 **검색 차단은 승인 없이 자동**) | 1 | 1시간 → PM | 퍼지 미실행 + 차단 유지 + 알림 | 3 |
| 샘플링 리뷰에서 발견된 오탐의 일회 허용(재심) | 요청자 본인 | 임직원 | PM (운영 책임자 역) | 1 | 1영업일 → 없음 | 기각 | 2 |

**감사 필드** — 3/12 감사 레코드 스키마에서 승인·실행 블록을 빼고, 이 시나리오의 핵심인 **근거의 권한·버전 정보**를 더한다. 관측 로그와 저장소·보존을 분리하고, 샘플링하지 않으며, 본문은 저장하지 않는다(기밀 — `evidence_id`로 불변 버전을 참조하면 시점 재현이 된다).

| 블록 | 필드 | 왜 필요한가 |
|---|---|---|
| 상관 키 | `record_id`, `run_id`, `trace_id`, `session_id` | 관측 트레이스·피드백 이벤트와 연결 |
| 요청자 | `user_id`, `group_set_hash`, `clearance_level`, `requested_at` | "그 시점 그 사용자의 권한 범위"를 재구성 |
| 판정 | `route: {source, choice, p, question_version, fallback}`, `abstain: bool` | 라우팅이 분류기였는지 폴백이었는지 구분 |
| 근거 | `evidence_ids[]` 각각에 `doc_version`, `valid_at`, `superseded_by`, `acl_tags_hash`, `classification`, `trust_grade`; `excluded_by_acl_count` | **"권한 밖 근거가 섞였는가", "어느 개정판 기준이었는가"**가 내부 감사의 두 질문 |
| 규칙 | `rules_applied[]: {rule_id, rule_version, result}` — citation 존재·권한 재확인·개정 상충·숫자 일치·PII·외부 URL | 규칙 버전 없이는 "그때 규칙이 무엇이었나"를 복원 못 함 |
| 게이트 | `gate_output: pass\|block\|degrade`, `degrade_mode?: keyword_only\|public_only\|unverified_flag` | 저하 구간의 답변을 정상 답변과 구분 |
| 버전 | `versions: {prompt, llm, embedding_model, chunking_rules, classifier, taxonomy, acl_mapping, nli_verifier}` | 시점 재현 키(번들 매니페스트와 일치) |

보존 기간은 내부 감사 주기에 맞춰 예시 2년, append-only. 섀도 결정 모델 판정은 관측 트레이스에만 남긴다(운영 판정이 아니므로 감사 대상이 아님).

### 9.5 관측 설계 — 한 요청을 끝까지 따라가는 트레이스

4절의 질의 흐름 ①~⑩을 그대로 스팬 트리로 옮긴다. 규약은 [Part 1/07 관측성 설계 요소](../01-foundations/07-operations-vocabulary.md)와 [Part 5/03](../05-cross-cutting/03-observability-tracing.md), 알림 심각도는 1/07의 P1(즉시 호출)·P2(업무 시간)·P3(다음 리뷰). 이 시나리오의 관측이 답해야 할 질문은 하나다 — **"이 답에 인용된 근거가 그 시점 그 사용자의 권한 안이었고, 지금도 삭제되지 않았는가."** 그래서 공통 속성 중 `agent.evidence_ids[]`를 `(evidence_id, doc_version)` 쌍으로 남기고, 배치 쪽 삭제 레인의 문서 단위 트레이스와 **조인 가능**하게 두는 것이 설계의 중심이다. 모든 스팬에 버전 키 5종(`agent.model_version / prompt_version / index_version / rules_version / catalog_version`)과 번들 매니페스트 버전, `tenant_id`(단일이지만 처음부터), `user_role_hash`가 붙는다.

| 구간 (레이어 → 단계) | 스팬 이름 | 반드시 남길 속성 | 이 시나리오 전용 지표 | 알림 → 런북 |
|---|---|---|---|---|
| ① Interaction → Reasoning · 질의 수신·그룹 해석 | `turn` (루트, `request_id`) → `invoke_agent {doc_qa}` | `session_id`, `agent.group_set_hash`, `agent.clearance_level`, 그룹 해석 지연·결과(ok / cached_ttl / failed), 버전 키 5종 | 그룹 해석 p95(2/10 ≤ 100ms), 캐시 TTL 경유 비율, E2E p95(9.1 답변 지연) | 그룹 해석 실패율 급증 → 9.2 ① 런북(fail-closed 확인, 저하 진입 통보) P2 |
| ② Reasoning · 입력 가드레일 | `gate.evaluate {input}` | `agent.rules_version`, `rules_applied[]`(인젝션 패턴·범위 밖·길이 — rule_id·결과), `agent.outcome=blocked`일 때 사유 코드 | 차단률(사유별), 인젝션 패턴 적중 수 | 인젝션 차단 급증 → 패턴 사전 점검, 샘플 리뷰 P2 |
| ③ Reasoning · 질의 이해·라우팅 | `routing.decide {route}` → 자식 `routing.shadow {decision_model}` | `agent.decision`(faq / doc_qa / out_of_scope / complex), `agent.confidence`, `agent.decision_source=classifier`, 질문 정의 버전, 재작성 발생, `agent.shadow_decision`·`agent.shadow_agreement`, 분해 하위 질의 수 | 세 갈래 비율, ECE(샘플 라벨), **섀도 불일치율**(분류기 ↔ 결정 모델), 분해 발생률 | 범위 밖 판정 비율 급변 → 9.1 ⑤ 런북(라우터 롤백·샘플 리뷰) P2 / 섀도 불일치율 급등 → 결정 모델 벤더 변경 확인 P3 |
| ④ Reasoning → Knowledge · 검색 | `retrieval.search` → 자식 `retrieval.acl_filter`, `retrieval.rerank`, `retrieval.assemble` | `agent.index_version`, `agent.acl_mapping_version`, `agent.retrieval_mode`(hybrid / keyword_only), 필터 전후 후보 수, `agent.evidence_ids[]`(상위 k, `doc_version` 포함), `agent.excluded_by_acl_count`, 컷오프 점수 분포, `agent.degradation[]`(embedding_fallback · public_only), 임원 등급 경로 여부(self_hosted) | 벡터 검색 p95(2/04 ≤ 300ms), 0건 비율, 필터 후 결과 부족률, **`retrieval_mode=keyword_only` 비율**, **임원 등급 문서의 외부 API 경로 호출 건수(0)** | keyword_only 비율 임계 초과 10분 → 9.2 ② 런북 P2 / 외부 경로 1건 → 보안 사고 절차 **P1** |
| ⑤ Reasoning · 생성 | `generation.generate` | 1/01 모델 호출 속성(해석된 모델 버전·프롬프트·스키마 버전·토큰·캐시·TTFT) + 문장 수, 인용된 `agent.evidence_ids[]`, `abstain` 플래그 | 첫 토큰 p95(9.1 ≤ 2초), 스키마 실패율, 문장당 인용 근거 수 분포 | 스키마 실패율 2배 15분 → 프롬프트-모델 호환 매트릭스 직전 셀로 롤백 P2 |
| ⑥ Reasoning · 뉴로심볼릭 검증 | `generation.verify` → 자식 `gate.evaluate {citation_rules}`, `generation.nli` | `rules_applied[]`(citation 존재·권한 재확인·개정 상충·숫자 일치 — rule_id·version·결과), **`agent.cited_subset_of_retrieved`**(인용 ⊂ ④의 evidence_ids 자동 검증), **`agent.acl_recheck_blocked_count`**, NLI 통과·저확신 수, 재생성 횟수, `agent.outcome`(success / fallback→abstain) | 규칙 통과율, 재생성률(9.1 ≤ 10%), NLI 통과율(9.1 근거 부합률의 자동 프록시), **권한 재확인 차단 건수(0 — 1건이라도 ④ 사전 필터 결함)** | 권한 재확인 차단 ≥ 1 → 9.1 ③ 런북(컬렉션 킬 스위치 + 보안 사고 절차) **P1** / 재생성률 > 10% 1시간 → 9.1 ② 런북 P2 |
| ⑦⑧ Reasoning → Interaction · 응답·렌더 | `ui.map`(규칙) + 프론트 보고 `ui.render {CitationList \| EvidenceHighlight \| OptionChips}` | `agent.catalog_version`, 컴포넌트 인스턴스 ID, `citations[]`(evidence_id 참조), `excluded_by_acl_count` 표시 여부, `degrade_mode` 배지 표시 여부, 하이라이트 오프셋 일치 여부, SSE 첫 델타 지연 | 첫 델타 p95(4/04), **하이라이트 어긋남률**(2/08 문장 분할 오류의 UI 측 관측), 저하 배지 표시율(9.1 ⑥ "저하 상태 표시 필수") | 저하 비율 1시간 중 20% 초과 → 9.1 ⑥ 런북(온콜) P2 / 저하인데 배지 미표시 → 설계 결함 P2 |
| ⑨ Interaction → Reasoning · 피드백 | `ui.event {feedback}` (W3C 헤더로 `trace_id` 되돌림) | 이벤트 유형, 대상 응답 ID·citation ID, 이유 코드(근거 틀림 / 오래된 개정판 / 도움 됨), 컴포넌트 인스턴스 ID, 명확화 선택 시 재진입 여부 | 피드백 이유 분포(9.1 ⑤), **"오래된 개정판" 비율**, citation 클릭률, 명확화 후 재진입률 | "오래된 개정판" 비율 급증 → `superseded_by`·유효 시점 필터 점검 P3 / "근거 틀림" 급증 → 주간 리뷰 전수 전환 P2 |
| ⑩ Knowledge(배치) · 삭제·ACL 전파 — 문서 단위 트레이스 | `sync.delete {doc_id}` → `index.tombstone`, `sync.acl_reflatten`, `sync.canary` | `doc_id`·`doc_version`, 레인(우선 / 일반), 계보 파생물 수(청크·벡터·parent·캐시·트레이스 본문)와 삭제 수, DLQ 체류 시간, 카나리 결과 | 삭제 레인 지연 p95(9.1 ④ ≤ 1시간), DLQ 크기, 대조 배치 유령 건수, **유령 인용 건수** = 삭제 완료 시각 이후의 ⑥ 스팬에 같은 `(evidence_id, doc_version)`이 인용된 수(0이 정상) | 삭제 레인 지연 초과 → 9.1 ④ 런북(신규 레인 정지·삭제 먼저) P2 / 카나리 실패 또는 유령 인용 ≥ 1 → 9.2 ③ 런북 **P1** |

**이 시나리오의 차별점 — ACL·근거 ID·삭제 전파를 한 조인으로.** ④의 `evidence_ids[]`와 ⑥의 `cited_subset_of_retrieved`·`acl_recheck_blocked_count`, ⑩의 `sync.delete` 이벤트를 `(evidence_id, doc_version)`으로 조인하면 세 질문이 쿼리 하나씩이 된다 — "인용이 검색 결과 밖에서 왔는가"(⑥ 자동 검증), "권한 밖 근거가 섞였는가"(⑥ 차단 수 + 2/10 노출 방향 대조), "삭제된 문서가 아직 인용되는가"(⑩ 유령 인용). 9.2 ③의 탐지 원천은 톰스톤 카나리와 주 1회 대조 두 가지였는데, 이 조인이 **세 번째·가장 빠른 원천**이 된다. 섀도 결정 모델 판정(③)은 운영 경로에 영향이 없으므로 관측 트레이스에만 남기고 감사 레코드에는 넣지 않는다(9.4).

**9.1 SLO → 측정 스팬·지표.**
- ① 답변 p95 → `turn` duration + ④⑤⑦ 자식 스팬 분해표
- ② 근거 부합률·재생성률 → ⑥ `generation.verify`
- ③ 권한 밖 노출 0건 → ⑥ `acl_recheck_blocked_count` + ⑩ 카나리 + ④ 외부 경로 0건
- ④ 신선도 → ⑩ 삭제 레인 지연·DLQ
- ⑤ 완료율·abstain 정확도 → ③ 세 갈래·⑨ 이유 분포·⑥ abstain
- ⑥ 가용성 → ④⑦의 `degradation[]`·배지 표시율

**9.2 장애 → 탐지 신호.**
- ① 권한 서비스 다운 → ①의 그룹 해석 실패 + ④ `degradation=public_only` 비율
- ② 임베딩 API 다운 → ④ `retrieval_mode=keyword_only` + 임베딩 서킷 이벤트
- ③ 삭제 미전파 → ⑩ 카나리·유령 건수·유령 인용 조인

**대시보드 3장.**
- ① 사용자 관점 E2E: 답변 p95(첫 토큰·총 분리), 과업 완료율·abstain 비율, 저하 모드 비율(keyword_only / public_only — 배지 표시율과 나란히), 피드백 이유 분포, **권한 밖 노출 카운터(상시 0, 큰 숫자 하나)**.
- ② 레이어별 SLI: Knowledge — 검색 p95·0건율·필터 후 부족률·삭제 레인 지연·DLQ·카나리 상태·유령 인용(0); Reasoning — 라우팅 세 갈래·섀도 불일치율·규칙 통과율(규칙별)·재생성률·NLI 통과율·권한 재확인 차단(0); Interaction — 첫 델타 p95·하이라이트 어긋남률·저하 배지 표시율·citation 클릭률.
- ③ 비용·판정 분포: 모델 티어별 비용을 **외부 API 경로 vs 자체 호스팅 경로로 분리**(임원 등급 반출 0의 비용 측 증거), 캐시 적중률(권한 범위가 키에 들어가 낮을 것을 전제), 라우팅 확신도 히스토그램, 분류기 × 섀도 결정 모델 일치 매트릭스, 야간 저하 구간의 비용 절감분.

**감사 추적 저장소로 분리되는 필드와 보존.** 9.4 감사 필드 표의 전 블록(상관 키·요청자·판정·근거·규칙·게이트·버전)을 `trace_id` 기준으로 ①③④⑥ 스팬에서 추출해 별도 저장소에 append-only로 쓴다 — 본문 없음, `(evidence_id, doc_version)`으로 불변 버전을 참조, 보존 예시 2년(내부 감사 주기, 9.4). 관측 트레이스에만 남는 것: 지연·토큰·캐시·점수 분포·섀도 판정·하이라이트 오프셋·SSE 이벤트 수 — 메타데이터 보존 예시 30일, 실패·abstain·저확신·피드백·저하·ACL 차단 건은 90일. 본문 저장소(opt-in)는 예시 7일, 기밀 등급을 고려해 가장 짧다. 사용자 ID 원문은 어느 저장소에도 없다(`user_role_hash`·`group_set_hash`만).

**샘플링 정책.** 메타데이터(속성·지표)는 전수. 본문(질의·생성 텍스트·검색 청크)은 opt-in이며 **공개 등급 문서만 인용된 턴**에 한해 예시 2% 샘플, 부서 한정 이상이 인용된 턴은 본문 기록 없이 `evidence_id` 참조만, **임원 한정 문서가 인용된 턴은 본문 기록 자체를 금지**(2/10 반출 불가 원칙을 관측 저장소에도 적용). 실패·abstain·저확신(θ 미만)·피드백·저하 모드·ACL 재확인 차단·인젝션 차단 건은 테일 샘플링으로 **턴 단위 전수** 보존(검색 스팬만 남고 UI 스팬이 빠지는 일이 없게 샘플링 결정은 `turn` 종료 시 한 번). 승인 흐름이 없으므로 "승인 건 전수" 규칙은 해당 없음 — 대신 ⑩ 삭제 레인 트레이스가 전수다.

### 9.6 운영 준비도 리뷰(ORR) 통과 조건

전사 공개(10주차) 전에 아래가 모두 체크되어야 한다. 세 레이어와 횡단 관심사를 모두 포함한다.

- [ ] **[Knowledge]** 권한 서비스 다운 시 fail-closed(캐시 TTL → 공개 문서만 → 거부)가 테스트로 확인되었고, fail-open 경로가 코드에 없다
- [ ] **[Knowledge]** 권한 없는 계정의 누출 카나리 질의가 매 배치 후 자동 실행되고, 실패 시 컬렉션 검색 킬 스위치가 배포 없이 작동한다
- [ ] **[Knowledge]** 삭제·권한 회수가 우선 레인으로 처리되고, 톰스톤 카나리와 주 1회 전체 대조가 유령 0건을 보고한다
- [ ] **[Knowledge]** 임베딩 API 다운 시 BM25 단독 모드로 저하되며 응답에 `retrieval_mode`가 표시되고, 임원 한정 등급은 자체 호스팅 경로만 탄다
- [ ] **[Knowledge]** 블루/그린 인덱스 1세대가 보존되어 전환 후 회귀 시 별칭 롤백이 가능하다
- [ ] **[Reasoning]** 모든 사실 문장에 citation 존재·권한 재확인·개정 상충 규칙 게이트가 있고, 재생성 상한 2회 후 abstain으로 간다
- [ ] **[Reasoning]** `decide()` 뒤 라우터가 설정 한 줄로 분류기 ↔ 결정 모델 전환·복귀되고, 섀도 판정은 운영 경로에 영향을 주지 않는다
- [ ] **[Reasoning]** 프롬프트·임계값·택소노미·ACL 매핑 규칙이 코드 밖 버전 데이터이고, 번들 매니페스트 한 장에 모든 버전이 있다
- [ ] **[Interaction]** `excluded_by_acl_count`와 저하 상태(키워드 검색만·공개 문서만)가 위젯에 보이고, 계약 ②③ 호환 테스트가 CI에 있다
- [ ] **[Interaction]** 문서 본문 → 하이라이트 → 피드백 경로의 출처 태그와 서버 재검증이 있다(유일한 UI 인젝션 경로)
- [ ] **[횡단]** 감사 레코드에 `evidence_id`별 권한·버전 정보와 규칙 버전이 있고, "권한 밖 근거 0건" 리포트가 레코드만으로 생성된다
- [ ] **[횡단]** 6개 E2E SLO의 대시보드와 알림이 있고, 각 알림에 한 장짜리 런북(지표 3개·스위치 1개·연락처 1명)이 연결되어 있다
- [ ] **[횡단]** RACI의 모든 행에 A가 있고, 권한·기밀 관련 A가 팀 밖(보안 책임자·문서 소유 부서)에 지정되어 있다
- [ ] **[횡단]** 기술 부채가 기록되어 있다 — "ACL은 메타데이터 필터, 쿼리 시 실시간 그룹 해석은 2차", "NLI 검증기는 faithfulness 측정 후", "그래프·온톨로지 보류"
- [ ] **[횡단]** 한 턴의 트레이스에서 `turn → routing.decide → retrieval.search(evidence_ids) → generation.verify(인용 ⊂ 검색, 권한 재확인) → ui.render → ui.event(feedback)`가 같은 trace_id로 끊김 없이 보이고, 섀도 결정 모델 판정이 자식 스팬으로 함께 남되 감사 레코드에는 들어가지 않는다
- [ ] **[횡단]** 삭제 레인 `sync.delete` 이벤트와 답변 트레이스의 `(evidence_id, doc_version)`을 조인하는 "삭제 후 인용" 쿼리와 임원 등급 외부 경로 호출 카운터가 대시보드에 상시 0으로 표시되고, 1건이라도 P1 알림이 울린다
